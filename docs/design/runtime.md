## 0. 목표와 범위

**목표 (0107 G2′·G3)**: 작업 집합(한순간에 동시에 필요한 바이트)이 메모리 안에 들어오는 작업이면, 필요 메모리의 **1/2~1/4 예산**에서 **무손실로**, **예산을 넘지 않고** 돌린다. 느려질 정도는 **실행 전에 예측**해 알린다.

**하는 일**
- 큰 버퍼 하나하나에 대해, 예산이 모자라면 다섯 행동 가운데 되돌리는 비용이 가장 싼 것을 고른다.

| 행동 | 메모리에서 없어지는 것 | 되돌리는 법 | 무손실 |
|---|---|---|---|
| **두기** (Resident) | 없음 | — | ✅ |
| **압축** (Compressed) | 원래 크기 − 압축 크기 | 풀기 | ✅ (바이트 셔플 + zstd, 0038) |
| **원본 재읽기** (Dropped-Source) | 전부 | 원본 파일 구간을 다시 읽고 다이제스트 확인 | ✅ (β `source`, 0039) |
| **재계산** (Dropped-Lineage) | 전부 | 계보(입력 버퍼 + 계산 함수)로 다시 계산 | ✅ (결정적 계산일 때, §5 I5) |
| ~~**SSD 이동** (Spilled)~~ | — | — | **v0.2에서 제외**(0110 N1: SSD에 쓰지 않음). 필요해지면 새 결정과 `disk_writes` 동의로 추가 |

- 접근 순서를 알면(기록된 반복, 사용자 힌트) 다음에 쓸 버퍼를 **미리** 되돌려 계산과 겹친다.
- 모든 결정은 **실측 비용**으로 한다. 가정하지 않는다(0103의 교훈).
- **쓰기 없음(0110)**: 런타임은 SSD에 쓰지 않는다. 원본 재읽기는 페이지 캐시를 거치지 않는다(macOS `F_NOCACHE`, Linux `POSIX_FADV_DONTNEED`). 페이지 캐시도 물리 RAM이라, 런타임 때문에 생기는 메모리 전체를 예산 안에 두기 위해서다. 원본도 계보도 없는 데이터는 압축으로만 줄일 수 있고, 모자라면 "이 예산으로는 불가능"이라고 알린다.

**하지 않는 일 (범위 밖)**
- 한순간에 동시에 필요한 양이 예산보다 큰 작업. 이것은 알고리즘을 바꿔야 한다. 런타임은 실행 전에 "불가능, 작업 집합 X > 예산 Y"라고 알린다.
- 계보를 모르는 임의 메모리의 재계산. 런타임이 만들었거나 등록된 버퍼만 관리한다. 투명 모드(§6, Linux)는 페이지 단위의 원본 재읽기·압축·방출만 한다.
- 손실 방법의 자동 적용. 무손실이 기본이다. 손실(양자화 등)은 사용자가 `quality`로 허용할 때 접근 계층이 적용한다(U4 유지).

## 1. 설계 원칙

| # | 원칙 | 의미 |
|---|---|---|
| R1 | **무손실 기본** | 런타임의 다섯 행동은 모두 비트 단위로 되돌린다. 되돌린 바이트는 다이제스트(원본·방출) 또는 결정성 검사(재계산)로 확인한다 |
| R2 | **상한 보장** | 관리 버퍼의 상주 바이트 + 런타임 작업 버퍼 ≤ 예산. 이것을 **새 할당 전에**(입장 제어) 지킨다. 넘칠 것 같으면 먼저 다른 버퍼를 내보낸다. 내보낼 것이 없으면 할당을 거절한다(오류, 제안 포함) |
| R3 | **실측 비용** | 되돌리는 비용(재읽기·풀기·SSD 대역폭, 재계산 시간)은 이 기기에서 잰 값이다. 처음 값은 과거 실험(§7)에서 가져오고, 실행 중에 계속 고친다 |
| R4 | **소유권으로 안전** | 버퍼 바이트를 바꾸는 것은 그 버퍼의 상태 기계뿐이다. 사용 중(pin)인 버퍼는 절대 옮기지 않는다. 백그라운드 스레드는 **런타임이 소유한 메모리만** 만진다. 사용자 텐서의 저장공간 교체는 안전 지점에서만 한다(0052 E6 규칙 유지) |
| R5 | **되돌릴 길 없이는 버리지 않는다** | 버리기 전에 확인된 복원 경로가 적어도 하나 있어야 한다: 다이제스트가 맞는 원본, 살아 있거나 되돌릴 수 있는 입력을 가진 계보, 압축본, 방출 파일. 복원이 실패하면 오류를 낸다. 조용히 다른 값을 쓰지 않는다(β `IntegrityError`와 같음) |
| R6 | **예측과 보고** | 실행 전에 예상 느려짐(자릿수 수준, U6)을 알리고, 실행 뒤에 실제 값과 행동별 바이트·시간을 보고한다 |
| R7 | **플랫폼 정직성** | Linux는 투명 모드(userfaultfd)가 가능하다. macOS는 명시적 핸들을 쓴다. 되지 않는 것은 되지 않는다고 알린다 |
| R8 | **fail-open** | 런타임 내부 오류로 사용자 프로그램을 멈추지 않는다. 단, 데이터가 틀릴 수 있는 경우는 예외로 오류를 낸다(R5) |
| RS1~RS5 | **유지** (0027) | 한 호출 안의 전송, 버퍼 빌리기, 스레드별 문맥, 메모리 상한 버퍼 풀, 입출력·계산 중첩 |

## 2. 핵심 개념

### 2.1 관리 버퍼 (Buffer)

| 필드 | 뜻 |
|---|---|
| `id` | 런타임 안의 식별자 |
| `nbytes` | 바이트 수. 형식(dtype, shape)은 연결층이 가진다. 런타임은 바이트만 안다(P1: 프레임워크 무관) |
| `memory` | 소유 형태: **Owned**(런타임 아레나가 할당, §3.1) 또는 **Borrowed**(외부 저장공간, 예: torch 텐서 저장공간. 교체는 연결층이 안전 지점에서) |
| `recipes` | 되돌리는 법의 목록(0개 이상): `Source`, `Lineage`, `Seed` (§2.2) |
| `state` | 현재 상태(§2.3) |
| `pins` | 사용 중 횟수. 0보다 크면 옮기지 않는다 |
| `stats` | 마지막 접근, 접근 횟수, 기록된 접근 순서에서의 위치, 되돌리기 실측 시간 |
| `digest` | 상주 바이트의 다이제스트(원본·방출·재계산 확인용, xxh3-128, 0038) |

### 2.2 만드는 법 (Recipe)

| 종류 | 내용 | 확인 | 기존 부품 |
|---|---|---|---|
| `Source` | 파일 경로, 구간(offset, len), 파일 크기·수정 시각, 다이제스트 | 다시 읽을 때 다이제스트 비교, 파일이 바뀌면 복원 거부 | `spill::SourceRef`, `read_into` (0038) |
| `Lineage` | 계산 함수(연결층이 등록: Python 호출 가능 객체, Rust 함수, C 콜백), 입력 버퍼 id들, 인자, `deterministic` 표시 | 처음 한 번은 재계산 결과를 다이제스트로 확인(선택), 이후 신뢰 | 새로 만듦 |
| `Seed` | 난수 생성기와 시드 | 재생성 | 새로 만듦(가벼움) |

- 계보는 **DAG**다. 한 버퍼를 계보로 버리려면, 그 입력들이 상주하거나 스스로 되돌릴 수 있어야 한다(재귀, 깊이 제한). 되돌리기 비용은 입력들의 되돌리기 비용까지 합한다(DTR의 연쇄 비용과 같은 발상, 0108).

### 2.3 상태 기계

```
            alloc / from_file / derive
                      │
                      ▼
   ┌──────────────► Resident ◄─────────────────────────────┐
   │   pin/unpin      │  │  │  │                              │ restore (미리 읽기 또는 요청 시)
   │                  │  │  │  (v0.2: Spilled 없음, 0110)
   │                  │  │  └──── drop (Lineage 있음) ─► Dropped-Lineage ─┤
   │                  │  └─────── drop (Source 있음) ─► Dropped-Source ──┤
   │                  └────────── compress ─────────► Compressed ─────┘
   │
   └── FileBacked (Source가 있고 mmap 가능: 깨끗한 파일 페이지, OS가 쓰기 없이 버리고 다시 읽음, 0072)
```

- 모든 전이는 **버퍼 단위 잠금** 아래에서 한다. 사용 중(`pins > 0`)이면 Resident에서 나가지 않는다.
- `FileBacked`는 런타임이 직접 버리지 않고 OS에 맡기는 특수 상주 상태다. 예산 계산에서는 "쓰기 없이 버릴 수 있는 바이트"로 따로 센다.
- 장치(GPU) 버퍼는 한 단계를 더 가진다: **Offloaded-Host**(장치 → 호스트 RAM). 그다음 호스트 버퍼로서 위 상태를 탄다(β `host`와 같음).

### 2.4 계층과 예산

| 계층 | 예 | 예산 |
|---|---|---|
| 장치 | CUDA 메모리, Apple 통합 메모리(MPS 한도, K5) | `device` 풀(0059), 보유 메모리와 캐시 실측(0099~0103) |
| 호스트 RAM | 상주 버퍼, 압축본 | `host` 풀 |
| 파일 페이지 | FileBacked | 따로 표시(OS가 회수 가능) |
| SSD | 방출 파일 | `disk` 풀, `disk_writes` 동의, 20% 여유 바닥(0032 H4) |

- 런타임의 예산 = 사용자가 준 크기(또는 자동) 가운데 **관리 버퍼가 쓸 몫**이다. 관리하지 않는 메모리(인터프리터, 라이브러리, 사용자 작은 객체)는 시작 때 실측해 뺀다.

## 3. 구성 요소 (Rust, `crates/memopro/src/rt/`)

| 모듈 | 책임 | 기존 부품 |
|---|---|---|
| `rt::arena` | 관리 버퍼 전용 할당기. 큰 버퍼는 자기 mmap 영역, 중간 크기는 크기별 슬랩. 버린 영역은 `madvise(MADV_DONTNEED / MADV_FREE)`로 즉시 OS에 돌려준다. 할당기 낭비(MPS 1GiB 힙 0080, CUDA 조각 0105, libmalloc 캐시 0060)를 관리 버퍼에서는 없앤다 | 새로 만듦(Mesh 계열 발상, 0108) |
| `rt::registry` | 버퍼 표, 상태, 잠금, 사용 중 표시. Rust는 `Pinned<'a>` 가드(RAII), Python은 `with`, C는 `acquire/release` | `ledger` 확장(`Location`에 `Resident`, `Lineage`, `FileBacked` 추가) |
| `rt::recipe` | Source·Lineage·Seed 표현, 계보 DAG, 되돌릴 수 있는지 판정 | `spill::SourceRef`, 다이제스트 |
| `rt::cost` | 행동별 되돌리기 시간 추정 = f(바이트, 실측 대역폭, 재계산 실측 시간, 연쇄 비용). 다음 접근까지의 예상 시간(기록된 순서 또는 최근성) | 새로 만듦. 초기값 §7 |
| `rt::policy` | 입장 제어(R2). 내보낼 버퍼와 행동을 고른다: 점수 = 예상 정체 시간 / 풀리는 바이트가 가장 작은 것부터(DTR·Capuchin 계열 점수의 다섯 행동 일반화). 기록된 접근 순서가 있으면 미리 읽기 계획을 세운다 | 새로 만듦 |
| `rt::io` | 되돌리기·내보내기 파이프라인: 병렬 읽기·쓰기·압축·풀기, 계산과 겹치기(RS5), 버퍼 풀 상한(RS4). Linux는 이후 `io_uring`, macOS는 `F_NOCACHE`·큰 순차 읽기 | `spill`, `codec`, `residency::FileMap::prefetch` |
| `rt::predict` | 실행 전 예측: 기록된 한 반복(또는 사용자가 준 작업 설명)의 버퍼별 필요 순서와 크기 → 예산에서의 최소 되돌리기 바이트 → 대역폭으로 나눈 예상 추가 시간. 실행 뒤 실측과 비교해 보고 | 새로 만듦(U6 모형의 일반화) |
| `rt::fault` (Linux, 3단계) | 투명 모드: `userfaultfd`로 등록한 영역의 페이지 폴트를 받아 페이지 단위로 원본 재읽기·압축·방출 | 새로 만듦(UMap·ExtMEM이 실현성을 보임, 0108) |
| (기존) `hwinfo`, `pressure` | 예산의 기반, OS 압박은 **참고 정보만**(γ 결론, 0088) | 그대로 |

**스레드 구조 (RS7 해제 제안, §11)**
- **프로세스당 런타임 서비스 스레드 하나**: 정책을 판단한다. GIL과 무관하다.
- **입출력·압축 작업자 풀 하나**: rayon, RS3.
- **Python 쪽 연결층**: 버퍼 바이트를 직접 만지지 않는다. 핸들만 쥔다.

## 4. 인터페이스 (초안)

### 4.1 Rust

```rust
let rt = Runtime::new(Budget::bytes(8 << 30))?;          // 또는 Budget::auto()
let w = rt.from_file("model.safetensors", range)?;        // Source 레시피, 아직 읽지 않음
let x = rt.alloc(n_bytes)?;                               // Owned, 레시피 없음 → 압축·방출만 가능
let y = rt.derive(&[&w, &x], deterministic, |inputs, out| { /* 계산 */ })?;  // Lineage
{
    let view = y.pin()?;                                  // 필요하면 되돌린 뒤 고정
    use_bytes(&view);
}                                                         // 가드가 풀리면 다시 후보가 됨
rt.hint_sequence(&[w.id(), y.id(), /* … */]);             // 접근 순서 힌트(선택)
let r = rt.report();                                      // 행동별 바이트·시간, 예측 대 실측
```

### 4.2 C ABI (C/C++/다른 언어)

`mp_rt_new(budget)`, `mp_buf_alloc`, `mp_buf_from_file`, `mp_buf_derive(inputs, n, callback, ctx, deterministic)`, `mp_buf_pin(buf, &ptr, &len)`, `mp_buf_unpin`, `mp_rt_hint`, `mp_rt_report_json`. 소유권 규칙은 헤더에 적는다.

### 4.3 Python (`memopro.rt`)

```python
import memopro.rt as rt

r = rt.Runtime(budget="8GB")                       # 예산: 기존 형식(0059) 그대로
a = r.array_from_file("big.npy")                   # NumPy 파일 → Source 버퍼
b = r.derive(lambda x: np.log1p(x), a)             # Lineage 버퍼(결과는 필요할 때 계산)
with b.pin() as view:                              # view = numpy.ndarray(복사 없음)
    total = view.sum()
print(r.predict())                                 # 실행 전 예상(기록된 반복이 있으면)
print(r.report())
```

- **NumPy**: 고정 중에는 `numpy.ndarray` 뷰(버퍼 프로토콜, 복사 없음)를 준다. 고정이 풀린 뒤 그 뷰를 쓰는 것은 금지한다(문서화하고, 디버그 모드에서 검사).
- **PyTorch**: 런타임 버퍼에서 텐서를 만든다(`torch.frombuffer`, DLPack). 사용자 텐서를 내보낼 때는 β처럼 **안전 지점에서 `tensor.data`를 바꾸는 방식**을 쓴다(0036 B1, 가드 0048).
- **접근 계층 연결(2단계)**
  - `load`: 가중치를 `Source` 버퍼로 두고 층마다 미리 읽는다. fp16 무손실로 예산보다 큰 모델을 돌리는 경로다.
  - `train_session`: 활성값을 `Lineage`(checkpointing의 일반화)나 방출로, 옵티마이저 상태를 압축·방출로 다룬다.

## 5. 불변식 (시험으로 지킨다)

| # | 불변식 | 시험 |
|---|---|---|
| I1 | 관리 상주 바이트 + 작업 버퍼 ≤ 예산 | 무작위 할당·접근 순서 속성 시험(proptest), 실측 RSS 대조 |
| I2 | 사용 중인 버퍼는 옮기지 않는다 | 동시 고정·내보내기 경쟁 시험(loom 또는 스트레스) |
| I3 | 버리기 전에 복원 경로가 확인돼 있다(R5) | 원본 파일을 바꾸고, 방출 파일을 지우고, 계보 입력을 없애는 오류 주입 |
| I4 | 되돌린 바이트 = 버리기 전 바이트(다이제스트) | 모든 행동의 왕복 시험(비트 동일) |
| I5 | 재계산은 `deterministic` 표시가 있거나 첫 재계산을 다이제스트로 확인한 뒤에만 쓴다 | 비결정적 함수 등록 시험 → 재계산 대신 압축·방출을 고름 |
| I6 | 백그라운드 스레드는 Borrowed 메모리를 만지지 않는다 | 코드 구조(타입으로 분리) + 시험 |
| I7 | 런타임 내부 오류는 사용자 프로그램을 멈추지 않는다. 단, I3·I4 위반은 오류 | 오류 주입 |

## 10. 위험

- **사용 부담**: 명시적 고정(pin)을 사용자가 잊으면 느리거나 오류가 난다. 연결층(NumPy·torch 어댑터, 접근 계층)이 대부분을 감춰야 한다.
- **재계산의 결정성**: GPU 연산은 비결정적일 수 있다. 첫 재계산 다이제스트 확인(I5)이 비용을 더한다.
- **"조합의 새로움"**(0108): 관문 결과가 기존 도구 단독으로는 안 되는 것을 보여 주지 못하면 논문 주장이 약하다.
- **macOS 투명 모드 부재**: 코드 수정 없는 사용은 Linux에서만 가능할 수 있다.
- **SSD 수명**: 방출은 동의(`disk_writes`)와 쓰기량 보고를 유지한다. 원본 재읽기·압축·재계산을 우선한다.
