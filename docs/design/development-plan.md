**순서의 논리 (0012 S3, 0015 P1·P2)**
- **측정이 먼저다(P1)**: 남은 핵심 불확실성(α 수렴, β 수요, 중복도, OS 대비 이득)은 설계로는 풀리지 않는다. 기능 구현 전에 저비용 실험으로 판정한다.
- **걷는 뼈대(P2)**: 빌드 → wheel → 설치 → import를 S1에서 먼저 관통시켜 배포 문제를 조기에 발견한다.
- v0.1은 **고유성이 확인된 것**(β, census의 중복도 측정)과 모든 기능의 기반(doctor)부터 낸다.
- v0.1은 "큰 모델을 돌리게 한다"를 직접 달성하지 않는다. 대신 **개발 단계의 메모리 회수와 낭비 진단**을 제공한다(0013 V2). 직접 적합은 v0.2에서 제공한다.
- R2 센서스 연구와 v0.1 census 제품은 같은 코드를 쓴다. 연구와 제품이 서로를 앞당긴다.

규모 표기: **S** (며칠) / **M** (1~2주) / **L** (수 주). 1인 개발 기준 상대 규모이며 일정 약속이 아니다.

### A1. Rust 코어 (v0.1 범위) — 규모 M
- **순서 (0032)**: A1a `hwinfo`(→ doctor) → [Gβ] → A1b `spill`·`ledger`·`codec` 정리 → E009·E011. census 커널은 Python(numpy)으로 먼저 만든다(0022 R1).

| 모듈 | 완료 조건 |
|---|---|
| `hwinfo` (sysinfo 기반, **A1a**) | macOS·Linux에서 RAM·스왑·디스크, **cgroup v1/v2 한도**(Docker `--memory` 컨테이너에서 검증) |
| `codec` (바이트 셔플 + zstd, lowbit) | 비트 단위 정확 왕복(proptest: 무작위·NaN·Inf·비정규 수), 청크 스트리밍, bf16 압축률 측정 |
| `ledger`, `spill` (**방출 엔진**, 0027, **A1b — Gβ 통과 후**) | **주 경로 = 원본 파일 → 텐서 읽기 + 병렬 해시 확인**(0032 H1). 동시성 테스트, 방출 후 복원 비트 정확, 청크 단위 I/O. 방출 파일 안전성(P5: 0600, 종료 시 정리, 잔여 파일 청소, pickle 금지). SSD 정책(H3·H4: 해시 일치 시 재기록 생략, 낮은 I/O 우선순위, 여유 공간 20% 기준). **RS1~RS5 완료 조건**(architecture §6.1): Python 할당 최대치 < 청크 1개, 입력 주소 = `data_ptr()`, 반복 호출 시 스레드·문맥 수 불변, 입력 2배에도 RSS 증가량 불변(E008b의 367MiB 초과 원인 제거), 파이프라인 시간 < 순차 합 |
| E009 (방출 엔진 뒤, 0027) | 압축 방출 대 무압축 방출 확인 실험. **엔진 구현 후 사전 등록**하고 여러 크기·여러 날에 걸쳐 실행. 통과 시에만 β 방출 기본값을 압축으로 변경(그 전까지 무압축, 0025 C5). **기준선(0030 C2)**: macOS는 `torch.save`·`numpy.tofile`, Linux는 TensorNVMe. 결과로 Linux에서 TensorNVMe 선택 백엔드 연동 여부도 판단. **지표에 실제 SSD 쓰기 바이트 포함**(0032 H5) |
| E011 (0022 R3, 0032) | β 대 OS 스왑·압축 비교: 회수량, 복원 지연, 시스템 반응성, 실제 macOS 압축기의 fp32 압축률. 사전 등록 후 실행 |
| 프로토타입 정리 | `bytes` 입력 바인딩(`codec_*`, E008용)을 공개 API에서 제거하고 기록 (E008 재현은 커밋 `9fd9bd3`) |
| `census` 커널 | 표본 엔트로피가 numpy 기준 구현과 일치 |
| PyO3 바인딩 | buffer protocol로 복사 없이 전달(RS2, bf16은 uint8 뷰), GIL 해제 |
