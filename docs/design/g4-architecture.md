# memopro G4 설계 초안 v0.1 — 단점 극복과 새 개념 후보

- **상태**: 초안 (사용자 검토 대기). 연구 기록 0125
- **목표**: G4 (0123) — 메모리가 부족한 기기에서 Unsloth와 경쟁할 수 있는 라이브러리. B(중심) + C(보조)
- **관계**: 런타임 C-R([runtime.md](runtime.md)) 위에 쌓는다. 지금까지 만든 것은 버리지 않는다

---

## 1. 출발점: memopro의 단점과 한계 (지금까지의 대화와 실험에서)

| # | 단점·한계 | 근거 | G4에서의 중요도 |
|---|---|---|---|
| W1 | **학습·추론 속도가 느리다.** 스트리밍 학습은 CPU 경로이고, M1 bf16 역전파가 2.8 GFLOPS 경로로 떨어진다 | 0115, 0121 (1.5B LoRA 한 단계 4~5분) | **최상** |
| W2 | **런타임이 GPU 메모리(MPS·CUDA)를 다루지 않는다** | 0115 (CPU만) | **최상** |
| W3 | 원본도 계보도 없고 압축도 안 되는 데이터는 줄일 수 없다(SSD 쓰기 제외) | 0110, 0122 | 중 (정보 이론적 한계) |
| W4 | 1회차는 순서를 몰라 미리 읽지 못한다 | 0121 (기다림 1.8~3.8초) | 중 |
| W5 | 계산이 주도하는 작업에서는 되돌리기가 계산과 대역폭을 나눠 써 이득이 작다 | 0121 (0.945배) | 중 |
| W6 | Mac에서는 코드를 고쳐야 한다(투명 모드는 Linux·NumPy만) | 0122 | 중 |
| W7 | 텐서 하나가 한도 안에 통째로 들어가야 한다(나누면 비트 동일성을 잃을 수 있음) | 0114 수정 1 | 상 (7B 이상에서 임베딩 등) |
| W8 | 가중치가 바뀌는 전체 학습은 쓰기 없이 1/4 메모리에서 못 한다(옵티마이저 상태) | 0114 | 상 |
| W9 | 사용성·모델 범위·생태계가 없다(알파, 미배포) | 0106 | **최상** (경쟁의 절반) |
| W10 | 독창성이 "조합" 수준이다 | 0108, 이번 조사 | 연구상 상 |
| W11 | 예측이 되풀이되는 작업(한 주기 기록)에만 맞는다 | 0115 | 하 |

## 2. 경쟁 지형 갱신 (2026-10-03 조사)

| 대상 | 확인한 사실 | memopro에 주는 뜻 |
|---|---|---|
| **Unsloth** | NVIDIA·AMD·Intel GPU와 **Mac 학습을 공식 지원**(MLX). 최소 메모리: 7B QLoRA 5GB / 16비트 LoRA 19GB, 14B 8.5GB / 33GB, 70B 41GB / 164GB | "Mac을 지원하지 않는다"는 차별은 없다. 남는 빈칸은 **16비트(무손실) LoRA가 기기 메모리를 넘는 경우**다. 예: 16GB Mac에서 7B 16비트(19GB), 32GB에서 14B(33GB). Unsloth의 답은 QLoRA(손실)다 |
| **mlx-tune 등** | Unsloth 호환 API로 MLX 위에서 Mac 파인튜닝 | Mac 사용성 기준선 |
| **AirLLM** | 층 단위로 디스크→GPU 스트리밍해 양자화 없이 70B 추론. 다만 층별로 다시 나눈 파일이 필요해 **디스크에 모델 크기의 2~3배를 쓴다**. 70B는 1토큰/초 미만 | `memopro.rt.torch`의 추론 스트리밍과 겹친다. 차이: 원본 파일을 그대로 읽음(쓰기 0), 예산만큼 붙잡기, 미리 읽기, 예측, 학습 지원 |
| **Fuyou(LoHan)** | 단일 GPU에서 NVMe SSD를 메모리 층으로 써 100B 파인튜닝 | SSD **쓰기** 기반이다. memopro는 쓰기 0(0110)이 차이 |
| **DFloat11, ZipNN** | bf16 가중치를 무손실로 약 70% 크기로(지수부 엔트로피 부호화, GPU 해제 커널). ZipNN은 연속 체크포인트의 XOR 델타도 압축 | 무손실 상주 압축과 델타 압축은 이미 있다 |
| **인증된 int8 LM 헤드**(verified-progress, 2026), **실행 중 인증하는 양자화 어텐션**(Calver, 2026) | 저정밀 결과가 원본과 같은 결정을 내리는지 오차 한계로 인증하고, 안 되면 정밀 경로로 | "결정 인증" 아이디어는 헤드·어텐션 단위로 있다 |
| **RepDL, batch-invariant 연산** | 정확한 반올림·고정 순서로 플랫폼·배치에 상관없이 비트 동일 | "순서와 무관한 정확성"도 있다 |

**결론**: 이길 경기장은 **"16비트(무손실) LoRA·추론을 기기 메모리보다 큰 모델로, 디스크 쓰기 없이, 계산 속도에 가깝게"**다. 이 경기장에서 Unsloth는 QLoRA(손실)로 답하고, AirLLM은 추론만 하며 디스크에 쓰고, Fuyou는 SSD에 쓰고 CUDA 전용이다.

## 3. 아키텍처 개요

```
 ┌────────────────────────────────────────────────────────────────────┐
 │ L3  사용자 경험: memopro.finetune / load (Unsloth 비슷한 한 줄 API), │
 │     HF·PEFT 호환, 예산과 예상 속도를 먼저 보여 주는 계획표           │
 ├────────────────────────────────────────────────────────────────────┤
 │ L2  실행 계획기 SCP (Stream-Compute Planner)                         │
 │     단계당 토큰 수·마이크로배치 순서·체크포인팅·창 크기를 정해       │
 │     읽기를 계산 뒤에 숨긴다 (예측기 R로 미리 계산)                   │
 ├────────────────────────────────────────────────────────────────────┤
 │ L1  장치 상주 런타임: CPU 영역 + MPS 무복사 버퍼 + CUDA 고정 메모리  │
 │     (기존 C-R의 다섯 행동을 장치까지 확장)                           │
 ├────────────────────────────────────────────────────────────────────┤
 │ L0  연구 베팅(새 개념 후보): DCLF · Δ-상주 · SIEE (§5)               │
 └────────────────────────────────────────────────────────────────────┘
        C(보조): CUDA에서 Unsloth·Liger가 있으면 L2 아래 계산 백엔드로 감쌈
```

## 4. 공학 트랙 (기존 기법의 결합 — 신규성 주장 없음, 효과가 가장 큼)

| 트랙 | 무엇 | 푸는 단점 | 근거·위험 |
|---|---|---|---|
| **E1 MPS 무복사 스트리밍** | 런타임 영역(쪽 정렬 mmap)을 무복사 Metal 버퍼로 감싸 MPS 텐서로 쓴다. 통합 메모리라 전송 없이 GPU에서 계산 | W1, W2 | E015 G-F 통과(파일 mmap → 무복사 Metal 버퍼 → DLPack, 비트 동일). 위험: 고정 중인 영역의 수명 관리 |
| **E2 계산 주도가 되도록 단계 크기 정하기** | 가중치를 한 번 읽을 때 처리하는 토큰을 늘려(단계당 토큰 수) 읽기 시간 ≤ 계산 시간이 되게 한다. 예: 7B bf16, 16GB Mac, 단계당 2,048토큰이면 계산이 주도(대략 추정, 측정 필요) | W1, W5 | 활성값 메모리가 늘어난다 → E3 |
| **E3 활성값도 런타임에** | 체크포인팅 + 경계 활성값의 압축·재계산을 같은 다섯 행동 정책으로 | W1, W8 일부 | DTR·Checkmate와 겹침(인용) |
| **E4 정확한 추측 디코딩** | 상주하는 저정밀 사본으로 초안을 쓰고, 흘려 쓰는 원본으로 k토큰을 한 번에 검증한다(탐욕 출력 동일). 가중치 한 번 읽기로 k토큰 | W1 (추론) | QSpec·자기 추측 디코딩과 겹침 |
| **E5 무손실 상주 압축** | DFloat11식 지수부 엔트로피 부호화로 상주분을 약 70%로 → 더 많이 붙잡음 | W1, W5 | 해제 비용; 외부 구현을 감쌀지 직접 쓸지 결정 필요(0010) |
| **E6 1회차 순서** | PyTorch 모듈 그래프에서 첫 순서를 얻는다 | W4 | ZeRO의 모듈 순서 미리 가져오기와 같음 |
| **E7 C 보조** | CUDA에서 Unsloth·Liger 커널이 있으면 계산 백엔드로 쓰고, 메모리 초과분만 런타임이 맡는다 | W1 (CUDA) | 설치가 선택이어야 함(0012 S2) |
| **E8 사용성** | `memopro.finetune(model, data, budget=...)`: 계획표(예상 메모리·단계 시간) → 학습 → 저장. HF·PEFT 어댑터 호환 | W9 | 문서·노트북·모델 지원 확대 |

E1+E2+E3만으로도 "16GB Mac에서 7B 16비트 LoRA(Unsloth 기준 19GB 필요)를 계산 속도에 가깝게"를 노릴 수 있다. 이것이 G4의 **승부처**다.

## 5. 새 개념 후보 (연구 베팅)

> 신규성 규칙: "새롭다"고 말하지 않고, 조사 범위와 결과를 적는다. 아래 세 후보는 **이번(2026-10-03) 웹 조사에서 가까운 선행 연구를 찾았다.** 그래서 개념 자체를 새롭다고 할 수 없다. 새로 설계하는 부분은 각 후보 안의 **구체적인 알고리즘**(★ 표시)이다. 그것도 더 깊은 조사 뒤에야 "찾지 못함"이라고 말할 수 있다.

### N1. DCLF — 결정 인증 지연 정밀도 (Decision-Certified Lazy Fidelity)

- **개념**
  - 가중치를 여러 정밀도로 둔다: 상주하는 저정밀 사본(int4/int8)과 원본(디스크).
  - 계산은 저정밀로 하면서 각 값의 **오차 구간**을 함께 전파한다.
  - 최종 출력이 이산적 결정(탐욕 토큰, 임계값 비교, 정렬, 수렴 판정)이고 그 결정이 구간 안에서 바뀔 수 없음이 **증명되면**, 원본을 읽지 않고도 **원본으로 계산한 것과 같은 결정**을 낸다.
  - 증명이 안 되면 결정을 뒤집을 수 있는 부분만 원본으로 정밀화한다.
- **푸는 것**: W1. 읽는 바이트 자체를 줄인다. 무손실 정의는 "출력 결정이 같다"이다.
- **선행**: LM 헤드 인증(2026), 헤드별 어텐션 오차 한계(2026), 정확 실수 계산(iRRAM)의 지연 정밀화.
- **★ 새로 설계할 알고리즘: "뒤집힘 위험 정밀화 계획"(flip-risk refinement planner)**
  - 출력 여유(1등과 2등의 차이) 대비 불확실성을 각 가중치 조각(tile)의 기여로 나눈다(뒤로 가는 구간 민감도).
  - "줄어드는 불확실성 / 읽는 바이트"가 큰 조각부터 원본을 읽는다(탐욕 배낭). 인증되는 순간 멈춘다.
  - 기존 인증 헤드는 인증에 실패하면 헤드 전체를 정밀 경로로 돌린다. 조각 단위 선택적 정밀화를 네트워크 전체에 적용한 것은 이번 조사에서 보지 못했다.
- **위험(높음)**: 28층을 지나며 구간이 너무 넓어져(LayerNorm, softmax) 거의 다 정밀화해야 할 수 있다.
- **싼 확인 실험(E030 후보)**
  - 먼저 LM 헤드(1.5B에서 467MB, 전체의 15%)에서 인증에 필요한 행의 비율을 잰다.
  - 그다음 마지막 n층으로 넓힌다.
  - 관문 예: 탐욕 토큰 100%가 원본과 같고, 읽은 바이트 ≤ 30%.

### N2. Δ-상주 — 바뀌는 학습 상태의 시간 델타 상주 (Temporal Delta Residency)

- **개념**: 학습 중 계속 바뀌는 버퍼(전체 학습의 가중치, Adam m·v)를 내보낼 때, 마지막 기준본과의 **비트 XOR 델타**로 메모리에 압축해 둔다. 무손실이다.
  - 한 단계의 변화는 작아서 상위 비트(부호·지수·상위 가수)가 거의 그대로다.
  - bf16 가중치는 작은 학습률에서 한 단계에 대부분의 원소가 아예 변하지 않을 수 있다(측정 필요).
- **푸는 것**: W8. 쓰기 없이 전체 학습의 상태를 메모리 안에서 줄인다. 원본이 무효가 되는 문제를 "원본 + 델타"라는 레시피로 바꾼다.
- **선행**: 연속 체크포인트의 XOR 델타 압축(ZipNN, 텐서 증분 스냅숏), 기반·미세 조정 모델 사이 델타(FM-Delta, BitX). 모두 **저장용**이다.
- **★ 새로 설계할 알고리즘: 재기준(rebase) 결정을 스키 대여 문제로 푸는 온라인 정책**
  - 델타 사슬이 길어지면 복원 비용이 커진다. 언제 새 기준본을 만들지를 "델타를 계속 빌리기 대 기준본 사기"로 놓는다.
  - 스키 대여 문제의 경쟁비 2 규칙을 쓰고, 이것을 런타임의 재사용 거리 점수에 넣는다.
  - 실행 중인 학습 루프의 상주 정책으로 델타 사슬을 관리하는 것은 이번 조사에서 보지 못했다.
- **위험(중)**: Adam m은 단계마다 약 10% 바뀌어 이득이 작을 수 있다. 0019의 E005에서 fp32 학습 텐서 자체는 약 14%만 무손실로 압축됐다(시간 델타는 그때 재지 않았다).
- **싼 확인 실험(E029 후보)**: GPT-2·Qwen 0.5~1.5B 짧은 전체 미세 조정(CPU)에서 단계 사이 XOR 델타의 무손실 압축률을 잰다. 대상은 가중치 bf16/fp32, m, v. 관문 예: 가중치와 v가 2배 이상.

### N3. SIEE — 일정과 무관한 정확 실행 (Schedule-Invariant Exact Execution)

- **개념**: 모든 축약(내적, 기울기 누적, 손실 합)을 순서와 무관한 정확 누산기로 계산한다. bf16 곱은 fp32에서 정확하므로, 정수 초누산기로 모은 뒤 마지막에 한 번 반올림한다.
  - 그러면 결과가 **메모리 일정과 완전히 독립**이 된다: 예산, 타일 크기, 스트리밍 순서, 마이크로배치 순서, 장치.
- **푸는 것**
  - W7: 어떤 텐서든 원하는 크기로 나눠 흘려 쓸 수 있다.
  - W5: 계획기가 비트를 바꾸지 않고 마음대로 순서를 바꾼다.
  - "다른 예산에서도 같은 결과"가 정의상 보장된다.
- **선행**: RepDL(정확 반올림으로 플랫폼 간 비트 재현), batch-invariant 연산, ReproBLAS, Ozaki 방식(int8 텐서 코어로 고정밀 GEMM 흉내).
- **★ 새로 설계할 부분**: 목적의 전환이다. 재현성이 아니라 **"메모리 일정을 자유 변수로 만드는 것"**이다. 그리고 그 위에서 계획기(L2)가 층 우선·샘플 우선 실행을 비트 동일하게 바꿔 끼우는 일정 탐색을 한다.
- **위험(중~높음)**: 정확 누산의 계산 비용. CPU에서는 크게 느릴 수 있다. 계산 주도 경로라면 치명적이다.
- **싼 확인 실험(E031 후보)**: bf16 GEMM을 정확 누산으로 계산할 때 CPU(NEON)·MPS(Metal)에서 표준 대비 시간. 관문 예: ≤ 1.5배.

### 새 개념의 종합 평가 (정직하게)

- 세 후보 모두 **개념 수준에서는 선행 연구가 있다.** 원하시는 "조합이 아닌 완전히 새로운 개념"을 지금 확정할 수는 없다.
- 새로울 **가능성**이 있는 것은 각 후보 안의 구체 알고리즘(★)이다.
  - 조각 단위 뒤집힘 위험 정밀화 계획.
  - 델타 사슬의 스키 대여 재기준 정책.
  - 정확 누산을 메모리 일정 자유화에 쓰는 계획기.
- 이것들도 깊은 조사 뒤에만 "찾지 못함"이라 쓸 수 있다.
- **추천**
  - G4의 승부는 §4 공학 트랙(E1~E3, E8)으로 낸다.
  - 연구 베팅은 확인 실험이 싼 순서로(N2 → N1 → N3) 사전 등록해 가능성만 먼저 잰다.
  - 통과한 것만 제작한다. α의 전례(0018): 실험이 기각하면 접는다.

## 7. 순서

1. 런타임 3단계 마무리(시험 실패 2건 수정, 0124 기록, PR) — 0123의 결정.
2. 이 초안을 사용자가 검토 → 승인된 범위로 결정 기록.
3. E1(MPS 무복사 스트리밍) 원형 + E028 사전 등록(3B 16비트 LoRA, M1 8GB).
4. 연구 베팅 확인 실험: E029(N2) → E030(N1) → E031(N3).
5. E8 사용성(API·문서), 다운로드 허락 뒤 Unsloth·mlx-tune과 직접 비교.
