## 평가 방법

- 0147과 같은 영역·비중·판정 단계(입증됨 / 부분 입증 / 미입증 / 반증)를 쓴다. 그래서 이번 합계는 **0147과 직접 비교할 수 있다.**
- 수치는 각 기록의 측정값이다. 달성률(%)은 그 근거에 따른 연구자의 판단이다.
- 측정 기기는 0147과 같다. 0147 이후의 새 측정은 모두 **M1 8GB 한 대**에서 했다.

## A. G4-B — 메모리 제한 기기에서 손실 없는 LLM 학습·추론 (비중 30%)

| 근거 | 결과 | 판정 |
|---|---|---|
| E036b (0161), S1 | **7B bf16(14.2GiB) LoRA를 8GB M1에서** 예산 1.5·2GiB로 완주. 손실 유한·비트 동일, 7.3토큰/초(129토큰) | 입증 |
| E037c (0169) | `finetune` 기본 길이 512토큰에서 **예산이 학습 단계 전체를 덮음**: 3B·7B 모두 footprint ≤ 예산 + 158MiB, 손실 비트 동일. 3B 약 36, 7B 약 16토큰/초. 들어갈 수 없는 예산은 시작 전에 거절 | 입증 |
| E033c (0152), S2 | 3B 무손실 생성 2.82배(1.19초/토큰), 출력 비트 동일 4/4 | 입증 |
| E038b (0174) | 7B 무손실 생성 8.95 → 2.37초/토큰(3.77배), 출력 동일, footprint +3,015MiB | 입증 |
| E034 (0151), S3 | 같은 과제: 1.5B는 mlx-tune 118.9 대 memopro 45.4토큰/초(**2.6배 느림**). 3B는 mlx-tune이 메모리 부족으로 시작 못 함, memopro는 1GiB 예산으로 완주 | 입증 |
| 미시험 | 16GB Mac(실측 없음, 8GB 결과로 대신함 — 0158의 논리), 512토큰 초과, Qwen2.5 밖의 모델 계열, CUDA에서의 G4 경로, Unsloth와의 직접 비교 | 미입증 |
| 한계 | 생성은 예산이 단계 전체를 덮지 않음(`hold_back`은 학습만). 7B 생성 2.4초/토큰은 대화형으로 느림. 학습 속도 격차는 PyTorch MPS 계산(0156) | 부분 |

- **판정: 입증됨(핵심), 범위는 부분.**
  - 목표의 경쟁 지점("같은 기기에서 남들이 못 하는 크기를 16비트 그대로")은 3B·7B, 학습·생성 모두에서 보였다.
  - 하지만 한 기기, 한 모델 계열이다. 속도는 "들어가는 크기"에서는 경쟁자보다 느리다.
- **달성률: 40% → 약 65%.**

## B. G2′·G3 — 범용 런타임 C-R (비중 20%)

- 0147 뒤 새 관문은 없다. 런타임에 더해진 것은 `Runtime::hold_back`(실행 중 한도 줄이기, 0165) 하나다.
- 남은 것도 같다: macOS 투명 모드, 학습·GPU 경로의 느려짐 예측, C ABI의 외부 사용자.
- **달성률: 약 65%(그대로).**

## C. G1 — 접근 계층 (비중 15%)

- 변화 없음. 0175에서 `memopro run`과 흘려 쓰는 MPS 모델의 워터마크 충돌을 정리했다.
- **달성률: 약 66%(그대로).**

## D. 연구 코어와 논문 근거 (비중 10%)

| 항목 | 0147 뒤 변화 |

| 런타임 C-R(논문 B) | 7B 학습·생성, 경쟁자 비교, 예산이 단계를 덮는 상한까지 측정이 갖춰짐 |

## 남은 빈칸 (달성률을 가장 많이 올릴 순서, 제안)

1. **첫 공개 배포(S4)** — 제품 준비의 가장 큰 빈칸. 사용자 쪽 준비 뒤 태그만 올리면 된다.
2. **모델 계열 넓히기** — Llama·Mistral·Gemma 계열에서 학습·생성 확인. 행 불변 검증의 구조 지원 확인. 모델 내려받기와 디스크 공간 필요.
3. **생성도 예산이 덮게** — 학습처럼 KV 캐시·로짓을 `hold_back`으로 예산 안에 넣는다.
4. **속도** — PyTorch MPS 계산이 상한이다. MLX 계산 백엔드를 감쌀지(0156 선택지 C)는 새 결정이 필요하다.
5. **다른 기기** — 16GB Mac, CUDA(G4-C), Linux CPU.
6. **논문 A·고유 기법** — E010(사용자와 동료), E012, N1~N3.
