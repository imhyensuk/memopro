# 0189. 사용자 결정 A(E040): 투명 모드 넓히기 — 큰 `malloc`을 모두 페이저로, 프로세스 전체 상한, 그 뒤 E040b

- **날짜**: 2026-10-05
- **유형**: decision (사용자 선택) + design + survey
- **상태**: 확정(설계). 제작 중
- **관련 기록**: 0185 (E040 결과·진단), 0124 (Linux 페이저), 0122 (G-R3), 0108 (선행 조사)

## 결정

> "E041은 A, E040도 A로 진행해." (2026-10-05)
> E040의 A = 투명 모드의 범위를 넓히고(페이저 밖 메모리, 되읽기) E040b로 다시 잰다.

## 문제 (0185에서)

1. **페이저 밖 메모리 0.4~1.1GB.** 지금의 투명 모드는 NumPy 메모리 처리기로 16MiB 이상의 NumPy 배열만 잡는다. 정렬 버퍼, pandas 해시 표, scipy C++ 버퍼처럼 C 확장이 `malloc`으로 바로 잡는 메모리, 16MiB보다 작은 배열은 잡지 못한다.
2. **상한이 프로세스 전체가 아니다.** 페이저는 자기 몫만 지킨다. 페이저 밖이 늘면 프로세스가 한도를 넘어 죽는다.
3. **되읽기 폭주.** 무작위 접근(정렬·groupby, 반복 스텐실)에서 76배 이상 느려졌다.

## 선행 조사 (새로움 규칙)

| 대상 | 방식 | memopro와의 관계 |
|---|---|---|
| ExtMEM (USENIX ATC 2024) | `LD_PRELOAD`로 들어가 mmap·madvise 시스템 호출을 가로채고 userfaultfd(+ 커널 수정 200줄)로 응용별 페이징 | **같은 구조**: 미리 불러온 라이브러리 + userfaultfd로 수정 없는 프로그램을 관리한다 |
| libvmmalloc (PMDK) | `LD_PRELOAD`로 malloc·free·calloc·realloc·posix_memalign을 가로채 메모리 매핑 파일 위의 힙으로 | malloc 가로채기 자체는 오래된 기법이다 |
| UMap (LLNL) | userfaultfd로 응용이 요청한 영역만 페이징 | 0108에서 조사함 |

- **판정**: 큰 할당을 가로채 userfaultfd 페이저에 넣는 것은 기존 기법의 조합이다. **새로움을 주장하지 않는다.** 엔지니어링으로 G-R3의 적용 범위를 넓히는 일이다. memopro 쪽의 차이(무손실 압축만, 디스크 쓰기 없음, 프로세스 상한)는 0108의 "조합의 새로움" 범위 안이다.

## 설계

### 1. `memopro-preload` (Linux, 새 crate, cdylib)

- `LD_PRELOAD`로 들어가 `malloc`, `free`, `calloc`, `realloc`, `posix_memalign`, `aligned_alloc`, `memalign`, `malloc_usable_size`를 가로챈다.
- **문턱(기본 4MiB, 조각 반올림 낭비를 25% 이하로) 이상**의 할당은 페이저 영역(`Pager::map`, 쪽 정렬, 0으로 시작)에서 준다. 작은 것은 원래 `malloc`(`dlsym(RTLD_NEXT)`)으로 넘긴다.
- `free`·`realloc`은 주소가 페이저 영역인지 보고(정렬된 영역 표) 나눈다.
- **재귀 막기**
  - 이 라이브러리의 Rust 전역 할당기는 원래 `malloc`으로 바로 간다.
  - 페이저 스레드와 페이저 호출 안에서는 스레드 지역 표시로 모든 할당을 원래 `malloc`으로 보낸다(zstd 등 C 코드의 `malloc`도 이 라이브러리로 오므로).
  - `dlsym`이 처음 `calloc`을 부를 때는 정적 버퍼로 답한다(알려진 처리법).
- 설정은 환경 변수(`MEMOPRO_PRELOAD_BUDGET`, 문턱, 보고서 경로). 끝날 때 보고서를 쓴다(측정용 파일. 런타임 데이터는 디스크에 쓰지 않는다는 0110의 원칙과 같은 성격: 보고서만).

### 2. 프로세스 전체 상한

- 사용자는 **프로세스 전체 예산 T**를 준다.
- 페이저의 한도 = T − (프로세스 RSS − 페이저가 가진 메모리) − 여유. 페이지 폴트를 처리할 때마다 `/proc/self/statm`으로 다시 계산한다.
- 페이저 밖이 커지면 페이저가 더 내보내 전체를 T 안에 둔다. 페이저 밖만으로 T를 넘으면 어쩔 수 없다(보고서에 남긴다).

### 3. 되읽기 폭주 (측정 뒤 결정)

- 먼저 1·2로 E040 작업을 다시 재고(개발 측정), 남은 느려짐을 본다.
- 후보: 조각 크기(1 → 4MiB), 무작위 접근에서 내보낼 조각 고르기, 더 빠른 압축(lz4). 측정 없이 고르지 않는다.

### 4. `memopro run --transparent`

- Linux에서 `LD_PRELOAD`와 예산을 넣고 한 번 다시 시작한다(macOS에서 하는 다시 시작과 같은 방식, 0081). 이때 NumPy 처리기는 쓰지 않는다(모든 큰 `malloc`이 이미 잡힌다).
- **배포 꾸러미에 .so를 넣는 일은 남는다.** E040b에서는 실험 작업 흐름이 crate를 빌드해 경로를 넘긴다.

## 개발 방식

- 이 Mac에는 Linux가 없다(userfaultfd는 Linux 전용). 개발 측정은 GitHub Actions의 수동 작업 흐름(`e040.yml` 진단 모드)으로 한다.
- 관문은 E040b 사전 등록에서 정한다: E040의 T1~T3 그대로, 작업 셋 + E027 영상 작업(회귀).
