## 구현

| 구성 | 내용 |
|---|---|
| 대상 | 텐서, `nn.Module`(파라미터·버퍼·그래디언트), 옵티마이저(상태 텐서). 텐서 객체 단위로 한 번씩(공유 가중치 중복 없음) |
| 해제 방식 (B1) | `tensor.data`를 크기 0 텐서로 교체하고 복원 시 되돌린다. **객체 정체성이 유지**되어 옵티마이저 참조가 그대로 유효하다. 텐서마다 "복원 가능한 형태 만들기 → 즉시 해제"를 반복하므로 추가 메모리는 텐서 하나 분량을 넘지 않는다(V6) |
| 방법 5종 | `source`: safetensors 헤더로 이름을 대응시키고(base_model_prefix 처리), 원본을 읽어 dtype을 변환한 뒤 현재 텐서와 **다이제스트로 비트 단위 비교**. 복원 시에는 파일 크기·수정 시각과 다이제스트를 재확인한다(B3). `host`: CUDA만(MPS는 통합 메모리라 이득 없음). `compress`: 자동 모드에서는 90% 이하로 줄 때만 쓴다. `bf16`: 명시할 때만. `spill`: 동의 필요(`ask`), 20% 여유 기준, 하루 한도, 0600 파일, 바뀌지 않았으면 재기록 생략(H3) |
| 텐서별 혼합 | `auto`는 텐서마다 가능한 첫 방법을 쓴다. 예: 수정된 모델의 가중치는 `compress`, 바뀌지 않은 버퍼는 `source`. 명시 모드는 대체 방법 없이 적용하고, 맞지 않는 텐서는 이유와 함께 `handle.kept`에 남긴다(H6) |
| 자동 복원 (B2) | 모듈은 모든 하위 모듈에 forward pre-hook을 달고, 옵티마이저는 step pre-hook을 단다. 노트북에서 텐서는 이름을 `SleepingTensor` 대리 객체로 바꿔, 처음 쓸 때 깨우고 이름을 되돌린다(`__torch_function__`, 연산자, 속성 접근) |
| API | `now(obj, mode, allow_spill, name) → Handle`, `Handle.wake()`, `wake(target)`, `plan(obj) → [PlanRow]`, `suggest()`, `status()`, `enable(auto, idle_cells)`, `register_source(model, *paths)`, `handles()` |
| 노트북 | `%load_ext memopro`로 추적기가 켜진다. 셀에서 쓴 이름은 AST와 원문으로 판정(E006 방식)한다. `idle_cells`(기본 3) 이상 안 쓴 1MiB 이상 객체의 합이 256MiB를 넘으면 한 줄로 제안하고, 같은 객체는 다시 쓰기 전까지 한 번만 제안한다. 매직: `%hibernate NAME [--mode] [--plan] [--spill]`, `%wake`, `%memopro status`. 오류는 출력만 하고 셀을 멈추지 않는다 |
| SSD 기록 (H5) | 방출 폴더의 `writes.json`에 로컬 날짜별 누적 쓰기량을 둔다. `status()`와 `%memopro status`에 표시한다. 이 프로세스의 파일은 종료 시 지우고, 죽은 프로세스의 파일은 다음 사용 시 지운다(P5) |
| 실측 보고 (V7) | 동면 전후 프로세스 RSS와 MPS·CUDA 드라이버 메모리(캐시 비운 뒤)의 차이. `memopro.report()`에 적용·복원을 기록한다 |
| 기타 | numpy를 `torch`·`hf` 선택 설치 의존성에 추가(바이트 뷰용). `IntegrityError` 추가 |

## 검증 (테스트)

`tests/test_hibernate.py` 18개, `tests/test_examples.py` 1개(예제 노트북 전체 실행)를 추가했고, 전체 97개가 통과한다.

| 검증 항목 | 결과 |
|---|---|
| GPT-2 축소판(safetensors 저장 후 `from_pretrained`) | CPU·MPS에서 `source`로 전부 해제, forward로 자동 복원, **로짓이 비트 단위로 동일** |
| bf16 파일을 fp32로 로드한 경우 | 변환 후 비교를 통과하고 동일하게 복원 |
| 불러온 뒤 가중치를 수정한 경우 | `source` 거부("differs from the tensor"), 아무것도 해제하지 않음 |
| 동면 중 원본 파일을 변경한 경우 | 깨울 때 `IntegrityError` |
| `compress` | 동일 복원, 보관 크기 < 원본의 절반(희소 텐서) |
| 압축이 안 되는 int64 난수 + `ask` | `auto`가 동의 필요로 거부하고 텐서 유지 |
| `bf16` | 명시할 때만 적용, 수치 변경 확인 |
| `spill` | 0600, 쓰기량 누적, 동일 복원, 재동면 시 재기록 0바이트(H3), `never`·20% 기준·하루 한도 거부, 파일 손상 시 `IntegrityError`, 죽은 프로세스의 파일 정리 |
| 옵티마이저 | `step()` 시 자동 복원 |
| `plan()` | 5개 행, 아무것도 바꾸지 않음 |
| 노트북 | 실제 IPython에서 매직·대리 객체·`status`·`--plan`·유휴 제안 확인 |

## 시연 측정 (M1 8GB, MPS, GPT-2 124M, HF 캐시 rev 607a30d)

`experiments/n1c_demo/run.py`로 측정했다. 원시 데이터와 환경은 `docs/research/data/n1c/demo_mps.json`, `env_mps.json`에 있다(스크립트 SHA-256 3f121b92…).
- 측정 전 상태: 사용 가능 메모리 1.54 GiB, 스왑 6.07 GB 사용 중
- 사전 등록 실험이 아닌 시연이다.
- 스크립트는 결과를 낸 뒤 동결했다. 포맷과 린트 예외는 pyproject에 두었다.

| S1: 원본 그대로인 GPT-2 fp32 (498MB) | 결과 |
|---|---|
| 선택된 방법 | `source` 100% (SSD 쓰기 0) |
| 비트 단위 동일 복원 | 3/3 |
| 회수량 (MPS 드라이버) | 매번 1.00 GiB. 모델을 올릴 때 늘어난 1.08 GB와 같은 수준이고, `del`+`gc`+`empty_cache` 기준선과도 같다 |
| 동면 시간 | 0.71 / 0.33 / 0.42 s (중앙값 0.42) |
| 깨우기 + 추론 1회 | 0.42 / 0.38 / 0.47 s (중앙값 0.42) |
| 기준선: `del` 후 `from_pretrained` 다시 불러오기 | 0.56 s (페이지 캐시가 따뜻한 상태) |

| S2: 가중치를 바꾼 bf16 모델 (249MB, 원본과 불일치) | 결과 |
|---|---|
| 선택된 방법 | `compress` 100%. 보관 크기 171MB(69%) |
| 비트 단위 동일 복원 | 예 |
| 회수량 | MPS 드라이버 1.00 GiB 감소, RSS는 230MB 증가(압축본 + 할당자 보유) |
| 깨우기 + 추론 | 0.52 s |
| SSD 방출 | 불가: 디스크 여유가 20% 기준 미만(8.6%). 정책대로 동작 |

**해석**
- 원본이 있는 모델에서는 **SSD에 쓰지 않고, 수동 삭제와 같은 양을 회수하고, 다시 불러오기보다 빨리** 돌아왔다.
- 원본이 없는 모델에서 통합 메모리(M1)의 순 회수량은 "원본 − 압축본" 정도로 작다(249 → 171MB). 수정된 모델에는 H1의 이득이 없다는 예상과 일치한다.
- MPS 드라이버 메모리는 1GiB 단위로 움직였다. 따라서 작은 모델의 회수량을 이 값만으로 해석하면 안 된다.

## 한계

- **CUDA 경로(`host`)는 실제 GPU로 검증하지 않았다**(I2, Colab 예정).
- 시연은 한 기기, 한 모델, 3회 반복이다. 페이지 캐시가 따뜻한 상태에서 잰 값이며, 차가운 캐시에서는 `source`의 복원 시간이 SSD 읽기 속도에 좌우된다.
- 동면 중인 텐서를 직접 사용하면 형상 오류가 난다(B1이 받아들인 위험). 뷰(view)가 저장공간을 잡고 있으면 회수되지 않으며, 실측으로만 드러난다.
- 추적기는 셀 코드의 이름으로만 사용을 판정한다. 함수 안에서 전역을 간접 참조하는 경우는 놓칠 수 있다. 이 경우 유휴가 과대 추정되지만, 동면 대상은 사용자가 고르므로 영향이 제한적이다.
- `idle_seconds` 기준은 미구현이다(`InvalidArgument`).
