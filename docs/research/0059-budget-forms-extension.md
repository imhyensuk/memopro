# 0059. 예산 설정의 종류와 범위 확장

- **날짜**: 2026-09-26
- **유형**: decision + design (구현 기록은 같은 기록 뒷부분)
- **상태**: 확정
- **관련 기록**: 0035 (보수적 가용량, `kernel_available_bytes`로 예산을 잡지 않음), 0052 E3 (크기·비율·풀별 상한, "측정값보다 올리지 않는다"), 0053 (구현), 0058 (E011: 이 Mac의 보수적 가용량 1.48GiB 대 OS 추정 3.3GiB)

## 배경

> "사용자가 설정 가능한 예산의 종류와 범위를 더 다양하게 설정할 수 있으면 좋을 것 같아."

현재(0052 E3) 예산은 네 형식을 받는다: `"auto"`, 크기(`"6GB"`, 장치와 호스트의 상한), 측정 예산의 비율(`0.5`, `"50%"`), 풀별 상한(`{"device": "4GB", "host": "6GB"}`). 풀별 형식은 크기만 받고 디스크 풀은 없다. 여유분(headroom)은 비율로만 정한다. 예산을 바꾸는 방법은 전역 `configure()`와 호출별 인자뿐이다.

사용 사례에서 빠진 것은 다음과 같다.

| # | 사용자가 하고 싶은 말 | 지금 |
|---|---|---|
| N1 | "다른 앱을 위해 2GB는 남겨 줘" | 표현할 수 없다(비율로 어림할 뿐) |
| N2 | "최소 3GB가 안 되면 괜히 int4·오프로드로 버티지 말고 멈춰" | 표현할 수 없다. memopro는 끝까지 더 작은 구성을 찾는다 |
| N3 | "memopro 추정은 너무 보수적이다. 이 Mac에서 스왑을 감수하고 더 쓰겠다" | 할 수 없다. 이 Mac은 보수적 가용량이 1.48GiB, OS 추정이 3.3GiB다(0058). 예산을 올리는 방법이 없다 |
| N4 | "오프로드·방출이 디스크를 20GB 넘게 쓰지 않게 해 줘" | 디스크 풀 상한이 없다 |
| N5 | "장치는 80%, 호스트는 2GB 남기고"처럼 풀마다 다른 형식 | 풀별 형식은 크기만 받는다 |
| N6 | "이 블록에서만 예산 3GB" | `configure()`를 바꿨다가 되돌려야 한다 |
| N7 | 여유분을 비율이 아닌 크기로("1GB는 항상 비워 둬") | 비율만 받는다 |

## 고려한 선택지

1. **형식을 더 받는 것(채택)**: 기존 형식은 그대로 두고 문법을 넓힌다. 기존 설정과 테스트는 바뀌지 않는다.
2. 예산 객체 API(`memopro.Budget(host=..., reserve=...)`)만 추가: Python에서는 편하지만 `memopro.toml`, 환경 변수, CLI에서 쓸 수 없다. 기각. 대신 매핑 형식이 같은 표현력을 준다.
3. 측정값보다 높은 예산을 비율(`"150%"`)로 허용: 무엇의 150%인지 모호하고, 실수로 넣기 쉽다. 기각. 측정값을 넘기는 방법은 명시적인 두 가지(`!`, `budget_basis`)로 한정한다.

## 결정

### D1. 풀 하나의 값 (장치, 호스트, 디스크 공통)

| 형식 | 뜻 | 예 |
|---|---|---|
| `"auto"` | 측정 예산 | |
| 크기 | 그 크기를 넘지 않는다(측정값보다 올리지 않음) | `"6GB"`, `6_000_000_000` |
| 비율 | 측정 예산의 비율, (0, 1] | `0.5`, `"50%"` |
| **`-크기`** | 측정 예산에서 그만큼 남긴다(N1) | `"-2GB"` |
| **`크기!`** | 측정값과 관계없이 정확히 그 크기(N3). 보고서에 경고를 남긴다 | `"6GB!"` |
| **`최소..최대`** | 측정 예산을 최대로 자르고, 최소보다 작으면 멈춘다(N2). 한쪽은 비워도 된다 | `"2GB..6GB"`, `"3GB.."`, `"..6GB"` |
| **매핑** | 위 형식 하나(`use`)와 범위(`min`, `max`)를 함께 | `{"use": "-2GB", "min": "1GB"}` |

- "멈춘다"는 `load`·`check`·`optimize`·`train_session`·`memopro run`이 설정 단계에서 `BudgetExceeded`를 낸다는 뜻이다. 메시지에는 필요량, 측정 예산, 풀 이름이 담긴다. `doctor`는 멈추지 않고 경고로 보여 준다.
- `!`는 크기에만 붙는다. `!`로 정한 풀에는 γ 압박 축소(0052 E6)도 적용하지 않는다. 사용자가 명시한 값이기 때문이다.

### D2. 전체 값과 풀별 값

- 전체 `budget`에 D1의 형식 하나를 주면 장치와 호스트에 똑같이 적용한다(지금처럼).
- 풀별 값은 `{"device": ..., "host": ..., "disk": ...}` 또는 `"device=80%,host=-2GB,disk=20GB"`로 준다. 이때 D1의 모든 형식을 쓸 수 있다(N5). **디스크 풀을 추가**한다(N4). 디스크 상한은 `load`의 디스크 오프로드와 β `spill`에 적용한다.
- TOML에서는 표로 쓴다.

```toml
[budget]
device = "80%"
host = { use = "-2GB", min = "1GB" }
disk = "20GB"
```

### D3. 측정 기준 `budget_basis` (N3)

측정 예산의 출발점을 고른다. 적용 대상은 호스트, 그리고 호스트와 메모리를 함께 쓰는 통합 메모리 장치(MPS)다. CUDA는 언제나 드라이버가 알려 주는 여유량을 쓴다.

| 값 | 호스트 기준 | 성격 |
|---|---|---|
| `"conservative"` (기본) | 압축·스왑 없이 얻을 수 있는 양(0035) | 지금과 같음 |
| `"os"` | OS 추정 가용량(macOS: 다른 앱이 쓰는 메모리 일부 포함) | 압축·스왑이 생길 수 있다. 보고서에 경고 |
| `"total"` | 물리 메모리 전체(컨테이너면 그 한도) | 전용 기기·컨테이너용. 보고서에 경고 |

이것은 0035의 "`kernel_available_bytes`로 예산을 잡지 않는다"를 **사용자가 명시적으로 고를 때에 한해** 완화하는 것이다. 기본값은 바뀌지 않는다. 0052 E3의 "측정값보다 올리지 않는다"도 기본 동작으로는 유지하고, `!`와 `budget_basis`로만 넘길 수 있다.

### D4. 여유분을 크기로도 (N7)

`headroom`은 비율(`0.1`, `"10%"`) 또는 크기(`"1GB"`)를 받는다. 비율이면 측정값에 (1 − 비율)을 곱하고, 크기면 측정값에서 뺀다. 풀마다(장치, 호스트) 적용한다.

### D5. 범위가 정해진 임시 설정 (N6)

`with memopro.using(budget="3GB", quality="high"): ...`를 추가한다. 블록 안에서만 모든 설정을 바꾼다. `configure()`보다 우선하고, 블록을 나가면(예외 포함) 되돌아간다. contextvars로 구현하므로 스레드와 asyncio 작업마다 따로 적용된다. 이미 있는 호출별 인자(`memopro.load(..., budget=...)`)는 그대로 둔다.

우선순위: 기본값 < `memopro.toml` < `MEMOPRO_*` < `configure()` < `using()` < 호출별 인자.

### D6. 만들지 않는 것

- 여러 GPU의 장치별 예산(`cuda:0`, `cuda:1`): 접근 계층이 아직 주 장치 하나만 다룬다. 다중 GPU를 지원할 때 함께 결정한다.
- 용도별 예산(가중치 대 활성값): `check`의 계획과 겹친다. 수요가 확인되면 다시 본다.

## 구현

| 파일 | 내용 |
|---|---|
| `config.py` | `Limit`(use, reserve, force, minimum, maximum), `PoolBudget.disk`, 풀 값 파서, `budget_basis`, 크기 `headroom`, `using()` |
| `orchestrator/budget.py` | 기준 선택, 여유분(비율·크기), 풀마다 D1 적용, `Budget.forced`·`shortfalls`·`notes`, `describe_setting` 확장 |
| `access/_common.py` | 부족한 풀이 있으면 `BudgetExceeded`. 강제한 풀은 γ 축소 제외 |
| `hibernate/_ssd.py` | `spill`이 디스크 풀 상한을 지킨다 |
| `_doctor.py`, `cli.py` | 기준·강제·부족을 보여 준다. `--budget-basis` 옵션 |
| `__init__.py` | `memopro.using` |

기존 값은 그대로 파싱된다. 크기는 `int`, 비율은 `float`, 크기만 담은 풀별 값은 예전과 같은 `PoolBudget`이다. 새 형식만 `Limit`이 된다.

## 논문 매핑

- **논문 B System**: 예산 문법(D1~D5). 보수적 기본값과, 사용자가 명시할 때만 넘을 수 있는 두 가지 방법(`!`, `budget_basis`). "측정은 보수적으로, 결정권은 사용자에게"라는 원칙의 사례.
- **논문 B Discussion**: 최솟값(N2)은 "성능이 너무 떨어지는 구성으로 조용히 버티는 것"을 막는 장치다. fail-open(U-원칙)과 짝을 이룬다.
