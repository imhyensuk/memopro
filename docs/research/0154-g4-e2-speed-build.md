- **다시 읽기가 0이어도 PyTorch보다 1.1초 느리다** → 흘려 쓰기의 부가 비용이다.
- cProfile(전부 상주, forward 3번)의 호스트 시간
  - `torch.mps` 이벤트 기록: 1,017번에 1.27초(번당 1.25ms).
  - `metal_wrap`: 1,017번에 0.37초.
  - 울타리 목록 검사: 11만 번.
- **원인**
  - 0136의 `_MetalPins`는 버퍼가 안 쓰이게 되는 즉시 버퍼마다 MPS 이벤트를 기록했다. 이벤트 기록은 GPU 명령 버퍼를 제출시켜 GPU 작업 묶음을 끊는다.
  - 또 다음 사용 때 다시 감쌌다.
- **정밀도별 행렬곱(M1, GFLOPS)**: bf16 572~721, fp16 945~1,449, fp32 722~1,001.
  - M1 GPU는 bf16 하드웨어가 없다. 하지만 bf16 → fp32 변환(정확함)이 초당 33.5GB라서, 가중치를 쓸 때마다 변환해야 하는 흘려 쓰기에서는 이득이 없다. 채택하지 않았다.
  - fp16은 bf16의 범위를 담지 못해 손실이 생길 수 있다. 무손실 원칙에 어긋나 제외했다.
- **측정 조건 문제(발견)**
  - 오늘의 측정은 **배터리 전원 + 저전력 모드**(`pmset`: `lowpowermode 1`)에서 이루어졌다.
  - 같은 E034 memopro 1.5B 경우가 E034 때 45.4토큰/초였다. 지금은 이전 코드 33.0, 새 코드 33.4토큰/초다(27% 느림).
  - 그래서 위 절대값은 E034와 비교할 수 없다. 시스템 설정은 Claude Code가 바꾸지 않는다.

## 제작

1. **`_MetalPins`(python/memopro/rt/torch.py)**
   - 감싼 버퍼(고정 + 무복사 MTLBuffer + torch 텐서)를 다 쓴 뒤에도 남겨 둔다. 그래서 다음 사용은 비용이 없다.
   - 런타임의 여유(한도 − 사용량)가 한도의 1/4보다 작아질 때만, 캐시만 들고 있는 버퍼 전부를 **MPS 이벤트 하나로** 울타리 친다. 이벤트가 끝나면 그사이 다시 쓰이지 않은 것만 돌려준다(세대 번호).
   - 고정이 `BudgetExceeded`로 실패하면 지금처럼 기다렸다 돌려주고 다시 시도한다.
   - 1/4는 런타임의 미리 읽기 창 상한(한도/4, 0115)과 같다. 미리 읽기가 쓸 자리를 남긴다.
   - 결과(개발 측정): 전부 상주 + 체크포인팅 4.12 → 3.22초(PyTorch 3.17초와 같음). 체크포인팅 없음 3.63 → 2.85초. 768MiB + 체크포인팅 4.90 → 4.20초.
2. **`memopro.finetune(checkpointing=None)`(python/memopro/llm.py)**
   - 기본은 자동이다. 첫 단계 전에 32토큰 조각으로 체크포인팅 없는 학습 forward를 한 번 돌려, MPS에 남는 메모리(`current_allocated_memory` 차이)로 토큰당 활성값을 잰다.
   - `seq_len`에서의 활성값이 `ACTIVATION_ROOM` = 512MiB를 넘을 때만 체크포인팅을 켠다. MPS가 아니면 잴 수 없으므로 켠다.
   - 체크포인팅을 끄면 흘려 쓰는 가중치를 단계마다 세 번이 아니라 두 번 지난다.
   - 결과(개발 측정): 768MiB 129토큰에서 체크포인팅 4.20초 → 끔 3.25초. 활성값으로 footprint가 약 450MiB 늘었다.
   - 512토큰에서는 끄면 footprint +3.3GB라서 켜야 한다.
   - `FinetuneResult.checkpointing`에 무엇을 골랐는지 남긴다.
- **시험**
  - `test_finetune_checkpoints_only_when_activations_would_not_fit`(MPS, 작은 Qwen2): 넉넉하면 끄고, `ACTIVATION_ROOM`=0이면 켠다. 두 경우의 손실 차이는 1e-3 이내다.
  - 기존 MPS 시험(동일성, 행 불변, 초안)도 모두 통과한다(`tests/test_rt_torch.py` 16개).

## 남은 격차 (정직하게)

- 모델이 들어가는 경우 mlx-tune(E034, 1.08초/단계)과의 차이는 대부분 **PyTorch MPS 자체**다. PyTorch를 그냥 써도 2.48초다.
- 커널 경쟁은 목표 밖이다(0148). 그래서 이 차이는 이번 범위에서 줄이지 않는다.
- 흘려 쓰기의 부가 비용과 불필요한 가중치 통과는 이번 제작이 줄이는 몫이다.
