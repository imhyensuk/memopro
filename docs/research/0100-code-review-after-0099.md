# 0100. 재측정 전 정밀 코드 검토: 0099 예산 변경의 빈틈 7건과 노트북 결함 2건 보완

- **날짜**: 2026-09-29
- **유형**: implementation (검토 + 수정)
- **상태**: 확정. CUDA 재측정(E023, 0101) 전
- **관련 기록**: 0099 (D8+D5, D9, O1), 0098 (E022), 0059 (예산 형식, `budget_basis`), 0052 E6 (γ 예산 축소)

## 요청

> "PR #28 병합하고 재측정용 노트북 파일 보내줘. 파일 작성 전에 다시 한 번 정밀하게 코드들을 분석해서 버그나 오류 포인트를 보완해."

## 방법

- 0099의 라이브러리 변경 전체(diff)를 다시 읽었다. 이미 메모리에 있는 모델을 예산에 더하는 새 규칙이 기존 규칙과 만나는 곳을 하나씩 따라갔다: 예산 기준(`budget_basis`), 통합 메모리, γ 축소, 강제 크기.
- 재측정에 쓰는 노트북 코드를 다시 읽었다: `common.py`, `worker_common.py`, `worker_train.py`, `worker_infer.py`, `cell_remeasure.py`.
- 학습 한 단계의 실제 분할 경로(`step` → `_step_once` → `_plan_first`)를 따라가 계획 결과와 실행 결과가 맞는지 확인했다.

## 1. 라이브러리 결함과 수정

| # | 결함 | 영향 | 수정 |
|---|---|---|---|
| B1 | `budget_basis="total"`이면 호스트 측정값이 전체 메모리다. 이미 모델을 포함하는데도 0099가 모델 크기를 또 더했다 | 호스트 예산이 모델 크기만큼 부풀어 계획이 낙관적이 된다 | `total` 기준에서는 호스트에 더하지 않는다(`compute_budget`) |
| B2 | 통합 메모리(MPS)는 장치 예산이 `min(MPS 한도 남은 양, 호스트 가용)`이다. 0099는 min을 먼저 구한 뒤 더했다. `total` 기준이면 호스트 쪽이 이미 모델을 포함하므로 이중 계산이 된다 | Mac에서 `budget_basis="total"`일 때 낙관적 | 두 한계 각각에 알맞게 더한 뒤 min을 구한다(호스트 쪽은 `total`이면 더하지 않음) |
| B3 | γ 압박 축소(`_under_pressure`)가 모델을 포함한 총량에 계수를 곱했다(0099 이전에는 남은 양에 곱했다) | 압박 시 예산이 모델 크기의 절반만큼 더 줄어, 계획이 불필요하게 micro-batch 1로 떨어질 수 있다 | 이미 가진 양은 두고, 나머지에만 계수를 곱한다. 강제 크기는 그대로 |
| B4 | `resident_bytes`가 bitsandbytes 양자화 가중치의 보조 텐서(nf4 `quant_state`의 absmax·code·offset과 이중 양자화의 중첩 상태, int8 `SCB`)를 세지 않았다. 7B nf4의 absmax는 약 0.4GB로 추정한다 | 크기 상한을 준 경우 총량 계산이 그만큼 느슨하다. 자동 예산에서는 계획에서 상쇄된다 | 보조 텐서도 센다. 같은 메모리를 가리키는 텐서(묶인 가중치, int8 `CB`)는 `data_ptr`로 한 번만 센다 |
| B5 | 다중 GPU에서 예산은 첫 GPU에 대한 것인데, `resident_bytes("cuda")`가 모든 GPU의 텐서를 셌다 | 다른 GPU에 있는 모델을 첫 GPU 예산에 더한다 | CUDA는 0번(또는 번호 없음)만 센다 |
| B6 | 학습 계획이 `budget.device or budget.host`로 예산을 골랐다. 장치 예산이 0이면(상한 0, γ 축소) 거짓으로 보고 호스트 예산을 썼다 | 장치에 여유가 없는데 큰 호스트 예산으로 계획해 OOM 재시도로 이어진다 | `device if device is not None else host` |
| B7 | 계획이 "앞으로 생길 옵티마이저 상태"를 Adam 계열 이름일 때만 셌다(2배). 모멘텀 SGD, RMSprop 등은 0으로 봤다. 모르는 옵티마이저도 0이었다 | 첫 `step()`에서 상태가 생기며 계획보다 메모리를 더 쓴다 | `optimizer_state_to_come`: Adam 계열 2배(`amsgrad` 3배), bitsandbytes 8비트 원소당 2바이트, SGD는 모멘텀이 있으면 1배, RMSprop 1(+모멘텀 +centered), Lion·Muon 1, Adafactor 약 0, 그 밖은 Adam처럼(보수적) 센다. 상태가 이미 있으면 0이다(Adagrad처럼 생성 때 만드는 경우 포함). 이미 있는 상태는 보유 메모리로 예산에 들어가 있다 |

### 함께 고친 작은 것

- **`memopro run`의 int4 안내**: `memopro run`에서는 사용자가 코드를 고치지 않으므로 "quality='low'" 대신 실제로 쓸 수 있는 "`memopro run --quality low`"로 쓴다(CLI에 있는 옵션).
- **고른 분할의 일관성**: γ가 압박이 풀려 micro-batch를 두 배로 올릴 때도 `even_micro`를 쓴다(OOM 재시도는 0099에서 이미 적용).

### 확인했지만 고치지 않은 것

- **첫 단계의 분할**: 계획을 위해 첫 단계에서 표본 하나를 먼저 돌리고 나머지를 나눈다(16개, micro 8이면 1+8+7). 첫 단계에만 해당하고, 손실 가중치가 표본 비율이라 정확성은 유지된다.
- **`_measure_first`의 부작용**: CUDA 최대 메모리 통계(`reset_peak_memory_stats`)를 초기화한다. 사용자가 그 통계를 보고 있으면 첫 계획 이전의 최대값을 잃는다. 기록만 해 둔다.
- **CPU의 메모리 매핑 가중치**: safetensors를 CPU에 매핑해 둔 모델이면, 그 페이지는 보수적 가용량에서 "사용 중"이 아닐 수 있다. 그런데 보유 메모리로 다시 더하므로 호스트 예산이 낙관적일 수 있다. 가능성만 확인했고 재현하지 않았다. 흔한 경로(GPU 학습)에는 해당하지 않는다.
- **옵티마이저 `step()`의 임시 메모리**: foreach 구현은 단계마다 파라미터 크기만큼의 임시 텐서를 만들 수 있다. 계획은 역전파 최대값만 본다. 임시 메모리는 micro-batch와 무관해 계획으로 줄일 수 없으므로, OOM이면 재시도 사다리가 맡는다.
- **MPS 캐시**: CUDA처럼 torch 캐시 여유를 가용량에 더하지 않았다(0099와 같음).

## 2. 노트북 결함과 수정

| # | 결함 | 수정 |
|---|---|---|
| N1 | 모델을 바꿀 때마다 로컬 복사본을 모두 지워, 같은 7B를 세 번 복사했다(E022에서 약 15분, 0098) | 새 셀은 `stage(model)`이 다음에 쓸 모델만 남기고 지운다. 7B의 모든 경우를 한데 모아 한 번만 복사한다 |
| N2 | 로컬 복사가 중간에 끊기면(런타임 끊김) 반쯤 복사된 폴더가 다음 실행에서 완성본으로 쓰였다(폴더가 있으면 그대로 반환) | `<이름>.partial`에 복사한 뒤 이름을 바꾼다. 남은 `.partial`은 지우고 다시 복사한다 |

- **보강**
  - `env.json`의 `build_has`에 `0099_fixes`, `0100_fixes`를 더했다.
  - 새 셀은 이 둘이 참이 아니면 측정 전에 멈추고 이유를 알려 준다. E022는 경고만 했다.
  - 학습 워커에 `memopro_micro1`(micro-batch 1 고정, 계획한 분할의 정확성 기준) 경우를 더했다.
  - 세션 시작 때의 CUDA 상태(`session_start`: free, allocated, reserved)를 기록한다. 0099의 캐시 여유 가정을 실측으로 확인하기 위해서다.
  - QLoRA memopro 경우에도 단계별 micro 기록(`session_trace`)을 남긴다.
- **회귀 검사**: `int4_quality_note`는 CUDA에서 bitsandbytes 문구(`BNB_INT4_QUALITY_NOTE`)를 기대한다. 옛 빌드면 옛 문구를 쓴다(0099에서 반영).

## 시험

- 새 파일 `tests/test_review_0100.py` (7개)
  - B1: `total` 기준의 호스트.
  - B2: 통합 메모리의 두 한계.
  - B3: 압박 축소는 가진 양 밖만, 강제 크기는 그대로.
  - B4: 양자화 보조 텐서를 한 번씩 센다.
  - B6: 장치 예산 0이 호스트 예산으로 바뀌지 않는다.
  - B7: 옵티마이저별 상태 추정. 동결 파라미터 제외, 상태가 생긴 뒤 0.
  - `run` 안내 문구.
- 전체 시험 277개 통과(270 + 7). ruff check·format 통과. 노트북 5개를 다시 만들었다(`tests/test_colab_notebook.py`에 `remeasure2` 추가).
- 새 셀을 로컬 MPS에서 작은 설정(GPT-2 배치 4, 3단계, 1.5B)으로 끝까지 돌렸다(`MP_LOCAL_SMOKE`). 판정 표와 학습 표가 만들어졌다.
  - T1·T2 pass(손실 차이 3.4e-7). CUDA가 필요한 항목(QLoRA, bitsandbytes 문구, 7B가 들어가지 않는 조건)은 예상대로 n/a 또는 fail이었다. 측정에는 쓰지 않는다.

## 논문 매핑

- **논문 B Design/Lessons**: 예산의 뜻을 "이미 쥔 것을 포함한 총량"으로 바꾸면, 측정 기준(`total`), 통합 메모리, 동적 축소(γ)가 모두 그 뜻을 따라야 한다. 한 곳의 의미 변경이 주변 규칙 네 곳에 파급된 사례다.
