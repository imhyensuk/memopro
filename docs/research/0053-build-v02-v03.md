## 2. 사전 등록 기준의 수정 (A2-2) — 실행 전

0052 E2의 A2-2는 "최종 파라미터의 최대 상대 차이 ≤ 1e-5"였다. 실제 OOM 시험을 하기 **전에** 로컬에서 기준 자체를 점검했다(GPT-2 2층, 배치 8을 마이크로배치 2로, 3스텝).

| 비교 | 상대 차이 |
|---|---|
| 한 배치의 그래디언트(마이크로배치 누적 대 전체 배치) | **3.1e-7** |
| SGD 3스텝 후 파라미터 | **5.3e-7** |
| AdamW 3스텝 후 파라미터 | **2.9e-4** |

누적 자체는 정확하다(fp32 합산 순서 차이). AdamW는 갱신량을 `m / (√v + ε)`로 정규화하므로 0에 가까운 그래디언트 좌표에서 작은 차이를 키운다. 따라서 파라미터 비교 기준을 AdamW에 적용하는 것은 **기준이 잘못된 것**이다. 수정한 기준은 다음과 같다.
- **그래디언트와 SGD 파라미터**의 상대 차이 ≤ 1e-5
- AdamW는 값을 보고만 한다

이 수정은 판정 대상 실험(Colab 4차) 전에 기록한다.

| 항목 | 결과 |

| lint | ruff, clippy, rustfmt 통과 |
| 탐색 시험(v0.2·v0.3) 12종 | **결함 0/12**. 실제 GPT-2를 예산 400MB로 불러오면 bf16이 선택되고 생성까지 된다. 실제 GPT-2 `check`는 학습 2,327MiB, 추론 658MiB. 튜플 배치 10개를 마이크로배치 3으로 나눠도 차이 1.5e-8. `train_session`과 동면을 섞어도 비트 동일. 컴파일 모델 + OOM 재시도, `optimize` 후 동면, `run --census`, 스크립트 종료 코드·예외 전파, γ 이중 활성화, 옵티마이저 없는 정밀 모드, 없는 모델 id 오류, 비율 예산의 doctor 표시 모두 정상 |

| A2-1c (fail-open) | 첫 구성에 실패를 주입하면 다음 구성(반정밀도)으로 다시 불러오고, 두 기록이 `report()`에 남는다 |
| census 정밀 모드 | 작은 GPT-2(AdamW 3스텝 후) 결과는 가중치 8비트, 그래디언트 8비트, 옵티마이저 상태 16비트, 저장 활성값 8비트였다. 경량판(재구성 오차 기준)은 그래디언트에 ">8비트"라고 했지만 **학습 영향 기준으로는 8비트면 충분했다.** 두 기준이 다를 수 있다는 논문 A의 관찰 후보다. 파라미터·옵티마이저 상태·그래디언트는 비트 단위로 복원됐다 |

**탐색 중 고친 것**:
1. float16 autocast에 손실 스케일링이 없었다. T4처럼 bf16이 느린 GPU에서 마지막 단계로 켜지면 작은 그래디언트가 0이 되는 **조용한 수치 오류**가 될 수 있다. 그래서 float16이면 항상 `GradScaler`를 쓰고, 만들 수 없으면 그 단계를 건너뛴다.
2. 합 손실(`sum`)에 평균 가중치를 쓰면 기울기 크기가 조용히 바뀐다. `reduction` 인자를 추가했다.
3. γ 기록이 이전 감시의 이력을 이어받았다. `enable`마다 새로 시작하게 했다.
4. 예산 비교 테스트가 실시간 가용 메모리 변동에 흔들렸다. 고정 예산으로 바꿨다.

## 4. 관찰

- **이 Mac의 압박 수준은 계속 "경고"(2)다.** γ를 켜면 `load` 예산이 절반이 되어, 예산 2MB로 들어가던 작은 모델이 "맞는 구성 없음"이 됐다(설계대로 동작). 8GB 기기에서는 경고가 상시 상태일 수 있으므로 **수준별 예산 계수와 PSI 기준은 실측 보정이 필요하다.** γ 평가 실험(E013, 별도 사전 등록)의 첫 질문으로 둔다.
- 경량판 필요 비트(재구성 오차)와 정밀 모드 필요 비트(학습 영향)가 그래디언트에서 달랐다(>8 대 8).

## 한계

- torch 내부 API에 기댄다: `torch.distributed._tools.mem_tracker.MemTracker`, `FakeTensorMode`. 바뀌면 `check`는 가중치만 예측하고 `train_session`은 계획 없이 OOM 재시도만 한다(fail-open).
- CPU·통합 메모리에서는 OOM이 예외가 아니라 스왑으로 나타날 수 있다. 그래서 `train_session`은 첫 표본 측정으로 미리 계획한다. 재시도는 CUDA·MPS 한도 초과에서만 확실하다.
- `run`의 로딩 정책은 transformers `PreTrainedModel.from_pretrained`에만 적용된다.
- γ의 효과는 아직 측정하지 않았다(E013).
- Windows는 로컬에서 확인하지 못했다(CI).

## 논문 매핑

- **논문 B System**: 메타데이터 기반 크기 추정, 할당 없는 추적, 품질 등급·선호에 따른 후보 선택, OOM 재시도의 정확성 조건(표본 가중), 안전 지점에서만 행동하는 γ, 필요할 때만 개입하는 `run`.
- **논문 B Evaluation**: 5절의 사전 등록 조건과 기존 도구 비교(accelerate).
- **논문 A**: census 정밀 모드의 "학습 영향 기준 필요 비트". 재구성 오차 기준과의 차이.
- **연구 방법론**: 판정 실험 전에 기준 자체를 점검해 AdamW 증폭을 발견하고 기준을 고친 사례.
