## 해석

- **라이브러리의 약속은 지켰다.** 프로세스는 예산 + 256MiB 안이었다(E041b와 같은 +3.27GB).
- **스왑 기준은 기계 상태 때문에 실패했다.**
  - 시작 때 이미 스왑 2.1GB를 쓰고 있었다. 첫 시도가 다른 프로그램의 메모리 2.8GB를 스왑으로 밀어냈고, 둘째 시도에서도 0.67GB가 더 밀려났다.
  - 8GB 기기에서 약 3.3GB 프로세스는 다른 앱이 열려 있으면 들어갈 자리가 없다.
  - E038b는 사용자가 다른 앱을 닫은 상태에서 같은 크기(약 3.0GB)로 스왑 −25MiB였다.
- 0190에서 "연구자의 동시 빌드 탓일 가능성이 높다"고 했으나, 이번 결과로 보면 **동시 빌드가 없어도 실패한다.** 0190의 그 해석은 근거가 약했다(기록은 고치지 않고 여기서 바로잡는다).

## 선택지 (사용자 결정)

- **A. 다른 앱을 닫고 G7 다시 (추천)**: E033c·E038b와 같은 조건. 사용자가 앱을 닫았다고 알려 주면 바로 잰다.
- **B. 더 작은 예산으로 G7b 사전 등록**: 2.5GiB(필요 ≥ 2,296MiB). 프로세스가 약 2.7GB로 줄어 다른 프로그램을 덜 밀어낸다. 대신 가중치 몫이 줄어 느려진다.
- **C. 그대로 두기**: A13은 ✘.
