# 0148. 사용자 결정: 목표 문장 하나로 정리 승인 (0107 + 0123)

- **날짜**: 2026-10-04
- **유형**: decision (사용자 승인)
- **상태**: 확정
- **관련 기록**: 0147 (평가와 목표 초안), 0107 (목표 재정의), 0123 (G4), 0110 (디스크 쓰기 없음)

## 결정

0147 "목표 재확인" 절의 문장을 **그대로 승인**했다(2026-10-04). 선택지는 "그대로 승인 / SSD는 목표에 남김 / 수정 필요"였다.

## 확정된 목표

- **한 문장**: memopro는 메모리가 부족한 기기(8~16GB 노트북·Mac, 작은 GPU)에서, 그 기기 메모리를 넘는 작업을 손실 없이, 보장된 메모리 상한 안에서, 쓸 만한 속도로 돌리게 하는 오픈소스 라이브러리다(Rust 코어 + Python).
- **주 목표 1 — G4-B (AI)**: 기기 메모리를 넘는 LLM의 16비트 LoRA 학습과 추론.
  - 기본은 무손실이다(일반 실행과 비트 동일, 예산과 무관한 결과).
  - 같은 기기에서 Unsloth·mlx-tune·HF가 못 돌리는 크기로 경쟁한다. 커널 속도 경쟁은 하지 않는다.
- **주 목표 2 — G2′·G3 (범용)**: 일반 작업을 필요 메모리의 1/2~1/4에서 돌린다. 무손실, 상한 보장, 느려짐 예측. 엔진은 Rust 런타임 C-R(유지 / 무손실 압축 / 원본 재읽기 / 계보 재계산).
- **유지 — G1**: 접근 계층. **보조 — G4-C**: CUDA에서 Unsloth 류 백엔드를 선택적으로 감싸기.
- **원칙**: 런타임은 디스크에 쓰지 않는다(0110). 0107의 "SSD로 옮기기"는 목표에서 뺀다.
  - 기존 β의 spill(사용자 동의가 있을 때만)은 그대로 둔다.
- **범위 밖**: 코드를 쓰지 않는 최종 사용자, 외부 도구로 안내, 커널 경쟁, 손실이 기본값인 방식.
- **성공 기준**

| # | 기준 | 상태 |
|---|---|---|
| S1 | 8GB M1에서 3B 16비트 LoRA / 16GB Mac에서 7B 16비트 LoRA 완주 | 3B 달성(0138), 7B 미시험 |
| S2 | 무손실 생성이 흘려 쓰기만 할 때의 2.5배 이상 | E033b 3.22배, 관문은 E033c 대기 |
| S3 | mlx-tune 또는 Unsloth와 같은 과제로 직접 비교 | 미시험(설치 허락 필요) |
| S4 | 한 줄 API와 첫 공개 배포 | 미착수 |
