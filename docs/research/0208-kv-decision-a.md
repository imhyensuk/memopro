# 0208. 사용자 결정 A(E044): KV 전용 압축은 만들지 않는다 — 측정 결과로 기록, KV는 덜어 두기와 일반 `adopt`로

- **날짜**: 2026-10-06
- **유형**: decision (사용자 선택)
- **상태**: 확정
- **관련 기록**: 0204 (E044: KV 무손실 약 0.67), 0205·0207 (`adopt`, E045: bf16 KV는 프로세스 메모리가 거의 줄지 않음), 0182 (생성의 KV 덜어 두기)

## 결정

> "A로 진행해" (2026-10-06)

- **KV 캐시 전용 압축 기능(선택지 B: 쉬는 대화만 압축)과 손실 양자화(C)는 만들지 않는다.**
- KV 캐시는 지금처럼 다룬다.
  - 생성 중: 예산에서 자리를 덜어 둔다(0182).
  - 여러 대화를 번갈아 쓰는 사용자: 일반 API `Runtime.adopt(cache)`로 맡길 수 있다(0205, E045에서 결과 동일·예산 준수 확인).

## 근거

1. **E044**: 실제 KV는 무손실로 약 0.67이다. 가중치와 같은 수준이고 이론적 하한(지수 엔트로피) 근처라, 더 나은 무손실 방법의 여지가 거의 없다.
2. **생성의 접근 형태**: 매 토큰이 KV 전부를 읽는다. 생성 중의 KV를 압축하면 매번 풀어야 한다.
3. **E045**: 쉬는 대화의 KV를 맡겨도 프로세스 footprint가 407 → 403MiB로 거의 그대로였다. 아끼는 약 1/3을 꺼내고 넣는 복사본이 먹는다.
4. **일반 API가 이미 그 쓸모를 덮는다**: 대화가 아주 많거나 긴 경우에는 `adopt`로 같은 효과를 얻는다. 전용 기능은 중복이다.

## 남기는 것

- 논문(측정 연구): "추론 상태(KV 캐시)와 가중치의 무손실 정보량이 같다(약 0.67)", "생성의 접근 형태가 무손실 압축의 쓸모를 좁힌다".
- 손실 KV 양자화는 기존 기법을 감싸는 선택지(0010)로 나중에 다시 정할 수 있다. 지금은 범위 밖이다.
