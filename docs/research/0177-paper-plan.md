- **상태**: 제안

## 요청

> "지금까지 작업한 모든 연구 기록들을 기반으로 할때, 어떤 논문이나 연구 보고서를 작성할 수 있고, 어떤 것을 작성하는 것이 좋을지 추천해줘. 하나의 심도 깊은 논문보다는 여러 논문이 학사 논문에 더 유리할 것 같아."

## 0033 계획과 달라진 점

- 0033은 **논문 A(census 측정 연구)를 주력**, 논문 B(도구 논문)를 배포 뒤로 두었다.
- 그 뒤 목표가 바뀌었다(0107, 0123, 0148). 측정이 쌓인 곳은 **런타임 C-R과 G4**다. 논문 A의 실험 E012는 아직 돌리지 않았다.
- 그래서 지금 쓸 수 있는 논문은 대부분 0033의 "논문 B" 쪽에서 나온다. 이를 **기여가 겹치지 않는 짧은 논문 여럿**으로 나눈다.
- 나눌 때의 원칙: 논문마다 **다른 질문, 다른 실험 데이터**를 쓴다. 같은 결과를 여러 논문에 나눠 싣지 않는다(중복 게재·쪼개기 게재 금지). 겹치는 배경은 서로 인용한다.

## 추천

**학사 논문용으로는 P1 + P2 + P4를 먼저, 여유가 있으면 P3 또는 P6을 더한다.**

1. **P1(대표 논문)**
   - 가장 강한 결과다: 8GB M1에서 14.2GiB 7B를 16비트로 학습, 예산이 달라도 손실 비트 동일, 같은 기기에서 mlx-tune은 3B도 못 돌림.
   - 데이터가 다 있다. 위협 요인(한 기기, 한 모델 계열)은 Threats 절에 쓴다. 다른 모델 계열 하나를 더 재면 크게 좋아진다.
2. **P2(짧은 알고리즘 논문)**
   - 질문이 좁고 결과가 깨끗하다: "여러 행 검증은 bf16에서 결과를 바꾼다(0141의 실제 사례) → 행 불변 검증으로 비트 동일 + 2.8~3.8배".
   - P1과 데이터가 겹치지 않는다(학습 대 생성).
   - **주의**: 추론 결정성·배치 불변성에 관한 선행 연구를 다시 조사해야 한다. 지금 기록에는 추측 디코딩 쪽(0139: SubSpec, ML-SpecQD 등)만 있다. "조사 범위에서 찾지 못함"으로만 쓴다.
3. **P4(경험 보고)**
   - 쓰기 쉽고, 다른 사람에게 바로 쓸모 있다. 재현 코드가 이미 있다.
   - 결함을 PyTorch에 보고하고 이슈 번호를 인용하면 더 단단해진다(외부 게시는 사용자 몫).
4. **P3 또는 P6(넷째)**
   - P3은 가치가 크지만 작업 종류를 2~3개 더 재야 한다.
   - P6은 지금 데이터로 쓸 수 있다. 사전 등록과 기각의 과정을 보여 주는 점이 학사 논문에서 연구 방법론의 증거가 된다.

**지금은 쓰지 않을 것**: P8(실험 미실행), β·γ의 가치 논문(E010 수집 전에는 근거 없음).
