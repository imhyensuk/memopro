# 0128. 투명 페이저의 핑퐁 결함: CI 파이썬 시험이 3시간 36분 — 최근 폴트 청크 보호로 수정

- **날짜**: 2026-10-03
- **유형**: implementation (결함 발견·수정)
- **상태**: 확정. CI 재확인 뒤 PR #38 병합, 그다음 E027
- **관련 기록**: 0124 (3단계 제작), 0122 (E027 사전 등록)

## 발견

- PR #38의 CI는 모두 통과했다.
  - Linux에서 페이저 Rust 시험 4개와 C 연기 시험이 실제로 돌았다. C 연기 시험 결과: 최대 7.0 / 한도 8.0MiB, 재계산 1회, 쓰기 0.
  - 파이썬 투명 모드 시험도 맞는 결과를 냈다.
- 그러나 **Python 3.11·3.14 작업이 각각 3시간 35~36분**(12,935초, 12,986초) 걸렸다. 진행 표시의 74~98% 구간(투명 모드 시험이 있는 곳)에서 시간이 흘렀다. 보통은 몇 분이다.

## 원인 (분석)

- 페이저는 폴트를 시계로 쓰는 재사용 거리로 내보낼 청크를 고른다. 반복 훑기에서는 이것이 "방금 들어온 청크를 먼저 내보내기"(MRU)가 된다.
- 그런데 `x[:] = y`처럼 두 배열을 번갈아 읽고 쓰는 코드에서는 다음이 반복된다.
  1. x의 청크에서 폴트가 나면, 방금 들어온 y의 청크(지금 읽는 중)를 내보낸다.
  2. y를 다시 읽으면 폴트가 나고, x의 청크를 내보낸다.
  3. 원소 몇 개마다 이 핑퐁이 반복된다.
- 명시적 런타임은 쓰는 중인 버퍼를 고정으로 보호하지만, 투명 모드에는 고정이 없다. 이 점을 설계에서 놓쳤다.
- 이 Mac에는 userfaultfd가 없어 CI 전에는 잴 수 없었다.

## 수정

- `choose`가 **가장 최근에 폴트가 난 청크들을 "지금 쓰는 중"으로 보고 내보내지 않는다.**
  - 개수는 들어가는 청크 수의 1/4, 최대 16개(`HOT_CHUNKS`).
  - 그런 청크만 남으면 그중 가장 오래전에 들어온 것을 내보낸다.
- 시험 `two_arrays_used_in_step_do_not_ping_pong` 추가(Linux): 16MiB 두 영역에서 `dst[i] = src[i] + 1`, 예산 8MiB. 폴트 ≤ 청크 수의 4배.
- Linux 대상 clippy와 macOS 시험 통과. Linux 실제 확인은 CI.

## 논문 매핑

- **Design**: 투명 페이징에서 "사용 중" 신호가 없을 때 MRU가 동시 피연산자 사이에 핑퐁을 만든다는 점과, 최근 폴트 보호 창. CLOCK·2Q의 "최근 들어온 것 보호"와 같은 계열(새 주장 없음).
- **Threats**: 개발 기기(macOS)에서 잴 수 없는 경로는 CI가 첫 측정이다.
