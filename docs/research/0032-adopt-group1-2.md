## 사용자 결정

> "1번부터 2번까지 전부 승인할게. 대신에 3번에서 연구 및 논문 방향성은 다시 한번 상세하게 알려줘"

### ① 개발 시작 전 (11개 항목)

| 항목 | 결정 |
|---|---|
| **I1** (+P8, H5 측정) | **β 수요를 구현보다 먼저 측정한다.** E006 계측 도구로 사용자와 동료 3~5명의 실제 노트북 세션을 수집한다(**E010**). 원본 파일이 있는 유휴 메모리의 비율도 잰다. 판정 기준은 수집 전에 사전 등록한다. 새 관문 **Gβ**에서 β의 범위를 정한다 |
| **R1** | Rust 코어 v0.1의 중심 = 방출 엔진 (0027 반영분의 공식 승인) |
| **H1** | β 1순위 = **원본 파일에서 다시 읽기**(SSD 쓰기 0). 원본과 같은지는 **해시로 확인**한다. 텐서 버전 번호는 `.data`를 거친 수정을 잡지 못한다(확인: `0 → 1 → 1 → 1`) |
| **H2** | 내장 SSD 쓰기는 **기본으로 끈다**(`disk_writes="ask"`). 허락할 때만 쓰고, 제안 화면에 쓰기량을 표시한다 |
| **H3** | SSD를 쓸 때 쓰기 최소화: 바뀌지 않은 데이터는 다시 쓰지 않음(해시 일치 시 기존 파일 재사용), 짧은 시간 반복 동면 경고, 자동 모드·γ의 하루 쓰기 한도, 압축으로 쓰기량 감소(E009에서 판단) |
| **H4** | SSD 성능 보호: 낮은 I/O 우선순위(macOS `setiopolicy_np`, Linux idle 클래스는 효과를 실측), 여유 공간 20% 미만이면 SSD 사용 안 함, 큰 순차 쓰기 |
| **H6** | 사용자 선택 인터페이스: `--mode source｜host｜compress｜bf16｜spill`, `--plan`(방법별 비교, 실행 없음), `%wake`, 전체 정책(`memopro.configure`, `memopro.toml`, `--disk-writes never`, `MEMOPRO_DISK_WRITES`). 고른 방법이 불가능하면 조용히 바꾸지 않고 이유와 대안을 알린다. 안전 검사는 우회할 수 없다. 손실 방법은 명시할 때만 쓴다 |
| **P5** | 방출 파일 안전성: 권한 0600, 정상·비정상 종료 시 정리, 다음 실행 시 남은 파일 청소, 디스크 예산 준수, pickle 금지(원시 버퍼 + 메타데이터) |
| **I4** | `import memopro`만으로는 전역 상태 변경·무거운 import·속도 저하가 없다. CI 테스트로 보장한다 |
| **I5** | 대리 객체 없는 **명시 핸들** 방식: `h = memopro.hibernate.now(obj)` → `obj = h.wake()`. 대리 객체 방식(`%hibernate`)은 편의 기능이다 |
| **브랜치 병합** | `x1-first-experiments` → main 병합 |

## 개발 순서 변경 (I1)

```
이전 (0028): 방출 엔진 → E009 → hwinfo → ledger → census → doctor → β

변경:
 ① E010 사전 등록 → 실데이터 수집 시작 (병행, 동료 참여 필요)
 ② hwinfo → doctor
 ③ census (빠른 모드 + 정밀 경량판, 정확성 검증, 행동 권고, HF·Lightning 콜백)
 ◆ Gβ 판정 (E010)
    ├ 수요 확인 → 방출 엔진(원본 읽기·해시 우선, RS1~RS5, P5, H3·H4) → E009 → E011 → β(H2·H6·I5) → Colab 검증(I2)
    └ 수요 미약 → β 범위 축소(CUDA 호스트 이동 중심), census 비중 확대 — 결정 기록 후
 ④ 시연 노트북(I3·I9), import 무비용 테스트(I4) → 🚀 v0.1.0
```

- doctor와 census는 β 수요와 관계없이 쓸모가 있으므로 Gβ 전에 만든다.
- 방출 엔진의 역할이 바뀐다(H1). 주 경로는 **원본 파일 → 텐서 읽기 + 병렬 해시 확인**이고, SSD 쓰기는 최후 수단이다. RS1~RS5는 읽기·쓰기 경로 모두에 적용한다.

## 한계

- E010은 동료 참여가 필요해 기간을 예측하기 어렵다. 그동안 doctor·census를 진행하므로 개발이 멈추지는 않는다.
- Gβ의 구체적 판정 기준(예: 메모리 압박 빈도, 유휴 바이트 비율)은 아직 정하지 않았다. E010 사전 등록 기록에서 확정한다.
- H1의 효과는 "원본이 있는 유휴 메모리의 비율"에 달려 있다. 이 값도 E010에서 측정한다.

## 논문 매핑

- **도구 논문 System 절**: β의 쓰기 없는 방법 우선 계층(원본 재읽기 → 장치 이동 → RAM 압축 → 명시 허락된 SSD)과 SSD 수명 정책. "메모리 회수 도구가 저장장치 수명을 비용으로 지불하지 않도록 한 설계"로 기술한다.
- **연구 방법론**: 수요 측정을 구현 앞에 둔 관문(Gβ). 기법 검증(Gα)과 같은 사전 등록 방식을 제품 수요에 적용했다.
