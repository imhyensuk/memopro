## 해석

- **사전 등록의 예상과 같다**(0196).
- **scikit-learn은 E040에서 실패했다가 이번에 통과했다.** preload가 C 확장(scipy 희소 행렬, scikit-learn)의 큰 `malloc`까지 페이저에 넣고, 프로세스 예산이 나머지 426MiB를 맞췄다.
  - 다만 같은 한도의 OS 스왑(28.3초)보다 느리다(39.8초). 영상 묶음은 OS 스왑보다 3.3배 빠르다(21.2초 대 69.5초).
- **데이터프레임과 시뮬레이션은 이 방식의 한계다**(0196의 진단 그대로).
  - 데이터프레임: 무작위 접근 → 되읽기 폭주.
  - 시뮬레이션: 압축 뒤에도 한도를 넘는 데이터 → overruns.
- 결과는 언제나 같았고 디스크에 쓰지 않았다(T1이 판정된 두 작업).
