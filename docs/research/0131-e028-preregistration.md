# 0131. E028 사전 등록: G4-B1 — 8GB M1에서 양자화 없는 16비트 LoRA를 메모리보다 작은 예산으로, GPU 스트리밍(E1)

- **날짜**: 2026-10-03
- **유형**: experiment (사전 등록)
- **상태**: 확정. 실행 전
- **관련 기록**: 0130 (E1 제작과 개발 점검), 0125 (G4 설계, §6 경쟁 목표), 0121 (E026 D1: CPU 1.5B LoRA)

## 질문

memopro가 8GB Mac에서, 기기 메모리에 들어가지 않는 크기의 모델을 **양자화 없이(bf16 원본 그대로)** LoRA로 학습할 수 있는가? 그 속도는 쓸 만한가?

- 이것이 G4의 경기장이다. 메모리가 부족할 때 Unsloth의 답은 QLoRA(4비트, 손실)다(0125).

## 환경

- MacBook Air M1 8GB, 로컬 모델(Qwen2.5-1.5B-Instruct 3.09GB, Qwen2.5-3B-Instruct 6.17GB, bf16).
- 경우마다 새 프로세스, `caffeinate -i`, `MallocLargeCache=0`, `PYTORCH_MPS_LOW_WATERMARK_RATIO=0.1`(0080·0081).
- 스왑 전후 기록, 오염 규칙(0114 수정 5: 64MiB 넘게 늘면 한 번 다시).
- **메모리 지표**: `proc_pid_rusage` V4의 평생 최대 `phys_footprint`(GPU 할당 포함). 기준은 모델을 만들기 직전의 footprint다.

## 경우

| # | 모델 | 예산 | 장치 | LoRA·데이터 |
|---|---|---|---|---|
| L15 | 1.5B | 768MiB (≈1/4) | MPS | r=8, `q_proj`·`v_proj`, fp32 어댑터, AdamW lr 1e-3, 1 × 128토큰, 5단계, WikiText-2 train(0114 수정 8) |
| L3a | 3B | 1GiB (≈1/6) | MPS | 같음 |
| L3b | 3B | 768MiB (≈1/8) | MPS | 같음 |

- 3B를 1.5GiB가 아니라 1GiB·768MiB로 한다. 활성값과 MPS 힙까지 더하면 1.5GiB는 이 기기의 보수적 가용 메모리(약 2GiB)를 넘어 스왑을 부를 수 있다(0114 수정 4와 같은 이유). 더 작은 예산이라 더 엄격한 시험이다.

## 기준 (실행 전 고정)

| # | 기준 |
|---|---|
| **B1** 속도 | L15의 정상 상태 단계 시간(단계 2~5 평균) ≤ E026 D1 768MiB CPU 값(257.2초)의 1/10, 즉 ≤ 25.7초 |
| **B2** 완주·무손실 | L3a와 L3b가 5단계를 끝내고, 단계별 손실이 두 예산에서 비트 동일하다(같은 장치·같은 계산이므로 예산이 결과를 바꾸지 않아야 함) |
| **B3** 메모리 | 모든 경우에서 footprint 증가 ≤ 예산 + 1GiB(활성값·MPS 힙·어댑터), 스왑 증가 ≤ 64MiB(오염 규칙 적용 뒤), 런타임 최대 계상 ≤ 한도 |

- **보고만**: 단계 시간과 처리량(토큰/초), 단계당 다시 읽은 바이트와 읽기 시간, 첫 단계 시간, L3 손실 곡선.
- **관문 G4-B1** = B1, B2, B3 모두 통과. 실패하면 멈추고 보고한다.

- B1은 다른 날 잰 CPU 값(E026)과 비교한다. 기기 상태 변동이 있지만 기준 여유(10배)가 크다.
- Unsloth·mlx-tune과의 직접 비교는 설치(다운로드) 허락이 필요해 이 실험에 없다.
