## α의 정의 (구현 기준)

- 블록 함수: `f_l(x) = block_l(x) − x`, 즉 `x_{l+1} = x_l + f_l(x_l)` (GPT-2 블록의 두 잔차 덧셈을 합친 형태)
- **힌트**: 은닉 차원 방향 64개 원소 블록별 대칭 absmax 양자화, b비트(정수 준위 −(2^{b−1}−1) … 2^{b−1}−1), 스케일은 fp16
- **고정점 반복 (plain)**: `x⁽⁰⁾ = dequant(h_l)`, `x⁽ʲ⁺¹⁾ = y − f_l(x⁽ʲ⁾)`, k회
- **Anderson 가속**: 같은 사상 `G(x) = y − f_l(x)`에 대한 Type-II Anderson 혼합(m=3), 평가 k회
- **k=0**: 교정 없이 `dequant(h_l)` 사용 (ActNN 방식 대조군)
- **체인 복원 (주 시나리오)**: `x_L`(마지막 블록 출력, ln_f 이전)은 원본 저장, `l = L−1 … 1`을 차례로 복원(y는 직전에 복원한 `x̂_{l+1}`). **`x_0`는 토큰 ID로부터 정확히 재계산**한다(임베딩 조회는 저비용이며 토큰 ID는 어차피 보관됨 — 결과와 무관하게 사전에 정한 설계). 부 시나리오로 `x_0`도 힌트로 복원하는 경우를 함께 보고한다.

## E001 — 야코비안 노름 (H1)

- 측정: 실제 활성값 `x_l`에서 `J_l = ∂f_l/∂x`의 스펙트럴 노름 σ_l. `JᵀJ`에 대한 멱반복 40회(Jv는 이중 역전파로 계산), 시퀀스 2개(T=512)를 각각 계산해 **최댓값**을 σ_l로 한다(보수적).
- **H1 통과**: σ_l < 1인 블록이 12개 중 **9개 이상**.
- 참고: σ < 1은 수렴의 충분조건이다. 실제 수렴은 E002가 직접 판정한다.

## E002 — 복원 수렴 (H2)

- 배치: 4 × 512 토큰(2,048 토큰).
- 격자: b ∈ {2, 3, 4} (+ 8 참고) × k ∈ {0, 1, 2, 3, 4, 5} × {plain, Anderson}.
- 지표: 층 l(1…11)마다 토큰별 상대 오차 `e_{l,t} = ‖x̂_{l,t} − x_{l,t}‖ / ‖x_{l,t}‖`의 평균 E_l(주 지표). 보조: p95, 최댓값, 프로베니우스 상대 오차.
- 진단: 정확한 y를 주는 **국소 복원** 곡선(k ≤ 10), 잔차 `‖x + f(x) − y‖ / ‖y‖`.
- **H2 통과**: b=4, k=3, {plain, Anderson} 중 층 평균이 더 낮은 쪽에서
  ① 층 평균 오차 `mean_l E_l ≤ 1e−2` **그리고** ② 같은 b의 k=0 대비 오차 비율 ≤ 0.5.

## E003 — 그래디언트 정확도 (H3)

- 손실: 인과 LM 손실(레이블 = 입력, 한 칸 이동), 4 × 512 배치 평균.
- 기준 그래디언트 g*: 전체 모델 표준 autograd (fp32, eval).
- **구현 검증 대조군**: 정확한 `x_l`을 넣은 블록 단위 수동 역전파의 g와 g*의 코사인이 **> 0.999999**여야 한다. 아니면 구현 오류로 보고 실험 무효.
- 지표: 전체 파라미터 그래디언트 벡터(묶인 가중치는 한 번만)의 코사인 유사도, 상대 L2 오차, 파라미터 텐서별 코사인(최솟값·중앙값).
- 주 비교: b=4, k=3, 가속 방식은 **E002에서 선택된 쪽**(사전 규칙). 대조군: b=4, k=0. 탐색: b ∈ {2,3,4} × k ∈ {0,1,2,3,5}.
- **H3 통과**: 주 비교의 코사인 ≥ 0.999.

## E005 — 텐서 중복도 파일럿과 OS 압축 기준선 (P3·census)

- 상태: GPT-2 small, `train()`(dropout 0.1), AdamW(lr 1e−4, wd 0.01), WikiText-2 train, 배치 2 × 256, 20스텝 후 21번째 스텝에서 수집.
- 범주: 파라미터, 그래디언트, Adam `exp_avg`, `exp_avg_sq`, 역전파 저장 활성값(`saved_tensors_hooks`, 파라미터·중복 저장공간 제외), 블록 입력 `x_l`.
- 각 범주(최대 64MB 표본)에서 측정:
  - 저장 비트/원소, 바이트 평면별 0차 엔트로피 합(비트/원소)
  - 압축률 ① **OS 방식 대리 지표**: 16KB 페이지 단위 LZ4 (macOS 페이지 크기. Darwin 압축기는 WKdm·LZ4를 쓰며 WKdm은 재현하지 않음), 4KB 페이지 단위 zstd-3 (Linux zram·zswap 대리) ② 청크 전체 zstd-3 ③ **바이트 셔플 + zstd-3** (memopro 후보)
  - 같은 범주를 bf16으로 변환했을 때의 압축률(참고)
- **β 설계 판정 규칙 (사전)**:
  - fp32 파라미터·옵티마이저 상태에서 `R(셔플+zstd) / R(LZ4-16KB) ≥ 1.25` → CPU에서 β 무손실 모드가 OS 압축보다 우위 → CPU 기본 모드로 유지
  - fp32에서 `R(셔플+zstd) < 1.3` → 무손실 압축만으로는 절감이 작다(< 약 23%) → β의 CPU 가치는 **SSD 방출과 명시적 손실 모드(bf16)**에서 나와야 하며, 큰 유휴 객체의 기본 모드를 재검토
  - 두 규칙은 동시에 성립할 수 있다.
