## 배경

- 0106 평가 뒤 사용자는 "새로운 능력이 없다"는 점을 가장 치명적인 약점으로 보았다. 이어서 처음 목표를 다시 밝혔다.

> "제한적인 하드웨어 환경에서도 고차원의 하드웨어 환경에서처럼 구동할 수 있게 도와주는 라이브러리 … 이 성능을 달성하는 것이 가장 목표였고, 이 달성 내용과 과정을 기반으로 연구 논문을 작성하려고 했지."

> "RAM 32GB 환경에서만 구동이 가능하던 모델이나 훈련, 학습, 추론 등을 RAM 16~8GB 환경에서 구동이 가능하게 하는 거지. 그리고 단순히 인공지능 분야에만 국한되는 것이 아니라 메모리의 효율성이 필요한 모든 작업에 활용될 수 있도록 하고 싶어. … 완전히 새로운 아키텍처를 상상해보고 제작해보자고 했던 거지."

> "Rust 언어의 메모리 병목이 없는 것(가비지 컬렉터가 없음)과 병렬 처리가 뛰어난 것 등을 적극 활용해서 만들어도 좋을 것 같아."

- **목표가 어긋난 경위** (기록 대조)
  - 0001의 G2·G3가 사용자의 뜻이었다.
  - 그런데 0010(기존 기법은 감싸기만), 0012(PyTorch 개발자 한정), 0018(α 기각), 0033(G3 장기 과제, 논문 A 주력)을 거치며 memopro는 "기존 기법을 잘 고르는 층"이 되었다.
  - "고성능 기기에서처럼"이라는 성능 목표는 측정 가능한 성공 기준으로 정해진 적이 없다.

## 논의에서 정리한 원리 (결정의 근거)

- **넘을 수 없는 한계는 하나다**: 한순간에 메모리에 담을 수 있는 정보량은 메모리 크기를 넘지 못한다.
- **그 밖은 모두 설계의 문제다.** 소프트웨어가 움직일 수 있는 축은 여섯이다.
  1. 표현: 같은 정보를 몇 비트로 담나.
  2. 동시성: 한순간에 무엇이 살아 있어야 하나(순서 재배치, 알고리즘 재구성).
  3. 저장 대신 계산: 재계산, 가역 계산.
  4. 위치: 압축 RAM, SSD, 다른 기기.
  5. 수명과 공유: 해제 시점, 제자리 연산, 중복 제거, 할당기 낭비.
  6. 압축된 채 계산.
- **공간은 시간으로 살 수 있다**: 시간 t의 계산은 약 √t 공간으로 흉내 낼 수 있다(Williams, STOC 2025, 0108). 문제는 "돌릴 수 있는가"가 아니라 "메모리를 1/4로 줄이는 대가로 시간을 얼마나 쓰는가"다.
- **Rust의 역할**: Rust는 작업이 요구하는 바이트를 줄이지 않는다. 대신 메모리를 줄이는 결정을 안전하게, 상한을 지키며, 계산과 겹쳐 실행하게 한다.
  - 소유권: 버퍼 상태 기계.
  - 결정적 해제: 상한 보장.
  - 안전한 병렬 처리: 미리 읽기, 압축과 계산의 중첩.
  - 저수준 제어: mmap, madvise, io_uring, userfaultfd.
  - SIMD.
  - C ABI: AI 밖으로 확장.

## 결정 (사용자 승인)

> 승인 응답: "기존 지금까지의 memopro 개발 과정에서 얻은 성과들은 유지하면서 위의 새 목표를 적용할 것". 정확성 기본 정책은 "무손실 기본".

### 새 목표

| # | 내용 |
|---|---|
| **궁극** | 메모리가 제한된 환경(예: 8~16GB)에서도, 더 큰 메모리(예: 32GB)가 필요하던 작업을 구동할 수 있게 한다. AI 학습·추론·개발뿐 아니라 메모리 효율이 필요한 모든 작업이 대상이다 |
| **G2′ (주 목표)** | 작업 집합(한순간에 동시에 필요한 메모리)이 기기 메모리 안에 들어오는 작업이면, 필요 메모리의 **1/2~1/4 환경에서 구동**한다. 정확성을 지키고(**무손실이 기본**, 손실 방법은 사용자가 허용할 때만), **메모리 상한을 보장**하며, 느려지는 정도를 **실행 전에 예측해 알린다** |
| **G3 (장기 과제 → 주 목표)** | 기존 기법 조합으로 어려운 부분은 **새 아키텍처**로 달성한다. 큰 버퍼 하나하나를 "만드는 법 + 현재 상태"로 다루는 **Rust 런타임**이, 버퍼마다 그대로 두기·무손실 압축·원본에서 다시 읽기·재계산·다른 계층으로 이동 중 가장 싼 것을 실측 비용으로 고른다. 새로움은 선행 연구 조사(0108)와 사전 등록 실험으로 확인한다 |
| **G1 (유지)** | AI 개발·학습·활용 전 단계의 메모리 부담 최소화. 지금의 접근 계층이 맡는다 |
| **범위** | AI(PyTorch)와 비AI(큰 배열, 이미지, 데이터프레임, 시뮬레이션 등). Python(NumPy, PyTorch)과 C/C++/Rust(C ABI) |
| **성능 기준** | OS 스왑보다 빠를 것. 고성능 기기와의 **격차 해소율**(품질 손실 한도 안에서 고성능 기기 성능의 몇 %)을 잴 것. 메모리 상한 준수 |
| **Rust** | 런타임의 핵심은 Rust가 맡고, Python은 얇은 연결층이 된다. RS1~RS5는 유지한다. RS6~RS8(SIMD 커널, GIL 없는 백그라운드 서비스, `gil_used = false`)의 보류는 설계 단계에서 안전 규칙과 함께 새 결정으로 푼다 |

### 논문 방향

- **주 논문**: 제한된 기기에서 필요 메모리의 1/2~1/4로 구동하는 런타임의 설계와 달성. 내용은 다음과 같다.
  - 격차 해소율 벤치마크.
  - 과정의 발견: T4 bf16 함정, int4 커널, 할당기 힙·조각, 파일 기반 상주 등.
  - 부정적 결과: α, γ.
  - 결함 → 수정 → 사전 등록 재측정의 폐회로.
- 도구 논문(논문 B)은 그대로 후보로 둔다.
