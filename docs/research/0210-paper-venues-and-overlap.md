## 결과 1: 후보별 겹침

판정: **유지**(핵심 기여가 조사 범위에서 발견되지 않음) / **축소**(겹치는 연구가 있어 주장을 좁혀야 함) / **포기**(독립 논문으로는 기여가 남지 않음).

### P1. 8GB 기기에서 7B를 16비트로 LoRA 학습: 상한을 보장하는 가중치 흘려 쓰기 — **축소, 유지 가능**

| 겹치는 연구 | 내용 | memopro와의 차이 |
|---|---|---|
| Soup CLI (2026-08, 블로그·도구, 논문 없음) | 기반 모델을 층 단위로 흘려 쓰며 학습. RTX 3050 4GB에서 Llama-3.1-8B 3.32GB. fp16 또는 NF4, RAM 또는 NVMe에서 읽기. 저자 스스로 조용한 정확성 결함을 보고 | **가장 가깝다(동시대 연구로 인용 필수).** 예산이 활성값까지 포함하는 상한 보장, 예산이 달라도 손실 비트 동일, 거절 규칙, Apple 통합 메모리 무복사, 디스크 쓰기 없음은 다루지 않는다 |
| Dbouk 외 (Qualcomm, arXiv 2606.19528, 2026-06) | 12GB 휴대폰에서 3B LoRA: int4 기반, 칩 밖 오프로드, 선택적 재계산, 근사 softmax | 기반이 int4이고 손실을 근사로 바꾼다(무손실 아님). 상한 보장 없음 |
| Geyko 외 (arXiv 2610.06325, 2026-10-05) | iPhone 17 Pro에서 SmolLM3-3B 4비트 LoRA 지속 학습 측정 | 모델이 메모리에 들어간다. 흘려 쓰기 없음. MLX 역전파 커널 결함 보고(P4와도 겹침) |
| AirLLM, oLLM, ssd-llm, LLM in a flash | 층 단위 흘려 쓰기 **추론** | 학습 아님. AirLLM은 E039에서 충돌 |
| ZeRO-Infinity, MLP-Offload (SC 2025) | 대규모 학습 오프로드 | 데이터센터, 상한 보장·비트 동일 초점 아님 |

- **주장해도 되는 것**: "16비트 가중치가 기기 메모리보다 큰 모델을, 활성값까지 포함한 메모리 상한 안에서, 예산과 무관하게 비트 동일한 손실로 학습"하는 런타임과 그 측정(8GB M1, 3B·7B, mlx-tune·llama.cpp·AirLLM 비교).
- **주장하면 안 되는 것**: "층 흘려 쓰기 학습의 최초", "소비자 기기 LoRA의 최초".

### P2. 흘려 쓰는 가중치 위의 무손실 추측 디코딩: 행 불변 검증 — **축소, 유지 가능 (가장 시의적)**

| 겹치는 연구 | 내용 | 차이 |
|---|---|---|
| Koziev·Sinev·Oseledets (arXiv 2609.15504, 2026-09) | "무손실" 추측 디코딩(Orthrus)이 bf16에서 자기회귀 기준과 궤적이 일치하는 비율이 45%뿐, fp32에서는 100% | **문제(0141에서 우리가 만난 것)를 이미 보고했다.** 해결책은 제시하지 않고 "정밀도를 명시하라"고 권한다 |
| Zhang 외, "Batch Speculative Decoding Done Right" (EMNLP 2026 Findings, arXiv 2510.22876) | 배치 추측 디코딩의 동기화 결함 수정(EqSpec). 배치 1 기준과 90.8~97.3% 일치, 나머지는 배치 의존 부동소수점 효과 | 비트 동일을 달성하지 못했다고 명시 |
| Thinking Machines, "Defeating Nondeterminism in LLM Inference" (블로그, 2025) | 배치 불변 커널 3개로 1,000회 비트 재현 | 배치 크기 불변이지 "여러 행 검증 = 한 행 생성" 불변이 아니다 |
| LLM-42 (Microsoft 외, arXiv 2601.17768, 2026-01) | 빠른 경로로 디코딩한 뒤 고정 모양 창에서 다시 계산해 검증·되감기(결정성) | **발상이 가깝다**(검증을 고정된 계산 경로로). 목적이 결정성이고 초안 모델·오프로드가 없다 |
| SpecExec (NeurIPS 2024), SpecOffload (arXiv 2505.10259) | 오프로드 + 추측 디코딩(가중치 읽기가 지배적이라 여러 토큰 검증이 거의 공짜) | 속도 결합은 이미 있다. 비트 동일성은 다루지 않는다 |

- **주장해도 되는 것**: "검증 행을 일반 생성과 같은 계산 경로(한 행씩)로 돌리면 bf16에서도 일반 greedy와 비트 동일하며, 가중치를 흘려 쓰는 경우 한 행씩 검증의 추가 비용이 작아 2.8~3.8배를 유지한다"(0142·0152·0174). 2609.15504가 남긴 문제에 대한 간단한 해법이라는 위치가 좋다.
- **보강 필요**: 프롬프트 수(지금 4개)를 늘려 일치율·속도 분포를 보고. 2609.15504와 같은 형식(일치율 표)으로.
- **주장하면 안 되는 것**: 오프로드 + 추측 디코딩 결합 자체, 배치 불변성 개념.

### P3. 수정 없는 프로그램을 메모리 절반에서: 압축만 하는 userfaultfd 페이징 — **축소, 결과가 반반**

| 겹치는 연구 | 차이 |
|---|---|
| UMap(LLNL), ExtMEM(ATC 2024), Lightswap | 사용자 공간 페이징 자체는 있다. 파일·SSD로 내보낸다 |
| Loom (GitHub, 2026) | userfaultfd로 RAM보다 큰 영역에 상한 있는 사용자 공간 버퍼 관리자. 디스크(희소 파일)에 쓴다 |
| zswap·zram·TMO, macOS 압축기 | 커널 수준 압축. 응용 의미 없음 |
| IBP (EuroSys 2026, Kamath 외) | ML 텐서의 무손실 비트 압축(GPU). 버퍼 단위 압축 여부 선택 |

- 남는 것: 디스크에 쓰지 않는 **압축 전용** 페이징을 LD_PRELOAD로 수정 없는 프로그램에 걸고 **프로세스 전체 상한**을 거는 조합은 조사 범위에서 발견되지 않았다.
- 약점: 결과가 2/4(영상 4.1배·OS 스왑보다 3.3배 빠름, scikit-learn은 OS 스왑보다 느림, 데이터프레임·시뮬레이션 실패). 실패 원인 분석(무작위 접근, 압축률 한계)을 함께 쓰면 "언제 되고 언제 안 되는가" 논문이 된다.

### P4. PyTorch MPS 함정 경험 보고 — **독립 논문은 포기, P1의 절과 결함 보고로**

| 겹치는 것 | 내용 |
|---|---|
| Niimi (arXiv 2609.22991, 2026-09) | MPS bmm이 2^32 원소에서 조용히 틀림. 체계적 경계 탐색 1,584회. MPS 조용한 오류의 측정 논문 형식을 선점 |
| PyTorch PR #139823, 이슈 #196949·#80192 | `F.pad`가 2^16 원소 이상에서 깨지는 결함 계열(0170의 151,936폭 logits 오염과 같은 계열로 보인다) |
| mps-sentry (GitHub) | MPS 조용한 오류 차등 검사 도구 |
| MLX 역전파 커널 결함(2610.06325) | Apple 기기 학습 함정 보고 |

- 0159의 "내부 차원 > 2^17이고 16384의 배수가 아니면 행렬곱이 NaN"은 검색에서 같은 보고를 찾지 못했다. **PyTorch에 결함으로 올리는 것이 먼저**(외부 게시는 사용자 몫). 논문으로는 P1의 "구현 시 함정" 절로 넣는다.

### P5. macOS 통합 메모리 측정 연구 — **보류**

- 학술 논문은 찾지 못했고 GitHub 이슈(MLX `get_peak_memory`가 실제 footprint를 크게 낮게 보고 등)만 있다. 빈 자리는 있으나 우리 측정이 흩어져 있어 같은 조건으로 다시 모아야 한다(0177과 같음).

### P6. 부정적 결과 모음 — **유지 (짧은 워크숍용)**

- α(잔차 고정점 체크포인팅)는 이론이 예측한 실패(Kim 외 2021)라 그 자체는 약하다. 오진법·삼진법 붕괴(0127), γ 압박 신호 특이도 0.54(0087), KV 압축 "보통" 판정(0204)과 함께 **사전 등록 → 기각** 과정을 보이는 묶음으로만 가치가 있다.
