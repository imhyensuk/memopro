# 0090. 완성도 평가 (0089 시점): 기능은 거의 완성, 기술 검증은 탄탄, 실사용 가치 입증은 부족한 알파

- **날짜**: 2026-09-29
- **유형**: assessment (사용자 요청)
- **상태**: 확정 (평가는 연구자의 판단이며, 수치는 각 기록의 측정값)
- **관련 기록**: 0065 (E011·E014 뒤 현황), 0057 (v0.1~v0.3 종합), 0068~0089

## 요청

> "지금까지의 라이브러리 완성도를 평가해." → "연구 기록으로 남기고 Colab 재검증 준비해."

## 요약

**기능은 거의 다 만들었고 기술 검증도 탄탄하지만, 실제 사용자에게 가치가 있다는 증거가 부족한 알파다.** 판은 0.1.0a1이고 배포하지 않았다.

## 영역별 평가 (백분율은 연구자의 주관적 판단)

| 영역 | 평가 | 근거 |
|---|---|---|
| 기능 구현 | 높음 (약 90%) | v0.1~v0.3 계획 기능이 모두 있고 `NotYetImplemented`가 남지 않았다. 계획 밖으로 파일 기반 상주(0072), MPS int4 백엔드(0069), 긴 입력 경로와 그룹 32(0085), 할당기 설정(0081)을 더했다 |
| 기술 검증 | 높음 (약 75%) | 아래 목록 |
| 실사용 가치 입증 | 낮음 (약 35%) | 외부 사용자 0명, E010 미수집. 8GB에서 쾌적함은 1.5B·3B int4까지만 확인했다 |
| 사용성·문서 | 보통 (약 60%) | 제안(D-a), 품질 비용 보고(Q-a), 꺼진 이유 보고(G1)가 있다. README는 연구 기록 성격이 강하고 빠른 시작이 부족하다 |
| 출시 준비 | 보통 이하 (약 45%) | 판 번호, 이름 선점, 배포 결정과 E010이 남았다 |

- **기술 검증의 근거**
  - Python 시험 251개, Rust 28개가 통과한다. CI는 Linux·macOS·Windows와 512MiB cgroup 환경에서 돈다.
  - β는 비트 단위로 똑같이 복원된다.
  - `check`는 T4에서 학습 오차 −0.2~−1.2%였다(0056).
  - 모든 실험을 사전 등록했고, 실패도 기록했다.

## 강점

1. **숫자로 입증된 개선**
   - 3B: bf16 0.24 tok/s(붕괴) → int4 파일 기반 약 10 tok/s(0071, 0078).
   - 1.5B·3B footprint: 1.5GB → 0.5GB(0080·0081).
   - 1024토큰 프롬프트: 29.2 → 8.7초(0085).
   - `train_session`은 MPS OOM이 나던 학습을 끝까지 돌렸다(0063).
2. **정직한 기본값과 보고**
   - 측정이 나쁘면 기본값을 보수적으로 바꿨다: γ를 macOS에서 기본으로 끔(0089), 제어기는 기능으로 만들지 않음(0082).
   - int4를 고르면 품질 비용을 보고서에 적는다.
3. **재구현 금지 원칙 준수**: 양자화와 커널은 torch·torchao의 조합으로만 만들었다.

## 약점

1. **제품 가치 미검증**
   - 수요 데이터가 없다(E010).
   - β는 del 후 다시 불러오기의 0.90배였다(0063).
   - γ는 쓸 만한 압박 신호를 찾지 못했다(0088).
2. **"훨씬 큰 모델"은 미입증**
   - 8GB에서는 3B까지만, 그것도 int4로 확인했다(품질 비용 PPL +5.7~7.6%, 0084).
   - 7B는 로컬에서 시험하지 않았다. 학습 쪽 쾌적함은 재지 않았다.
3. **최근 기능이 MPS에 치우침**
   - 파일 상주, int4 커널, 할당기 설정은 Apple GPU 전용이다.
   - 마지막 CUDA 검증은 Colab 6차(0056)로, 0059 이후 변경을 거치지 않았다.
   - Linux에서 γ가 쓰는 PSI 기준은 보정하지 않았다.
4. **미검증 항목**: E009(압축 spill), E013b(γ 조치 효과), 긴 입력 경로의 학습 시 비용.
