### 2.2 β hibernate: 유휴 메모리 회수 (v0.1, 연구 코어)

### 2.4 접근 계층: 예산에 맞추기 (v0.2)

기존 도구(transformers, accelerate, bitsandbytes, torchao, torch)를 연결한다. 재구현하지 않고, 신규성도 주장하지 않는다.

| 기능 | 내용 | 근거 |
|---|---|---|
| `memopro.load(id)` | 가중치를 받기 전에 메타데이터로 크기를 계산한다. 후보(원래 형식·반정밀도·int8·int4·CPU/디스크 오프로드) 중 `quality`(`lossless`<`high`<`balanced`<`low`)가 허용하고 `prefer`(`speed`·`quality`·`memory`) 순으로 맞는 첫 구성을 불러온다. 실패하면 원본에서 다음 구성으로 다시 불러온다(실패한 시도의 메모리는 먼저 해제). 양자화 백엔드는 장치에서 실제로 시험해 판정한다 | T4에서 **Qwen2.5-7B를 int8로(최대 8.97GB ≤ 예산 13.89GB)**, GPT-2는 예산에 따라 원래 형식→반정밀도→int8→int4(0054) |
| `memopro.check` / `memopro check` | 추론·학습 최대 메모리를 **할당 없이** 예측한다(가짜 텐서로 정상 상태 한 스텝 추적). `load`의 선택과 마이크로배치 계획도 보여 준다 | T4 6차: 학습 −0.2~−1.2%, 추론 +5%(0056). accelerate보다 6/6 정확(0054) |
| `memopro.optimize(model, goal)` | 이미 가진 모델에 필요한 만큼만 적용한다. 추론은 반정밀도 → torchao int8 → CPU 오프로드, 학습은 체크포인팅. 계획이 안 맞으면 아무것도 바꾸지 않는다 | 테스트 |
| `memopro.train_session` | 정확한 마이크로배치(표본 비율 가중, `reduction`)를 쓴다. OOM이 나면 그 배치를 처음부터 다시 하고, 이어서 체크포인팅 → 활성값 오프로드(CUDA) → 품질이 허용하면 혼합 정밀도(float16은 손실 스케일링)로 넘어간다. 첫 표본으로 미리 계획한다. `max_grad_norm`, 수동 형태를 지원하며 BatchNorm은 경고한다. 옵티마이저 교체·LoRA는 제안만 한다 | T4 실제 OOM 한도에서 완주, SGD 1.58e-7, 활성값 오프로드 2.4e-7(0054). accelerate는 배치를 줄이지만 memopro는 유효 배치를 유지 |

### 2.5 γ와 무수정 실행 (v0.3)

| 기능 | 내용 | 근거 |
|---|---|---|
| 압박 신호 | Rust: macOS `kern.memorystatus_vm_pressure_level`, Linux PSI(cgroup v2 우선). 그 밖의 OS는 fail-open | M1에서 "경고(2)", Colab에서 PSI(시스템) 읽기(0054) |
| `memopro.elastic` (γ) | 감시 스레드는 기록만 한다. 조치는 안전 지점에서만: 셀 경계(캐시 비우기·유휴 객체 쓰기 없는 동면), 학습 스텝 경계(한 단계씩 내리고 평온하면 올림), `load` 예산(경고 ×0.5, 위험 ×0.25), `checkpoint()` | 제어된 신호로 테스트 11개. **효과는 미측정(E013)** |
| `memopro run app.py` | 스크립트를 수정 없이 실행한다. 스크립트가 배치·정밀도를 정하지 않았고 원래 형식으로 들어가지 않는 `from_pretrained`만 예산에 맞춰 불러온다(명시 선택은 바꾸지 않음). γ와 `--census`, `--dry-run`을 지원하며 끝나면 패치를 제거한다 | 하위 프로세스 테스트, 탐색(종료 코드·예외 전파) |

### 2.7 공통

- `import memopro`는 부작용이 없고 torch를 불러오지 않는다(테스트).
- 모든 오류는 `MemoproError` 계층이다(`BudgetExceeded`, `ModeUnavailable`, `IntegrityError`, `ConfigError` 등).
- `report()`는 적용·실패·제안·실측 회수량을 기록한다. fail-open이며, CLI 종료 코드는 0·1·2·3이다.

| 영역 | 0047 (v0.1 직전) | 현재 | 근거 |
