# 0009. 활용 환경 분석: LoRA 보완 관계와 추론 단계 공백

- **날짜**: 2026-09-24
- **유형**: design
- **상태**: 확정 — 관찰 2(추론 공백)는 0010에서 해소
- **관련 기록**: 0006, 0008
- **설계 문서**: [docs/design/use-cases.md](../design/use-cases.md)

## 배경 / 동기

사용자 질문: "이 라이브러리는 어떤 환경에서 어떻게 활용될 수 있는가?"
환경별 시나리오를 정리하는 과정에서 설계와 실험 계획에 영향을 주는 관찰 두 가지가 나왔다.

## 관찰 1 — α는 LoRA·QLoRA의 보완재이다

- 학습 메모리 = 가중치 + 그래디언트 + 옵티마이저 상태 + 활성값.
- LoRA·QLoRA·8비트 옵티마이저는 앞의 세 항목을 줄인다. 그 결과 **활성값이 남은 병목**이 된다(특히 장문, 큰 배치).
- α는 이 남은 병목을 겨냥한다. 기존 도구와 **경쟁하지 않고 결합**한다.
- 규모 예시 (Llama-3-8B, 32층, d=4096, bf16, 배치 1): 저장 체크포인트가 4K 토큰에서 약 1.0GB, 16K에서 4.0GB, 32K에서 8.0GB.
  α(4비트 힌트)로는 각각 약 0.3 / 1.2 / 2.4GB로 추정된다(약 3.4배). 전체 피크 절감률은 실측이 필요하다.

**설계·실험 영향**
- R1의 E004에서 **전체 파인튜닝만 하면 α의 효과가 가려진다.** GPT-2 small의 경우 가중치와 Adam 상태가 약 2GB이고, 체크포인트는 수백 MB에 그친다.
  → **LoRA 파인튜닝 구성**과 **문장 길이 스윕**(예: 256 → 512 → 1024)을 추가해, 활성값 비중이 커질 때 절감 효과가 어떻게 달라지는지 측정한다.
- 논문 서론의 포지셔닝: "파라미터 효율 기법 이후에 남는 활성값 병목"

## 관찰 2 — G1의 "활용(추론)" 단계가 비어 있다

- β는 개발 단계, α는 학습 단계를 담당한다. 추론 단계는 후순위인 γ가 일부만 다룬다.
- G1은 "개발·학습·활용 **전 단계**"를 요구하므로 목표 대비 공백이다.
- 조치: 당장 범위를 넓히지는 않는다. 추론용 기존 도구가 매우 성숙해서(0002, 0006) 중복 위험이 크기 때문이다.
  메모리 센서스(R2)에서 추론 시 메모리 중복성도 함께 계측해, 새 후보가 나오는지 본다.
