# 0106. 객관 평가 2: E022~E024 반영 — memopro의 완성도와 성능

- **날짜**: 2026-09-29
- **유형**: assessment (사용자 요청)
- **상태**: 확정. 수치는 각 기록의 측정값이다. 달성률(%)은 연구자가 아래 근거에 따라 매긴 판단이다
- **관련 기록**: 0095 (직전 평가, 가중 약 53%), 0098 (E022), 0102 (E023), 0105 (E024), 0097 (오픈소스 결정)

## 요청

> "memopro 라이브러리의 완성도와 성능 등을 평가해."

## 평가 방법

- 0095와 같은 다섯 영역, 같은 비중, 같은 판정 단계(입증됨 / 부분 입증 / 미입증 / 반증)를 쓴다. 0095 이후의 근거만 더해 바뀐 점을 표시한다.
- 비교 대상은 사용자가 같은 기법을 직접 쓰는 경우다(HF, bitsandbytes, accelerate, gradient checkpointing).
- 한계: 측정은 T4 한 종과 M1 8GB, 모델은 Qwen2.5 계열과 GPT-2다.

## 1. 추론 (비중 30%)

| 근거 | 결과 | 0095 이후 |
|---|---|---|
| T4, E022 | T4(bf16 하드웨어 없음)에서 fp16을 골라 2048토큰 첫 토큰이 HF fp16의 1.04~1.07배. 7차의 3.7~5.4배 느림(D2)이 해소됐고, PPL은 같다 | 새로 입증 |
| T4, E022 | 7B `quality="low"`는 int4로 15.8 tok/s(HF bnb4 14.0, PPL +7.7% 대 +7.6%) | 새로 입증(D3) |
| T4, E022·E023 | 7B 기본 품질은 int8로 5.2~5.5 tok/s(PPL +0.8%). int4보다 2.9배 느리다. 이제 보고에 int4 안내가 나온다(O1) | 약점, 안내로 보완 |
| T4, E022·E023 | 수정하지 않은 스크립트를 `memopro run`으로 돌리면 7B에 정책을 적용하고(int8), 들어가는 1.5B에는 개입하지 않는다 | 새로 입증(D4) |
| T4, E021 | 14B(장치의 약 1.9배) int4 9.0 tok/s, OOM 0회 | 그대로 |
| 미시험 | 장치의 2배를 넘는 모델(오프로드 필요), M1 8GB의 7B | 그대로 |

- **판정: 부분 입증.**
  - 장치의 약 2배까지는 자동으로, OOM 없이, 알맞은 정밀도와 속도로 돌린다는 것이 이제 결함 없이 확인됐다.
  - 기본 품질의 7B가 느린 쪽(int8)을 고르는 것은 설계상의 선택이다(품질 상한). 안내로 보완했다.
  - 2배 초과는 여전히 미입증이다.
- **달성률: 60% → 약 65%.**

## 2. 학습 (비중 30%)

| 근거 | 결과 | 0095 이후 |
|---|---|---|
| T4, E023 | 0.5B 배치 8: micro 2로 micro 1보다 1.09배 빠름(960 대 881 tok/s). plain·AMP·ckpt는 OOM(7차) | 개선 |
| T4, E023 | GPT-2 배치 16: 8+8로 고르게 분할. HF ckpt보다 1.15배 빠름, 손실 차이 1.7e-7. 30% 상한은 OOM 재시도 없이 한 번에 계획 | 개선(D5) |
| T4, E022~E024 | 7B QLoRA(동결 파라미터): 계획 실패(D1) → 0.88배(E022) → 1.00배지만 예산 초과(E023) → **0.97배, 예산 준수, GPU 2.2GiB 적게**(E024) | 새로 입증 |
| T4, E023 | 계획 크기 예측이 네 경우 모두 실제 선택과 일치 | 새로 입증 |
| 정확성 | 정확한 전체 배치와 손실 1e-6~1e-7, 파라미터 1e-8~1e-9 | 그대로 |
| 한계 | 가중치+기울기+옵티마이저가 메모리를 넘는 학습은 해결하지 않는다(제안만). 애초에 불가능한 학습도 모든 단계를 시도한 뒤 거절한다(D6) | 그대로 |

- **판정: 부분 입증.**
  - 활성값이 넘치는 학습과 QLoRA는 정확하게, OOM 재시도 없이, 표준 방식과 거의 같은 속도로 해결한다.
  - 파라미터가 넘치는 학습은 여전히 범위 밖이다.
- **달성률: 55% → 약 62%.**

## 3. 개발 편의 (비중 15%)

- 0095의 근거(doctor 정확도, `check` 학습 예측 −0.2~−1.2%, 되는 설정만 제안)에 더해 달라진 점
  - 품질 비용 문구가 백엔드별 실측이 됐다(D9).
  - int4 속도 안내가 생겼다(`load`, `memopro run --quality low`).
  - 학습 계획 보고에 예산, 보유 메모리, 여유 계수, 돌려준 캐시가 나온다.
- 추론 예측은 여전히 거칠다(−3.5~−19%, 0093).
- **판정: 입증됨. 달성률 70% → 약 72%.**

## 4. 연구 코어 (비중 15%)

- 변화 없음: α 반증, β 정확하나 가치 미입증(E010 미수집, T4에서 다시 불러오기의 2.1배 시간, D7), γ 부정적(실험 기능, 기본 끔), census 측정 연구 미실행, F 등급 MPS 한정 부분 입증.
- **달성률: 약 25% (그대로).**

  - 오픈소스 배포 결정(0097, MIT OR Apache-2.0).
  - 정밀 검토로 예산 규칙의 빈틈 7건을 측정 전에 막음(0100).
- **남은 것**

  - 배포 판·이름 선점 미결정, 미배포.

- **한 문장 평가**: 접근 계층(추론·학습 자동화)은 이제 T4에서 결함 없이, 표준 방식과 같은 수준의 속도로, 더 안전하게 작동한다. 그러나 목표의 "훨씬 큰"(장치의 2배 초과, 파라미터 초과 학습)과 고유 연구 코어의 가치는 아직 입증하지 못했다.
- **기존 도구 대비**: 새 능력은 여전히 없다. 가치는 자동 선택, OOM 방지, 정확성(배치를 바꾸지 않음), 보고에 있다. 이번 재측정들로 "자동으로 고른 설정이 사람이 고른 표준 설정만큼 빠르다"는 근거가 생겼다: fp16 TTFT 1.04~1.07배, int4 1.13배, QLoRA 0.97배.
- **점수가 오른 이유**는 새 기능이 아니라 결함 수정과 그 실측 확인이다. 점수를 더 올리려면 새로운 입증이 필요하다.

## 달성률을 가장 많이 올릴 다음 단계 (제안)

1. **"2배 초과" 시험**: T4에서 32B int4(약 18GB > 15GB, 오프로드 필요), M1 8GB에서 7B int4. 목표 문장의 "훨씬 큰"에 직접 답한다. 추론 영역을 가장 크게 움직인다.
2. **E010 수집**(사용자): β의 가치를 판단할 유일한 근거이자 첫 외부 사용자 데이터다.
3. **D6**: 정적으로 불가능한 학습을 `check`처럼 즉시 거절(28~40초 낭비 제거). 작은 작업이다.
4. **배포 준비**: 빠른 시작 절, 판 번호·이름 선점 결정. 오픈소스 결정(0097)에 따른 첫 공개.
