# 0010. 범용성 중심 재설계: 범용 접근 계층 + 연구 코어의 2계층 구조

- **날짜**: 2026-09-24
- **유형**: decision + design
- **상태**: 확정 (설계 v0.2) — 중복성·논리 검증 결과 수정(→ 0011, 설계 v0.2.1); 일부 대체됨(→ 0107: 재구현 금지는 접근 계층에만)
- **관련 기록**: 0004 (플래너 — 일부 개념 경량화해 재도입), 0005 (신규성 조건 — 적용 범위 명확화), 0008 (설계 v0.1 → 대체), 0009 (추론 공백 → 해소)
- **설계 문서**: [architecture.md v0.2](../design/architecture.md), [development-plan.md v0.2](../design/development-plan.md)

## 배경 / 동기

사용자 요구 (원문 요지):
> 누구나 쉽게 자신의 프로젝트·서비스·개발·학습·사용에 쓸 수 있는 **포괄적 범용성**을 갖출 것.
> 궁극적으로 **메모리가 부족한 사용자 누구나 적은 메모리 환경에서 높은 메모리를 요구하는 서비스를 누릴 수 있게** 할 것.

설계 v0.1(0008)은 기법 모듈 중심이었고, 0009에서 **추론(활용) 단계 공백**이 드러났다.
궁극적 목표의 핵심 장면("작은 기기에서 큰 모델 서비스를 쓴다")은 대부분 **추론**이다.

## 긴장 관계

| 요구 | 출처 | 충돌 |
|---|---|---|
| 기존 도구와 겹치지 않는 새로운 기법 | 0005 | 추론 메모리 절감은 기존 도구(양자화, 오프로드)가 가장 성숙한 영역 |
| 누구나, 모든 단계, 큰 모델 서비스 | 0010 (이번 요구) | 추론을 빼면 궁극적 목표를 달성할 수 없음 |

## 결정: 2계층 구조

| 계층 | 내용 | 신규성 조건 적용 |
|---|---|---|
| **범용 접근 계층** | 환경 감지 → 예산 산정 → 적합 사다리 → 적용(fail-open) → 보고. 기존 검증된 기법은 **재구현하지 않고 선택적 백엔드로 연결** | ❌ 적용하지 않음 (공학적 가치). 단, **재구현 금지** 원칙 |
| **연구 코어** | α rfc, β hibernate, γ elastic, census | ✅ 적용 (0005 조건 유지) |

- 0005의 신규성 조건은 **memopro가 직접 만드는 기법**에 적용된다고 명확히 한다. 기존 기법을 "연결"하는 것은 재구현이 아니다.
- 0004 플래너의 개념 일부(예산 기반 자동 선택)를 **경량 규칙 기반 "적합 사다리"**로 재도입한다.
  0004의 학술적 플래너(다축 최적화)와 달리, 목적은 **설명 가능성과 단순함**이며 학술 기여로 주장하지 않는다.

## 범용성 점검표

| 차원 | 커버리지 |
|---|---|
| 사용자 | 비개발자·운영자(L0), 일반 사용자(L1), 실무자(L2), 연구자(L3), 라이브러리·Rust 개발자(L4) |
| 단계 | 개발(β, census) · 학습(학습 사다리, α) · 추론·서비스(추론 사다리, γ) |
| 하드웨어 | 1급: CPU, Apple Silicon(MPS), NVIDIA(CUDA) / 감지만: ROCm, XPU |
| 실행 환경 | 노트북, Jupyter·Colab, 워크스테이션, 공유 서버, 컨테이너 서비스 |
| 모델 | LLM, 이미지 생성(Diffusers), 비전, 임의 `nn.Module`(일반 폴백) |
| 프레임워크 | PyTorch(1급), HF 생태계 통합, Rust 코어(candle·burn 등에서 부품 사용) |

## 한계

- 접근 계층은 학술적 신규성이 아니다. 실용 가치와 연구 코어의 전달 수단이다.
- "적은 메모리로 큰 모델"에는 물리적 한계가 있다. 오프로드가 필요한 구성은 매우 느리다. memopro는 이를 숨기지 않고 알린다(U6).
- 연동 백엔드가 많아질수록 유지보수 부담이 커진다. 첫 범위를 최소화한다.
