# 0036. v0.1 제품 전 구간 제작 결정: Gβ를 "제작 전 관문"에서 "배포 전 검증"으로

- **날짜**: 2026-09-25
- **유형**: decision
- **상태**: 확정
- **관련 기록**: 0032 (I1: Gβ 관문과 순서), 0015 P4, 0013 V4~V8 (β 설계), 0034·0035 (뼈대, doctor)

## 사용자 결정

> "그럼 우선은 제품의 처음부터 끝까지 제작을 진행해."

## 해석과 범위

- **"제품"은 v0.1**로 해석한다. 0032 I7에서 제품의 중심을 β + census로 정했고, v0.1이 그 첫 완결판이다. v0.2(범용 접근 계층)와 v0.3(γ)은 이 기록의 범위가 아니다.
- **"처음부터 끝까지"**는 사용자가 설치해서 쓸 수 있는 상태까지를 뜻한다. 대상은 doctor(완료), census, β hibernate, 디스크 저장 엔진, 노트북 통합, HF·Lightning 콜백, 예제와 문서이다.
- **배포(PyPI·crates.io)는 하지 않는다.** 공개 배포는 사용자의 명시적 확인이 필요하다.

## 0032 순서에서 달라지는 점

| 항목 | 0032 | 이번 결정 |
|---|---|---|
| β와 디스크 저장 엔진 제작 시점 | **Gβ 통과 후** (E010 수요 데이터로 판정) | **지금 제작한다** |
| Gβ의 역할 | 제작 여부를 정하는 관문 | **배포 전 검증**. E010 데이터로 β의 기본 동작·범위를 조정하거나, 수요가 약하면 문서에 적고 기본값을 보수적으로 둔다 |
| E009 (압축 방출), E011 (β 대 OS 스왑) | 엔진 뒤, β 전 | **배포 전 검증 실험으로 이동**. 그때까지 방출은 무압축(0025 C5), OS 대비 이득은 주장하지 않는다 |

이유: 사용자가 제작을 먼저 지시했다. 0031 I1의 우려(수요 미확인 상태로 구현)는 남지만, Gβ를 배포 전 검증으로 유지하면 **수요 확인 없이 공개하는 일은 막을 수 있다**.

## 제작 중 확정할 설계 (0013·0032 설계를 구현 가능하게 구체화)

| # | 결정 | 이유 |
|---|---|---|
| B1 | **텐서 메모리 해제는 객체를 유지한 채 저장공간만 교체**한다(`tensor.data`를 크기 0 텐서로 바꾸고, 복원 시 되돌림). 모듈·옵티마이저·텐서 객체의 **정체성이 유지**되므로, 옵티마이저가 들고 있는 파라미터 참조도 복원 후 그대로 유효하다. 동면 중에 접근하면 크기 0 텐서라 **형상 오류로 크게 실패**한다(조용히 틀리지 않음) | architecture §5.1의 "`set_`으로 크기 0 저장공간을 만들지 않는다(조용히 틀린 결과 위험)"를 **수정**한다. 그 위험은 "다른 곳에서 보이지 않게 계속 쓰는 경우"이다. 이번 방식에서는 ① 모듈은 forward 전에 자동 복원(hook)되고 ② 그 밖의 접근은 형상 오류로 드러나며 ③ 실제 회수량은 실측으로 보고한다. 이 위험을 받아들이는 대신 대리 객체 없이 핸들 방식(I5)을 쓸 수 있다 |
| B2 | 모듈은 **forward pre-hook으로 자동 복원**한다. 텐서는 노트북 매직에서만 이름을 대리 객체로 바꿔 자동 복원하고, 핸들 방식에서는 `h.wake()`로 복원한다 | 모델 호출이 가장 흔한 사용 경로이다. 대리 객체는 텐서에만 한정한다 |
| B3 | **`source` 방식은 텐서 단위로 판정**한다. safetensors 헤더로 이름·dtype·형상을 대응시키고, 동면 시 **원본을 읽어 현재 텐서와 비트 단위로 같은지 확인**한다. 복원 시에는 다이제스트로 다시 확인한다. 로드할 때 변환된 가중치(융합·전치 등)는 일치하지 않으므로 그 텐서만 다음 방식으로 넘어간다(`auto`). 원본 파일이 바뀌었으면(크기·수정 시각) 복원을 거부하고 알린다 | 0032 H1. 모델 전체가 아니라 텐서별 판정이라 부분 적용이 가능하다 |
| B4 | census 정밀 경량판의 "필요 비트"는 v0.1에서 **복원 오차 기준**(블록 최댓값 양자화의 상대 오차)으로 추정한다. **그래디언트 영향 기준은 v0.2 정밀 모드**로 미룬다. 결과에 기준을 명시한다 | 그래디언트 영향 측정은 역전파를 다시 돌려야 해 비용이 크다. 기준을 숨기지 않는다(U6) |
| B5 | SSD 하루 쓰기 한도 기본값: **min(20 GB, 디스크 용량의 2%)**, 파일로 날짜별 누적 | 0032 H3의 "용량 대비 작은 비율". 256GB 기준 약 5GB/일. 초기값이며 근거 있는 측정값이 아니다 |

## 제작 순서

1. census (빠른 모드 + 경량판, 권고, 정확성 검증)
2. Rust 엔진: 다이제스트, 원본 읽기, 방출 파일, 압축, buffer protocol 바인딩(RS2), 프로토타입 `codec_*` 제거
3. β hibernate (방법 5종, 핸들, 매직, 제안, 상태, 자동 모드)
4. HF·Lightning 콜백, 노트북 통합
5. 시연 스크립트와 실측(M1), 문서(README, CHANGELOG, 알려진 한계)

각 단계는 결과를 연구 기록으로 남긴다.
