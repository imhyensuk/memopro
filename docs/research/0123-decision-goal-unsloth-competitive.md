## 판단 근거 (질문 전에 보인 분석)

- **Unsloth(공개 자료 기준, 이전 조사 0004·0011·0051)**
  - NVIDIA GPU에서 LLM 파인튜닝(LoRA·QLoRA·전체·RL)을 직접 쓴 Triton 커널로 빠르게 한다(HF 대비 약 2배, VRAM 크게 절감).
  - 활성값 RAM 오프로드로 긴 문맥을 다룬다.
  - 한 줄 불러오기, 노트북, 내보내기 같은 사용성이 강하다.
  - 모델 코드를 패치하는 방식이라 지원 모델군이 정해져 있다.
  - 메모리보다 큰 모델을 무손실로 다루는 방향은 아니다.
  - Apple Silicon·CPU 지원 현황은 이번 결정 시점에 확인하지 않았다 → 선행 조사에서 확인한다.
- **memopro가 입증한 것**: 메모리 축의 새 능력(0121). 양자화 없이 필요 메모리의 1/4에서 3B 추론, OS 페이징의 5배, 출력 비트 동일, 베이스 고정 LoRA.
- **memopro가 약한 것**: 학습 속도. CPU 스트리밍이고, M1 bf16 역전파가 느리다(1.5B LoRA 한 단계 약 4~5분, 0115·0121). 자체 GPU 커널이 없다. GPU 환경은 Colab T4뿐이다.
- **정면 경쟁(A)을 고르지 않은 이유**
  - 커널을 다시 만드는 일이라 0010(재구현 금지)과 RS6(커널 보류)을 바꿔야 한다.
  - 후발이고, 장비도 부족하다.

## 결정

| # | 내용 |
|---|---|
| **G4 (새 주 목표)** | **메모리가 부족한 기기(8~16GB Mac·노트북·작은 GPU)의 LLM 파인튜닝·추론에서 Unsloth와 경쟁할 수 있는 라이브러리**. 그 기기에서 Unsloth(또는 표준 HF)가 돌리지 못하는 크기의 모델을 돌리고, 돌릴 수 있는 크기에서는 쓸 만한 속도를 낸다 |
| **B (중심)** | 다른 경기장. 메모리보다 큰 모델의 파인튜닝·추론을 무손실 기본으로. 이를 위해 학습 속도(MPS·GPU에서 가중치 흘려 쓰기, bf16 역전파 경로)를 끌어올린다 |
| **C (보조)** | CUDA에서는 Unsloth 같은 기존 백엔드를 **선택적 백엔드로 감싸고**(0010의 접근 계층 원칙), 그 위에 memopro 런타임을 얹어 단독보다 더 큰 모델·문맥을 같은 GPU에서. 0012 S2("외부 도구로 보내지 않음")와의 관계: 사용자를 다른 도구로 안내하는 것이 아니라, 설치되어 있으면 memopro가 안에서 쓰는 것이다. 없어도 memopro만으로 동작해야 한다 |
| **순서** | 런타임 3단계(Linux 투명 모드, C ABI, `fallback="stream"`)를 시험·기록·커밋하고 PR #37 병합까지 마친 뒤 G4로 전환한다. E027(G-R3 관문 실행)은 미룰 수 있다 |
| **유지** | G2′·G3·G1과 지금까지의 원칙(무손실 기본, 상한 보장, 쓰기 없음 0110, 사전 등록, 연구 기록) |
