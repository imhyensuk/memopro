# 0205. 사용자 결정: 작업이 붙잡은 버퍼를 런타임에 맡기는 일반 API — `Runtime.adopt`

- **날짜**: 2026-10-06
- **유형**: decision (사용자 지시) + design + implementation
- **상태**: 확정. E045로 검증
- **관련 기록**: 0204 (E044: KV 캐시 무손실 약 0.67), 0112·0115 (런타임 C-R), 0036 (β 동면: `tensor.data` 바꿔 끼우기), 0185·0198 (데이터 종류·접근 형태별 압축 이득)

## 경위

- 사용자는 쉬는 대화의 KV만 압축하는 선택지 B가 유리하지 않으냐고 물었다. 이어서 memopro는 언어 모델에 한정되지 않는다고 짚었다.
- 답(대화): 압축의 이득은 두 가지로 정해진다.
  1. 데이터가 잘 줄어드는가: 정수·희소·영상 2~10배, bf16·실수 약 1/3.
  2. 쉬는 시간이 되살리는 비용보다 긴가: 매 단계 전부 읽거나(KV, 상주 가중치) 무작위로 읽으면(정렬) 손해다.
- 런타임 C-R은 이미 버퍼마다 이 판단을 실측 비용으로 한다. 그런데 KV 캐시·데이터프레임 열·중간 결과처럼 **작업이 만들어 붙잡고 있는 버퍼는 런타임 밖**에 있다. 그래서 KV 전용 기능 대신 일반 경로를 만든다.
- 사용자 지시: "일반 API 설계 기록하고 진행해" (2026-10-06).

## 선행 조사 (새로움 규칙)

- 같은 성격의 기존 기법이 있다.
  - 관리되는 메모리에 객체를 넘기고 쓸 때 고정하는 방식: AIFM의 원격 포인터(0108), Dask의 관리 메모리와 방출(spill), PyTorch의 `saved_tensors_hooks`로 활성값 넘기기.
  - 압축 상주: zswap, CLA(0108).
- **새로움을 주장하지 않는다.** memopro 쪽 차이는 0108의 조합(버퍼마다 비용 기반 선택, 디스크 쓰기 없음, 상한 보장) 안에 있다.

## API

```python
rt = memopro.rt.Runtime(budget="2GB")
h = rt.adopt(obj)        # obj: torch 텐서, nn.Module, 옵티마이저, 또는 그것들과 NumPy 배열이 든
                         # dict / list / tuple / 일반 객체(데이터클래스, HF DynamicCache 등)
with h:                  # 블록 안: 모든 바이트가 메모리에 있다(압축돼 있었으면 풀린다)
    ...                  # obj를 평소처럼 쓴다. 바꾸거나 새 텐서를 붙여도 된다
# 블록 밖: 쉰다. 런타임이 자리가 필요할 때 무손실로 압축한다(디스크에 쓰지 않음)
h.evict()                # 지금 압축(선택)
h.release()              # 맡기기를 끝낸다: 데이터를 평소 메모리로 돌려주고 버퍼를 놓는다
```

## 동작

- **찾기**: 객체를 따라가며(깊이 제한, 같은 객체는 한 번) 문턱(기본 1MiB) 이상의 잎을 찾는다.
  - torch 텐서: 모듈은 매개변수·버퍼·기울기, 옵티마이저는 상태(β의 `collect`).
  - NumPy 배열: 고칠 수 있는 부모(dict 값, list 항목, 객체 속성)에 있을 때.
  - 다른 텐서와 저장공간을 나누는 텐서(뷰, autograd가 저장한 것)는 맡기지 않는다(β 0041 규칙).
- **맡기기**: 잎마다 런타임 버퍼를 할당해 바이트를 복사한 뒤 잠재운다.
  - torch: `tensor.data`를 빈 텐서로 바꾼다. 텐서 객체는 그대로라 모듈·옵티마이저·캐시가 쥔 참조가 유지된다.
  - NumPy: 부모의 그 자리에 `Asleep` 표지를 둔다. 쓰려 하면 분명한 오류가 난다.
- **들어갈 때**(`with h`): 버퍼를 고정하고 잎을 되살린다.
  - CPU torch·NumPy: 런타임 메모리를 복사 없이 그대로 쓴다. 블록 안의 제자리 수정이 버퍼에 바로 쓰인다.
  - MPS·CUDA torch: 장치로 복사해 넣는다. 나올 때 바뀌었으면(`_version`) 다시 복사해 낸다.
- **나올 때**: 객체를 다시 훑는다.
  - 맡긴 잎은 잠재운다(고정을 푼다).
  - 블록 안에서 새로 생긴 잎(예: KV 캐시가 `torch.cat`으로 만든 새 텐서)은 새로 맡긴다.
  - 객체에서 사라진 잎의 버퍼는 놓는다.
- **예산**: 맡긴 버퍼는 런타임 예산에 들어간다. 쉬는 버퍼는 런타임의 점수(되살리는 비용 ÷ 줄어드는 양 ÷ 다음 사용까지의 거리)에 따라 압축된다. 디스크에는 쓰지 않는다(0110).
- **무손실**: 바이트를 그대로 복사하고 압축한다. 되살린 값은 비트 동일하다.

## 범위 밖 (이번에는)

- pandas DataFrame 내부 블록: 내부 구조라 따로 다룬다. 지금은 열을 NumPy 배열로 dict에 담아 맡긴다.
- 블록 밖 접근의 자동 깨우기(β의 가드 같은 것): 명시적 `with`만.
- 장치 메모리의 무복사(MPS 감싸기): 지금은 들어갈 때·나올 때 복사.

## 논문 매핑

- **System**: 런타임 C-R이 가중치·파일 말고도 작업이 붙잡은 임의의 버퍼를 같은 비용 기반 정책으로 관리한다. KV 캐시와 일반 데이터를 같은 API로.
