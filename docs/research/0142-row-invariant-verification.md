# 0142. 행 불변 검증 제작: 프롬프트 뒤의 행은 한 행씩, 층의 가중치는 한 번만 고정

- **날짜**: 2026-10-04
- **유형**: implementation
- **상태**: 확정. E033b(0143)로 검증
- **관련 기록**: 0141 (E033 결과와 선택지), 0139 (E4 제작)

## 사용자 결정

0141의 선택지 중 **A. 행 불변 검증 후 재측정**을 골랐다(2026-10-04).

## 문제 (0141)

- GPU의 bf16 행렬곱(과 어텐션)은 한 번에 받는 행 수에 따라 같은 행의 결과가 마지막 한 칸 달라질 수 있다.
- 보조 생성의 검증은 제안된 여러 토큰을 한 번에 계산한다. 그래서 일반 생성(한 행씩)과 동점 처리가 갈릴 수 있었다.
- 예: "describe"/"provide" 35.25 대 35.0 → 35.25 대 35.25.

## 제작 (`python/memopro/rt/torch.py`)

- `_row_invariant(model, prompt)`(내부 문맥 관리자)
  - Llama 계열 구조(`model.<base>.layers`, `.norm`, 출력 머리)를 찾는다. 없으면 `ModeUnavailable`.
  - **디코더 층**: 캐시가 있고 여러 행이 들어오면 행을 둘로 나눈다.
    - 위치 < `prompt`인 행(프롬프트)은 한 덩어리로 계산한다. 마스크·위치·회전 임베딩은 그 행들만큼 자른다.
    - 나머지는 **한 행씩** 계산한다(마스크 없음 = 캐시의 모든 키를 봄). 일반 생성의 한 행 단계와 같은 모양이다.
    - KV 캐시도 한 행씩 늘어나 일반 생성과 같아진다.
  - 층의 가중치는 행 반복 전에 한 번 고정해 둔다(`hold`: 고정된 텐서를 들고 있음). 그래서 흘려 쓰기의 읽기는 늘지 않는다. 행마다 도는 잎 모듈의 훅은 이미 고정된 메모리를 다시 쓴다.
    - 첫 구현은 바깥에서 잎 모듈의 `_before`를 불렀다. 안쪽 훅이 매개변수를 바꿔치기하면 바깥 텐서가 사라지는 결함이 있어, 텐서를 직접 들도록 고쳤다(시험 전에 발견).
  - **마지막 정규화**: 같은 규칙(프롬프트 덩어리 + 한 행씩). 이번 패스 전의 캐시 길이는 첫 층이 기록한다.
  - **출력 머리**: 여러 행이면 언제나 한 행씩. 일반 생성은 `logits_to_keep=1`이라 항상 한 행이다.
- `generate(model, input_ids, *, draft=None, **kwargs)`(공개)
  - 탐욕만 받는다(`do_sample=True`면 `InvalidArgument`). 한 시퀀스만 받는다([1, 길이], 패딩 없음).
  - 위 문맥 안에서 HF `generate(assistant_model=draft)`를 부른다.
  - **반환값은 `model.generate(input_ids, do_sample=False, **kwargs)`와 같다**는 것이 계약이다.
- 회전 임베딩은 위치를 한 번에 계산해도 비트가 같다. 내적 길이가 1인 곱(외적)이라 합산 순서가 없다. 그래서 감싸지 않았다.

## 시험

- `test_rows_after_the_prompt_are_computed_as_in_plain_generation[cpu|mps]`
  - 작은 Qwen2(bf16)에서 확인한다. 프롬프트 + 새 6행을 한 번에 넣은 결과와, 프롬프트 뒤에 6행을 한 단계로 넣은 결과가 있다.
  - 두 결과의 각 행 로짓이, 한 행씩 넣은 로짓과 **비트 단위로 같다**(`torch.equal`). 프롬프트 마지막 행도 프롬프트 단독 패스와 같다.
- `test_int4_draft_keeps_greedy_generation_of_the_streamed_model`
  - `generate`(초안 없음, 자기 초안, 다른 초안)가 일반 `model.generate`와 같다. 잘못된 인자는 거부한다.
- **개발 확인(결과 아님)**: 3B 1GiB + 1.5B int4 초안, E033의 프롬프트 1·2를 다시 돌렸다.
  - 둘 다 E033의 P와 64토큰이 같았다(프롬프트 1은 E033에서 어긋났던 것).
  - 속도는 0.93·0.32초/토큰이었다(E033 S15: 0.95·0.30).

## 논문 매핑

- **System (G4 E4)**: 추측 디코딩의 검증을 "일반 생성과 같은 행 모양"으로 계산해 비트 동일한 출력을 보장한다. 흘려 쓰기에서는 가중치를 층마다 한 번 고정하므로 읽기 비용이 늘지 않는다.
- **Lessons**: 무손실 추측 디코딩의 "대상 모델의 선택"과 "일반 생성과 같은 출력"은 GPU 수치에서 다르다. 그 차이를 없애는 방법.
