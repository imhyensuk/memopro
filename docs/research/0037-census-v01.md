# 0037. N1b census 구현 (빠른 모드 + 정밀 경량판, 권고, HF·Lightning 콜백)

- **날짜**: 2026-09-25
- **유형**: design+milestone
- **상태**: 확정
- **관련 기록**: 0036 (B4), 0032 (Q1·R2·P6·P7·I8), 0019 (E005 측정 정의), 0033 (K1·K3)

## 내용

`memopro.census.record(model, optimizer, mode="fast"|"light")`는 `with` 블록 동안 메모리를 기록한다. 결과는 `summary()`(사람용), `to_json()`, `advice()`로 제공한다.

| 항목 | 구현 |
|---|---|
| 범주 | 파라미터+버퍼, 그래디언트, 옵티마이저 상태, 저장 활성값. **저장공간 단위로 한 번만** 센다(뷰·공유 가중치 중복 없음). 저장 활성값은 `saved_tensors_hooks`로 잡고, 파라미터 등과 겹치는 저장공간(역전파용으로 저장된 가중치)은 제외한다 |
| 표본 | 범주당 최대 32개 텐서 × 65,536개 원소. 텐서 전체를 복사하지 않는다(연속 텐서는 간격 뷰, 비연속 텐서는 `unravel_index`로 색인). `torch.take`는 MPS에서 지원하지 않아 쓰지 않는다. 저장 활성값은 저장소 표집(reservoir sampling, 시드 고정) |
| 지표 | 저장 비트, 바이트 평면 0차 엔트로피(E005 정의), 무손실 한계 비율(보조 지표, R2), **0이 아닌 값 기준** max/median(거대 값, 기준 100배), 정확히 0인 값의 비율 |
| 정밀 경량판 (`light`) | 블록 64 최댓값 기준 대칭 양자화 8·4·2비트의 상대 L2 오차(중앙값·최악값). **필요 비트 = 최악 표본이 상대 오차 1e-2 이하인 가장 작은 비트 수**(K3). 그래디언트 영향 기준이 아니라는 점을 결과의 `criteria`에 적는다(0036 B4) |
| 할당자 대조 (V9) | CUDA `memory_allocated`·`max_memory_allocated`, MPS `current_allocated_memory`·`driver_allocated_memory`, CPU는 프로세스 RSS(Rust `hwinfo::process_rss` 추가). 종료 시점에 살아 있는 범주(파라미터·그래디언트·옵티마이저)가 장치 할당량의 몇 %인지를 **coverage**로 보고한다 |
| 권고 (P6) | 옵티마이저 상태가 25% 이상이면 8비트 옵티마이저, 저장 활성값이 25% 이상이면 활성값 체크포인팅, float32 파라미터·그래디언트는 bf16 혼합 정밀도, 무손실 1.3배 이상이면 `hibernate mode='compress'`, 거대 값이 있으면 K1 경고, 0이 절반 넘는 범주, 분류되지 않은 메모리가 20% 이상이면 알림. 각 권고에 **정확/수치 변경**을 표시하고, memopro 기능이나 일반 기법 이름만 쓴다(외부 도구 안내 없음, S2) |
| 콜백 (I8) | HF `Trainer`: `on_step_begin`부터 `on_optimizer_step`까지(`optimizer.step()` 뒤, `zero_grad` 전). Lightning: `on_train_batch_start`부터 `on_train_batch_end`까지. 기본은 2번째 스텝(옵티마이저 상태가 생긴 뒤). census가 실패해도 학습은 멈추지 않는다(U3). accelerate가 감싼 옵티마이저도 풀어서 쓴다 |

## 검증

| 검증 | 결과 |
|---|---|
| 정답을 아는 입력 (P7) | 균등 256값 uint8 엔트로피 8.0, 상수 float16 0.0, 두 값 1.0. 블록마다 127이 있는 정수값은 8비트 오차 0. 최악값 규칙 확인. 0을 제외한 max/median 계산 |
| 실제 바이트 대조 | 파라미터·그래디언트·옵티마이저 상태 바이트가 저장공간 합과 정확히 일치. 공유 가중치(임베딩과 출력층) 한 번만 계산. `no_grad`에서는 저장 활성값 0 |
| MPS | GPT-2 축소판(2층, 폭 128) 학습 1스텝: 종료 시 MPS 할당량의 **100%**를 분류(분류 안 된 양 2 KiB) |
| HF Trainer, Lightning 2.6.6 | 실제 `Trainer.train()`·`trainer.fit()`에서 한 스텝을 기록. 옵티마이저 상태·그래디언트가 0보다 큼 |
| 전체 | `pytest` 83 통과, ruff 통과 |

GPT-2 축소판 예시(무작위 초기화, 학습 3스텝)는 다음과 같았다.
- 저장 활성값 55%
- 무손실 비율: 파라미터 1.36배, 그래디언트 1.44배, 옵티마이저 상태 1.31배, 활성값 1.21배
- 필요 비트: 파라미터·그래디언트·활성값 8비트, 옵티마이저 상태는 8비트 초과
- 그래디언트·옵티마이저 상태에 거대 값(최대/중앙 613배, 2,589배)

이 값은 무작위 초기화된 작은 모델의 기능 확인용이며 **연구 결과가 아니다**(연구 측정은 E012).

## 한계

- 필요 비트는 복원 오차 기준이다. 학습에 미치는 영향 기준은 v0.2 정밀 모드에서 다룬다.
- CPU 텐서는 할당자 통계가 없어 coverage를 계산하지 못한다. RSS에는 파이썬·라이브러리 메모리가 섞여 있다.
- 저장 활성값의 바이트는 기록 중에 저장된 것의 합이다. 동시에 존재한 최대치(피크)와는 다를 수 있다.
- 권고의 임계값(25%, 1.3배, 20%, 100배)은 휴리스틱이며 근거 있는 측정값이 아니다.
- 노트북 셀 단위 메모리 증감은 β의 노트북 추적기와 함께 구현한다(0039).
