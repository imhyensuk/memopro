# 0122. 3단계 범위와 E027 사전 등록: 관문 G-R3 — 코드를 고치지 않은 NumPy 프로그램을 필요 메모리의 1/2에서 (Linux 투명 모드)

- **날짜**: 2026-09-30
- **유형**: design (3단계 범위) + experiment (사전 등록)
- **상태**: 확정. 3단계 제작(0124) 뒤 실행한다
- **관련 기록**: 0109 (설계: 3단계 = Linux 투명 모드, 접근 계층 연결, C ABI), 0110 (쓰기 없음, 다운로드 없음), 0108 (UMap·ExtMEM·TMO/zswap), 0121 (G-R2 통과)

## 3단계 범위 (0110의 제약에 맞춘 조정)

| 기능 | 내용 |
|---|---|
| **T 투명 모드 (Linux)** | `memopro::rt::Pager`. userfaultfd에 쓰기 보호(WP)를 더해 익명 메모리를 청크 단위로 무손실 압축·복원한다. 코드는 평범한 메모리로 읽고 쓴다. NumPy 연결은 NumPy의 메모리 처리기(`PyDataMem_SetHandler`, NumPy 1.22+)로 한다. `memopro.rt.transparent(budget)` 블록 안에서 만든 큰 배열(기본 16MiB 이상)이 페이저에 들어간다. `memopro run --transparent BUDGET script.py`는 **스크립트를 고치지 않고** 이것을 적용한다 |
| **C C ABI** | `crates/memopro-c`(`libmemopro_c`, `include/memopro.h`, `mp_*`). 명시적 런타임(버퍼·고정·재계산·통계·예측)을 C/C++에서 쓴다 |
| **A 접근 계층 연결** | `memopro.load`가 무손실로 들어가는 구성이 없을 때 제안에 스트리밍(`memopro.rt.torch`)을 더한다. 명시적 선택(`fallback="stream"`)으로 쓴다. 기본 경로를 자동으로 바꾸지는 않는다: CPU 스트리밍은 장치 실행보다 크게 느려, 조용히 고르면 사용자를 놀라게 한다(0032 H6: 조용한 대체 금지) |

- **설계와 다른 점**
  - 투명 모드는 원본 재읽기·방출이 아니라 **압축만** 한다. 익명 메모리에는 원본이 없고, 방출은 SSD 쓰기라 0110에서 뺐다.
  - 그래서 **압축되지 않는 데이터는 예산을 넘는다**(`overruns`로 센다). 페이지 폴트에는 거절할 길이 없다.
  - macOS에는 userfaultfd가 없다. 투명 모드는 이유와 대안(명시적 런타임)을 담은 `ModeUnavailable`로 거절한다(R7 플랫폼 정직성).
- **선행 연구와의 관계(0108)**
  - userfaultfd 페이징 자체는 UMap·ExtMEM이 보였다.
  - 커널 압축 스왑은 zswap·TMO가 한다.
  - 우리 조사에서 찾지 못한 조합: 프로세스별 **예산 상한** + 무손실 압축 + 재사용 거리 선택 + NumPy 처리기로 **코드 변경 없이** 연결.
  - 새롭다고 주장하지 않는다.

## E027 사전 등록 (G-R3, CI의 Linux에서)

### 환경

- GitHub Actions `ubuntu-24.04` 실행기(x86_64, Linux 6.x): `.github/workflows/e027.yml`, 수동 실행.
- 이 Mac에는 Linux와 userfaultfd가 없다. 실행기에서의 다운로드(NumPy, 파이썬 도구)는 사용자 기기 밖이라 0110의 제약에 걸리지 않는다. 사용자 SSD에는 아무것도 쓰지 않는다.
- 메모리 한도는 `sudo systemd-run --scope -p MemoryMax=L -p MemorySwapMax=0`(cgroup v2)으로 건다.
- 결과는 작업의 산출물(artifact)로 받아 `docs/research/data/e027/`에 둔다.

### 작업 W (고치지 않는 비AI 프로그램)

- `experiments/e027_transparent/workload.py`: 영상 더미 처리.
- 합성 16비트 흑백 영상 2,048장(512×512, 1GiB, 시드 고정, 매끄러운 무늬 + 4비트 잡음)을 한 장씩 만들어 `(N, H, W)` 배열에 채운다.
- 보통의 NumPy 식으로 네 번 훑는다.
  1. 영상별 평균
  2. 임계값을 넘는 화소 수(전체 크기의 bool 임시 배열이 생김)
  3. 배경(화소별 최솟값) 빼기(제자리 쓰기)
  4. 최종 합·최댓값과 배열 전체의 SHA-256
- 결과는 JSON 한 줄이다.

### 경우

| # | 경우 | 목적 |
|---|---|---|
| 1 | 그냥 실행, 한도 없음 | 결과 R, 시간 T0, 최대 메모리 P(cgroup `memory.peak`) |
| 2 | 그냥 실행, 한도 L = P/2, 스왑 없음 | 1/2에서 돌지 못함을 보인다 |
| 3 | `memopro run --transparent B`, 같은 한도 L, 스왑 없음, B = L − 192MiB(파이썬·NumPy 기본 몫) | 1/2에서 돈다 |
| 4 (보고) | 그냥 실행, 한도 L, 스왑 허용(실행기 디스크) | OS 스왑과 비교 |
| 5 (보고) | 경우 4 + zswap 켬(가능할 때) | 커널 압축 스왑과 비교 |

### 기준 (실행 전 고정)

| # | 기준 |
|---|---|
| **T1** 정확성 | 경우 3의 결과가 경우 1과 비트 동일하다(모든 통계와 SHA-256) |
| **T2** 필요 | 경우 2는 끝나지 못한다(OOM으로 죽거나 `MemoryError`) |
| **T3** 1/2에서 실행 | 경우 3이 한도 L 안에서 끝난다(죽지 않음). 페이저 `overruns` = 0, 페이저 최대 계상 ≤ 페이저 한도 |
| **C1** C ABI | CI(Linux)에서 `smoke.c`를 컴파일해 돌리면 `ok`로 끝난다 |
| **U1** 시험 | CI Linux에서 페이저 Rust 시험 4개와 파이썬 투명 모드 시험 2개가 건너뛰지 않고 통과한다 |

- **보고만**: 경우 3의 시간 T/T0, 폴트·압축률·복원 수, 경우 4·5의 시간(또는 죽음).
- **관문 G-R3** = T1, T2, T3, C1, U1 모두 통과. 실패하면 멈추고 보고한다(0110 N6).
- **UMap과 비교하지 않는다.** UMap은 프로그램이 자기 API(`umap()`)를 부르도록 고쳐야 하고, 소스를 받아 빌드해야 한다. 이 관문은 코드 변경 없음이 목표다. 커널 쪽 투명 기준선으로 OS 스왑과 zswap을 대신 잰다.

## 논문 매핑

- **Evaluation (3단계)**: 코드를 고치지 않은 NumPy 프로그램이 필요 메모리의 절반에서 비트 동일하게 도는지, 그 값(느려짐)과 OS 스왑·zswap과의 비교.
- **Design**: 쓰기 보호 기반의 안전한 내보내기(쓰는 스레드는 기다림), 폴트를 시계로 쓰는 재사용 거리 선택.
- **Threats**: 압축되지 않는 데이터에서는 상한을 지킬 수 없다(투명 모드의 원리적 한계). CI 실행기는 사용자 기기와 다르다.
