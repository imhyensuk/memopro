## 2. 연구 결과 요약

| 실험 | 질문 | 결과 | 설계에 준 영향 |
|---|---|---|---|
| E001~E003 (α) | 잔차 블록을 고정점으로 역산해 활성값 저장을 줄일 수 있는가 | **기각.** GPT-2 12개 블록 모두 비수축(σ 17~139). 4비트 힌트 k=3 교정 오차 10.2(교정 없음 0.218). 그래디언트 코사인 0.786(교정 없음 0.997) | α 트랙 종료. 규칙 K1~K4(이상치·LayerNorm 보호, 최악값 보고, 독립 복원) |
| E005 | 학습 중 텐서는 얼마나 압축되는가 | fp32 무손실 약 1.16배(≈14%). OS 방식(16KB 페이지 LZ4) 1.00배. bf16 경로 2.75~3.8배. 저장 활성값 1.6배 | β 기본 = 방출·호스트 이동. 손실 모드는 명시 선택만 |
| E006 | 노트북 유휴 메모리를 계측할 수 있는가 | 계측 도구 검증 통과(추적 120,004,004 B, 유휴 104,004,004 B 정확 일치) | 실제 수요 데이터 수집 도구 확보(실데이터는 미수집) |
| E007 (Muon) | Muon 옵티마이저가 학습 후보가 될 수 있는가 | 상태 메모리 −34%. 처음부터 학습은 3.7% 우위, Adam 사전학습 모델 전체 파인튜닝은 1.7% 열세. M1 MPS에서 2.98배 느림 | 후보에 넣지 않음 |
| E008 (사전 등록) | Rust 병렬 코덱이 Python보다 나은가, 압축 방출이 빠른가 | 단순 Rust는 Python 스레드의 0.40~0.90배. 메모리 기준 초과. 압축 방출이 무압축보다 느림 | β 방출 기본 = **무압축** |
| E008b (탐색) | 설계를 바꾼 Rust는 어떤가 | 3,852 MiB/s(Python 스레드의 1.49배). 파이프라인 방출 0.417s 대 무압축 0.508s. 메모리 증가 367MiB(목표 약 160MB 미달) | Rust 규칙 RS1~RS5 채택(0027). E009 확인 실험 필요 |

**연구 전체의 교훈**
1. 이론적으로 그럴듯한 기법(α)도 실제 사전학습 모델에서는 전제(수축성)가 성립하지 않았다. 측정 우선(P1)이 구현 비용을 막았다.
2. 학습 텐서의 무손실 중복은 작다(≈14%). 큰 중복은 **정밀도 쪽**에 있다. census의 연구 가치가 여기에 있다.
3. OS의 페이지 단위 범용 압축은 부동소수 텐서에 사실상 무효이다(1.00배).
4. Rust의 이점은 언어 자체가 아니라, 복사 제거·상태 재사용·파이프라인·구조적 메모리 상한을 **안전하게 구현할 수 있다는 점**이다.

## 3. 최종 라이브러리 설계 (v1.0 목표 형태, 설계 v0.3.5 기준)

**목표**: 메모리가 부족한 PyTorch 개발자가 자기 프로젝트·서비스·개발·학습에서 더 큰 메모리가 필요한 모델을 쓸 수 있게 한다. 외부 도구로 안내하지 않는다(0012 S2 기각).

### 3.1 구조

| 층 | 내용 |
|---|---|
| ① 진입점 | CLI(`memopro doctor` · `check` · `run`), Python(`load` · `optimize` · `train_session` · `report`), 노트북(`%load_ext memopro`, `%hibernate`), 통합(HF Transformers·PEFT·TRL·Diffusers·Lightning), 설정 파일·환경변수 |
| ② 오케스트레이터 | 환경 감지 → 풀별 예산 벡터 {device, host, disk} → 후보 구성 선택 → 적용(fail-open) → 감시(γ) → 실측 보고 |
| ③ 기법 레지스트리 | **연구 코어**(memopro 고유): β 동면, census, γ 탄력 런타임 / **기존 기법 연동**(재구현 금지): bitsandbytes·torchao·HQQ 양자화, safetensors 지연 로딩, accelerate 오프로드, torch 체크포인팅, 8비트 옵티마이저, KV 캐시 양자화 |
| ④ Rust 코어 | `hwinfo`(cgroup 포함) · `codec` · `spill`(방출 엔진) · `ledger` · `policy` · `census` 커널 · `pressure`(v0.3). 규칙 RS1~RS5 |

### 3.2 핵심 원칙
- 설정 없이 동작(U1). 초보 → 숙련 → 전문가로 점진 공개(U2, L0~L4).
- memopro의 오류로는 멈추지 않음(fail-open), OOM은 사전 예방(U3).
- 충실도 3분류(U5): **정확** → 자동 / **수치 변경** → 사용자가 고른 품질 범위 안에서만 / **의미 변경**(LoRA 전환 등) → 제안만.
- 물리 메모리가 아니라 **실제 가용 메모리**를 기준으로 함(U7): cgroup, MPS 권장 한도(8GB M1에서 5.33GB).
- 절감량은 논리 바이트가 아니라 **실측**으로 보고.

### 3.3 버전별 기능

| 버전 | 기능 | 사용자 가치 |
|---|---|---|
| v0.1 | `doctor`(풀별 예산) · census 빠른 모드(어디에·얼마나 중복) · β 명시 동면(CPU = 무압축 SSD 방출, CUDA = 호스트 이동, bf16은 명시 선택) | 개발 중 메모리 회수와 낭비 진단 |
| v0.2 | `optimize` · `train_session` · `load` · `check`, census 정밀 모드, 생태계 통합 | 큰 모델을 내 예산에 맞춰 실행·학습 |
| v0.3 | γ(실행 중 압박 대응) · `pressure` · `memopro run app.py`(코드 수정 없음) | OOM 대신 단계적 열화 |
| v1.0 | API 동결, 문서 사이트(영어·한국어), 어댑터 확충 | 안정판 |
