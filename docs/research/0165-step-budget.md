# 0165. 사용자 결정 A: `budget`이 학습 단계 전체를 덮는다 — 런타임 `hold_back`, `finetune`의 활성값 몫

- **날짜**: 2026-10-05
- **유형**: decision (사용자 선택) + implementation
- **상태**: 확정. E037b(0166)로 검증
- **관련 기록**: 0164 (E037: 활성값이 예산 + 512MiB를 넘음, 선택지), 0162 (워터마크), 0148 (목표: 보장된 메모리 상한)

## 결정

0164의 선택지 중 **A. `budget`이 단계 전체를 덮게**(2026-10-05).

## 제작

1. **Rust `Runtime::hold_back(bytes)`**(`crates/memopro/src/rt/mod.rs`)
   - 예산 중 `bytes`를 런타임 밖의 메모리(활성값 등)에 남긴다. 한도 = 예산 − 압축 여유 − `bytes`다(원자적 값, 미리 읽기 스레드도 같은 한도를 본다).
   - 고정되지 않은 버퍼를 내보내 새 한도에 맞춘다. 고정된 것이 넘거나, 런타임 자신의 여유보다 적게 남으면 아무것도 바꾸지 않고 `Error::Budget`을 낸다.
   - Python `Runtime.hold_back`, `_core` 바인딩, 형 스텁을 더했다.
   - 시험 `holding_back_shrinks_the_limit_and_gives_up_unpinned_buffers`: 한도가 줄고, 고정된 버퍼는 남고, 실패 때는 그대로이고, 내보낸 것은 파일에서 같은 내용으로 돌아온다.
2. **`_MetalPins`**: 한도를 매번 런타임에서 읽는다(줄어든 한도에서 울타리 문턱 = 한도/4).
3. **`memopro.finetune`(Apple GPU)**
   - 첫 단계 전에 설정으로 활성값을 추정해 1.5배를 떼어 둔다. 추정 = 2B × 토큰 × (층 × hidden + 4 × (4 × hidden + 3 × MLP)) + 손실 조각 4개.
   - 단계마다 GPU에 남은 가중치 밖 메모리를 잰다. 측정 = `torch.mps.driver_allocated_memory()` − 감싼 가중치 바이트. 이 값이 크면 그만큼으로 늘린다(줄이지는 않음).
   - 떼어 둔 뒤 남는 한도가 가장 큰 가중치보다 작으면 `BudgetExceeded`를 낸다("예산을 올리거나 `seq_len`을 줄이라"). 상한을 보장할 수 없는 설정은 시작하지 않는다.
   - `FinetuneResult.held_back`에 떼어 둔 바이트를 남긴다. CPU에서는 지금처럼 가중치만 묶는다.
   - 시험 `test_finetune_budget_covers_the_step_on_mps`: 떼어 둔 만큼 한도가 줄고, 손실은 유한하고, 너무 작은 예산은 거절한다.
     - 작은 모델에서는 측정값이 MPS 할당기의 최소 힙 단위(8·32MiB) 때문에 51MiB로 컸다. 그 힙도 실제 메모리이므로 그대로 쓴다.

## 개발 확인 (결과 아님)

- 3B·1GiB·512토큰·워터마크 0.01: 397MiB를 떼어 두었다.
- footprint 증가는 **+1,151MiB(예산 + 127MiB)**였다. E037은 +1,566MiB였다. 속도는 33.5토큰/초로 같다.
- 7B·1.5GiB·512토큰은 추정(약 612MiB)만으로도 가장 큰 가중치(1,039MiB)가 들어갈 자리가 없다. 그래서 거절된다.

## 논문 매핑

- **System (보장된 상한)**: 가중치 예산과 프로세스 상한을 하나로 묶는 방법이다. 런타임 한도를 실행 중에 줄이고, 측정으로 맞춘다.
