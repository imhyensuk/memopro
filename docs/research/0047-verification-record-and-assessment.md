- **날짜**: 2026-09-25
- **유형**: survey+milestone (검증 종합, 자기 비판 4차)
- **상태**: 확정
- **관련 기록**: 0034~0046 (구현·검증 각 단계), 0041 (자기 비판 3차), 0040 (배포 전 관문)

## 배경

> "지금까지의 테스트 과정까지 모두 기록해. 그리고 라이브러리의 완성도를 평가해."

단계별 기록(0034~0046)에 흩어진 테스트와 검증을 **층(layer)별로 한곳에 모은다.** 이어서 알파 배포 직전 시점의 완성도를 평가한다.

## 5. L7·L8: 결함을 찾은 방식

| 결함 | 증상 | 발견한 층 | 수정 |
|---|---|---|---|
| census `torch.take` | MPS에서 미구현 오류 | L2(개발 중 MPS 실행) | 간격 뷰 + `unravel_index` (0037) |
| census 비율 ∞ | 희소 텐서 max/median이 무한대 | L4(실제 모델 요약 출력) | 0 제외 (0037) |
| **D1** 공유 저장공간 | 깨운 뒤 뷰와의 공유가 **조용히 깨짐** | **L7 탐색적** | 공유 텐서 제외 (0041) |
| **D2** 역전파 도중 동면 | backward 형상 오류 | **L7 탐색적** | 그래디언트 hook 자동 복원 (0041) |
| **D3** meta 텐서 | torch 원래 예외 누출 | **L7 탐색적** | 건너뜀 + fail-open (0041) |
| MPS 오판정 | 가상머신에서 할당 실패 | **L5 CI** | 실제 할당으로 판정 (0042) |
| **F1** 회수량 음수 숨김 | `host`의 RAM 증가가 0으로 보고됨 | **L8 실제 GPU** | 부호 있는 보고 (0045) |
| **F2** CUDA 분류율 82.9% | cuBLAS 작업 공간 미분류 | **L8 실제 GPU** | 작업 공간 분류, 100% 달성 (0045·0046) |
| 테스트 자체의 결함 | 반복 변수가 뷰를 붙잡음, `start_ipython` 싱글턴 등 | L2 | 테스트 수정 (0039·0041) |

**교훈**
- **조용한 오류(D1)와 보고 오류(F1)는 자동 테스트가 아니라 탐색적 테스트와 실제 하드웨어에서 드러났다.** 자동 테스트는 설계자가 떠올린 경우만 확인한다.
- 이후 단계에서도 "예상 밖 사용"을 일부러 시도하는 탐색 단계와 실기 확인을 배포 관문에 유지한다.
- 한 번 발견한 결함은 모두 회귀 테스트로 고정했다(D1~D3, F1, F2, MPS 판정).

**종합**: v0.1 기준 **약 80%**(0041 수정 후 약 75%). v1.0 기준 **약 27%**.

**한 줄 평가**: 기술적으로는 알파를 내기에 충분하다. 세 플랫폼에서 원본과 비트 단위로 같게 복원되고, 결함은 발견 즉시 고쳐 회귀 테스트로 고정했다. 그러나 **"사람들이 이것을 필요로 하는가"는 여전히 검증되지 않았다.** 알파 배포의 가장 중요한 목적은 이 질문에 답할 자료(E010, 외부 사용자 5명 기준 I10)를 모으는 것이다.

## 8. 권고

1. **알파 배포를 진행한다.** 기술적 관문(V1·V2)은 통과했다. 남은 것은 계정·토큰·환경 설정(사용자)과 배포 직전 확인이다.
2. 알파와 함께 **E010·E011을 시작한다.** E011은 이 기기에서 가능하고, E010은 알파 사용자와 동료가 필요하다.
3. 알파 기간의 기술 과제
   - 양자화·분산 학습 시험
   - `source` 동면의 임시 사본 줄이기(0046)
   - 문서 변경을 별도 PR로 분리(CI 비용)

## 논문 매핑

- **연구 방법론**: 자기 비판 4차. 1차 설계 논리(0014), 2차 채택(0031), 3차 탐색적 시험(0041), 4차 검증 종합(0047).
