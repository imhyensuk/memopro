# 0133. G4 E3 제작: 학습의 활성값·손실·MPS 캐시를 예산 가까이로 — 3B 768MiB에서 예산 밖 몫 1,270 → 312MiB

- **날짜**: 2026-10-04
- **유형**: implementation + 개발 점검(사전 등록 측정 아님)
- **상태**: 확정. 사전 등록 E028b(0134) 전
- **관련 기록**: 0132 (E028: B3 실패, 사용자 결정 A), 0130 (E1), 0125 (E3 트랙)

## 사용자 결정

E028이 메모리 기준(B3)에서 실패한 뒤의 질문에 대한 답: **"A. E3 제작 후 재측정"**.

## 어디로 갔나 (3B, 768MiB, 1 × 128토큰, 단계별 측정)

| 지점 | footprint | MPS 실제 할당 | MPS 드라이버 |
|---|---|---|---|
| 모델 생성 뒤 | 460MiB | 7MiB | 8MiB |
| 순전파 끝 | 2,320MiB | 854MiB | 1,717MiB |
| 역전파 끝 | 2,343MiB | 57MiB | 1,250MiB |
| `empty_cache` 뒤 | 1,480MiB | 21MiB | 335MiB |

- 역전파용 활성값과 fp32 로짓이 약 850MiB다.
- PyTorch MPS 할당기는 그 약 2배를 잡고, 단계가 끝나도 캐시로 쥐고 있었다.

## 무엇을 만들었나 (`memopro.rt.torch`)

- **`enable_checkpointing(model)`**: torch의 **재진입** 체크포인팅을 켜고, 입력 기울기도 켠다(`enable_input_require_grads`). 층 입력만 남기고 나머지는 역전파에서 다시 계산한다.
  - 비재진입 방식을 먼저 시도했다. 재계산이 저장하는 값을 자기 훅으로 붙잡아 `saved_weights`의 참조 저장을 우회했고, 흘려 쓰는 가중치 고정이 749MiB까지 쌓여 예산을 넘었다. 그래서 재진입 방식을 쓴다.
  - 재계산이 다시 고정한 가중치를 바로 뒤 역전파가 메모리에서 찾으므로, 단계당 읽기는 거의 같다(약 10.0~10.5GiB).
- **`causal_lm_loss(model, input_ids, labels=None, chunk=32)`**: 다음 토큰 교차 엔트로피를 32위치씩 계산한다. 각 조각을 재진입 체크포인트로 감싸, 전체 fp32 로짓(위치 × 어휘)이 한꺼번에 생기지 않는다.
  - 수학은 모델 자신의 손실과 같다. 합하는 순서만 다르다.
- **`StreamedWeights.finish(release_cache=True)`**: GPU를 기다려 고정을 돌려준 뒤, MPS 할당기의 캐시도 돌려준다(`torch.mps.empty_cache`).

## 개발 점검 (3B, 768MiB, MPS, 3단계)

| 구성 | 최대 footprint(기준 대비 증가) | 단계 시간 | 손실 |
|---|---|---|---|
| E028 그대로 | +2,007MiB(2,460 − 453) | 10~13초 | 2.4207 … |
| 재진입 체크포인팅 + 캐시 반환 | +1,258MiB | 10.6~12.6초 | 2.4260, 3.5672, 3.2829 |
| + 조각 손실(전부) | **+1,080MiB = 예산 + 312MiB** | 11.7~12.2초 | 2.4260, 3.5672, 3.2829 |

- 체크포인팅을 켜면 손실이 마지막 자리에서 E028과 조금 다르다(2.4207 → 2.4260). 재계산 경로의 연산 순서 차이로 보인다. 같은 구성 안에서는 결정적이다. 예산 사이 비트 동일성은 E028b에서 확인한다.
- 조각 손실은 손실을 소수 넷째 자리까지 바꾸지 않았다.
- **시험**(작은 GPT-2, CPU)
  - 체크포인팅 + 조각 손실의 손실이 보통 단계와 1e-5 안으로 같고, 기울기가 유한하며, 예산을 지키고, 끝난 뒤 고정 0이다.
  - 스트리밍 모델이 아니면 거절한다.
  - 시험 9개 통과.
