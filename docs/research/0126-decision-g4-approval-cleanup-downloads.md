# 0126. 결정: G4 설계 초안 방향 승인, 16GB Mac은 나중에, 폴더 정리 뒤 7B 이상 다운로드 허락, 펜티너리 양자화 조사

- **날짜**: 2026-10-03
- **유형**: decision (사용자 결정)
- **상태**: 확정
- **관련 기록**: 0125 (G4 설계 초안), 0123 (G4), 0110 (다운로드 없음)

## 사용자 지시

> "초안의 방향성을 승인할게. 그리고 16GB 이상의 mac은 나중에 진헹해야할 것 같아. 그리고 지금 현재 memopro프로젝트 폴더의 무게가 많이 나가는데, 불필요한 것들을 줄여서 용량 확보를 한 후 7b이상 모델 다운로드를 승인할게. 그리고 추가 연구를 진행해서 펜티너리 양자화를 활용할 수 있을지 알이봐."

## 결정

## 폴더 정리 (D3 실행 기록)

- 정리 전: 프로젝트 12GB. 내역은 `.cache/hf` 9.2GB(GPT-2·Qwen2.5-1.5B·3B 원본; 실험 E025·E026이 씀), `target/` 1.4GB(Rust 빌드 산출물), `.venv` 1.4GB, 옛 `dist/` 0.0.1 배포 파일 0.7MB.
- **지운 것**: 다시 만들 수 있고 git이 추적하지 않는 것만.
  - `cargo clean` → 2.1GiB(19,465개 파일).
  - `dist/`의 0.0.1 휠·sdist, `.ruff_cache`, `.pytest_cache`, `__pycache__`.
- **남긴 것**: 모델 캐시(실험 원본, 중복 없음 확인), `.venv`.
- 정리 뒤: 프로젝트 11GB, 디스크 여유 18GiB.
- **남은 문제**: Qwen2.5-7B bf16은 약 15GB다. 받으면 디스크 여유가 약 4GB만 남는다. macOS 동작과 memopro의 디스크 하한(여유 20%)에 비해 너무 적다 → 사용자에게 선택지를 물었다.
- **사용자 답**: "프로젝트 밖에서 직접 확보". 사용자가 공간을 마련한 뒤 다운로드한다. 기존 실험 모델은 모두 유지한다.

## 논문 매핑

- **Methodology**: 시험대 제약(8GB 기기, 디스크 용량)과 다운로드 정책의 변경.
