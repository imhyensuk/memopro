- memopro는 자기 범위 안에서 문제를 해결한다. `check`와 `report`는 memopro가 제공하는 구성만 제시한다.
- 원칙 U6에서 "더 적합한 외부 도구가 있으면 안내한다"를 삭제한다.
- 0010의 **재구현 금지 원칙은 유지**한다. S2는 "안내"에 관한 제안이었고, 재구현 금지와는 별개이다.
- 결과: 코드를 작성하지 않는 LLM 채팅 최종 사용자는 대상이 아니며(S1), 그들을 다른 도구로 안내하지도 않는다(S2 기각).

## 수정안 v0.3 요지

### 궁극적 목표의 대상 명확화 (S1에 따른 결과)
> 메모리가 부족한 **PyTorch 개발자** 누구나, 자기 프로젝트·서비스·개발·학습에서 큰 메모리를 요구하는 모델을 쓸 수 있게 한다.
- "누구나" = 하드웨어 사양이나 숙련도와 무관하게, PyTorch로 무언가를 만드는 사람 누구나
- 포함: 직접 만든 모델, 확산(이미지 생성)·비전·오디오 모델, Python 코드 안에서 쓰는 LLM(HF Transformers), 파인튜닝, 연구 코드, Python 기반 서비스(FastAPI, Gradio 등)
- 제외: 코드 없이 LLM 앱을 쓰려는 최종 사용자

### 로드맵 재구성 (S3)

| 버전 | 내용 |
|---|---|
| **v0.1.0** | **doctor**(풀별 예산 벡터) + **census**(메모리 위치 + 중복도) + **β**(노트북 유휴 텐서 동면) |
| v0.2.0 | 범용 접근: `optimize(goal="infer"｜"train")`, `train_session`, `load`, `check` (PyTorch 워크로드 대상), 생태계 통합 |
| v0.3.0 | α (관문 Gα 통과 시) + 논문 |
| v0.4.0 | γ + `memopro run` |
| v1.0.0 | 안정화 |

- 연구 트랙(R1 α 검증, R2 센서스 연구)은 병렬로 진행한다. **R2 연구와 v0.1 census 제품은 같은 코드 기반**을 공유한다.
- v0.2의 추론 완료 조건은 0011 L4에 따라 PyTorch 워크로드 기준으로 재정의한다(0013에서 초안 작성).
