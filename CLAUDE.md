# memopro

Goal (0148, user-approved 2026-10-04; consolidates 0107 + 0123, nothing new): memopro is an open-source library (Rust core + Python) that lets memory-limited devices (8-16 GB laptops/Macs, small GPUs) run work that exceeds their memory **losslessly, within a guaranteed memory ceiling, at usable speed**. Main goal 1 — G4-B (AI): 16-bit LoRA training and inference of LLMs larger than device memory; lossless by default (outputs bit-identical to a plain run, results independent of the budget); compete on model sizes Unsloth/mlx-tune/HF cannot run on the same device, not on kernel speed (no Triton race, RS6 unchanged). Main goal 2 — G2′/G3 (general): ordinary memory-heavy work (arrays, images, dataframes, simulations; Python and C/C++/Rust via C ABI) in 1/2-1/4 of the memory it needs, lossless, ceiling guaranteed, slowdown predicted before running; engine = Rust runtime C-R choosing per buffer among keep / lossless compress / re-read verified source / recompute from lineage by measured cost. Kept — G1: the access layer (load/check/optimize/train_session/`memopro run`) wraps existing techniques and runs models that did not fit without OOM. Secondary — G4-C: on CUDA optionally wrap Unsloth-like back ends, the runtime takes only what exceeds memory (memopro works without them). Principle: the runtime never writes to disk (0110; the earlier 'move to SSD' action is out of the goal). Out of scope: no-code end users, routing users to external tools (0012 S2), kernel races, lossy-by-default methods. Success criteria: S1 3B 16-bit LoRA on an 8 GB M1 (met, 0138) and 7B 16-bit LoRA completed on a 16 GB Mac; S2 lossless generation ≥ 2.5x streaming alone (E033c); S3 a same-task comparison with mlx-tune or Unsloth; S4 a one-line API and the first public release. Everything built so far is kept as parts of the runtime (β source/compress/spill, spill engine RS1-RS5, file-backed residency, budgets, census). PyPI/crates.io name `memopro`.

Two layers (0010): **universal access layer** (env detection → budget → candidate configurations → apply fail-open → report; entry points CLI/`load`/`optimize`/`train_session`/notebook/integrations) wraps existing proven techniques as optional backends — **never reimplement them**; **research core** = memopro-native techniques (β hibernate, census, γ elastic; α rfc rejected in 0018) — novelty rule applies here only. ## Code conventions (0034 skeleton)

- `import memopro` must stay side-effect free and must not import torch/numpy/transformers/IPython; public names resolve lazily via `_LAZY` in `python/memopro/__init__.py` (`tests/test_import_cost.py` enforces it).
- Unbuilt API raises `memopro.NotYetImplemented(feature, planned, ref)`; Rust returns `Error::NotImplemented` and never panics (`unimplemented!` is banned). Never add silent no-op stubs.
- All memopro errors derive from `MemoproError`; a user-chosen method that cannot run raises `ModeUnavailable` with reason and alternatives, never a silent fallback.
- Settings: defaults < `memopro.toml`/`$MEMOPRO_CONFIG` < `MEMOPRO_*` < `configure()` < `using()` (contextvar block) < per-call options; add new settings to `Config` + `_validate` in `config.py`. Budget forms (0059): per pool (device/host/disk) `auto`, cap, fraction, `-2GB` reserve, `2GB..6GB` range (unmet minimum → access layer raises `BudgetExceeded`, doctor only warns), `6GB!` forced (may exceed measured, γ leaves it alone), `{use,min,max}`; old forms still parse to `int`/`float`/`PoolBudget`. Only `!` and `budget_basis` (`conservative` default, `os`, `total`) may exceed the conservative measurement; `headroom` is a fraction or a size.
- β method policy lives in `hibernate/_policy.py::resolve_modes`; apply techniques through `orchestrator.fail_open`. Magics print memopro errors and never break a cell.
- Access layer (0052 E3): `quality` ("lossless" < "high" < "balanced" default < "low") bounds automatic loss; `prefer` ("speed" default, "quality", "memory") orders candidates (`orchestrator/candidates.py`); sizes come from metadata (`access/_info.py`), never from loading. `load` never accepts `device_map`/`dtype`/`quantization_config` (it chooses them). Quantization back ends are available only if a tiny layer really runs on the device. `train_session` is exact first (micro-batches weighted by sample share, OOM retry from scratch, checkpointing, activation offload); float16 autocast always with `GradScaler`; it never swaps the user's optimizer (suggest only). `check` traces a steady-state second step with fake tensors, keeps only the loss, and passes the optimizer implementation torch would pick on the real device (0055); keep `tests/test_access.py::test_check_training_peak_matches_real_steady_state_tracking` passing. Measure GPU memory for experiments in a fresh process per case (0055: MemTracker cycles leaked memory between cases). After a failed attempt, drop the exception (it holds the failed attempt's tensors) before releasing memory.
- γ (0052 E6): the monitor thread only records the pressure level; every change happens at a safe point (`at_cell_boundary`, `at_safe_point` from `train_session`, load budgets via `budget_factor`). Never change tensors from a background thread. `memopro run` patches `from_pretrained` only in run mode, only when the script chose nothing and the model does not fit as stored, and removes the patch afterwards.
- `residency="file"` (0072) never changes which configuration is chosen, only the kind of memory; it is an explicit choice, so unsupported cases (non-MPS, int8 subclasses, offload, no disk consent to build a cache) raise `ModeUnavailable`. File-cache writes need `disk_writes="allow"` and the disk budget; reading a valid cache needs no consent; a changed source invalidates it.
- When nothing fits (0064): never a bare refusal. `BudgetExceeded` from `load` carries `.suggestions` produced by `access/_suggest.py` (only settings re-planned to really choose a configuration); every suggested setting must be a per-call option of `load`. `fallback` (`none` default, `stored`) is the only way to load over budget besides `!`/`budget_basis`, and always warns and reports.
- CLI exit codes: 0 ok, 1 memopro error, 2 usage, 3 not implemented.
- Anything that can touch a sleeping object must wake it first: guards live in `hibernate/_guards.py` (hooks + per-instance overrides removed before delegating). `now()` is serialised and rolls back on BaseException; wake restores data before removing guards and keeps guards if restore fails (`Handle.discard()` gives up). The handle registry is weak. Waking must happen before any torch.compile frame is entered (0049): overrides are bound methods, waking code is `torch.compiler.disable`d, `torch.compile` wrappers get hooks, `m.compile()`'s `_compiled_call_impl` is wrapped; a wake inside a compiled frame makes dynamo run eagerly from then on. After any hibernate change, re-run the probe categories of 0048 (save/copy/move/step/threads/interrupt/lifetime). Also run `tests/test_hibernate_compile.py`.
- Decide MPS with `memopro.env._torch.mps_usable()` (a real tiny allocation), never `torch.backends.mps.is_available()` alone: CI macOS VMs report MPS available but cannot allocate (0042).
- Hibernation frees memory by swapping `tensor.data` for an empty tensor and restoring it later (0036 B1); tensor identity must stay. Methods live in `hibernate/_methods.py` and work one tensor at a time (prepare, then release immediately). Never hibernate a tensor whose storage is shared (`_tensors.shared_reason`: views, autograd-saved tensors) or a meta tensor (0041); any unexpected error in a method must leave that tensor awake, not propagate. `source` must verify bit-equality by digest before releasing and re-check file size/mtime and the digest on wake. Never write to SSD without `disk_writes` consent; spill files are 0600, not pickled, and removed at exit.
- Rust bindings take buffers via the buffer protocol (`tensor.reshape(-1).view(torch.uint8).numpy()`), never `bytes`; the E008 `codec_*` prototypes are gone (reproduce E008 from 9fd9bd3). Frozen experiment scripts (hashed in env.json) include `experiments/n1c_demo/run.py`.
- Host `available_bytes` is conservative (0035): total − used (macOS: anonymous − purgeable + wired + compressor; Linux: MemTotal − MemAvailable). Never budget with `kernel_available_bytes` (macOS counts other apps' active memory). Budgets: `orchestrator/budget.py` (headroom 10%, MPS = min(limit − allocated, host usable), disk above the 20% free floor). `memopro.doctor(devices=False)` must not import torch.
